# 3.2 · Ownership

---
layout: center
---

## El problema: quién libera la memoria

Todo programa pide memoria mientras corre, y alguien tiene que devolverla. Hay tres
respuestas, y cada una cobra algo distinto.

<div class="text-sm cp-table-compact">

| Estrategia | Lenguajes | Lo que cobra |
| :--- | :--- | :--- |
| Recolector de basura | Python, JavaScript, Java, Go | CPU y memoria en ejecución, y pausas |
| Liberación manual | C, C++ | fugas, doble liberación, uso tras liberar |
| Ownership | Rust | reglas que el compilador verifica |

</div>

Rust libera sin intervención del programador, como un recolector. Lo hace en un punto
fijo que se conoce al compilar, como la liberación manual.

---
layout: center
---

## Las tres reglas

El sistema de **Ownership** es un conjunto de reglas que gobiernan cómo un programa en Rust gestiona la memoria:

<div class="important-note">

1. Cada valor tiene un propietario (*owner*).
2. Solo puede haber un propietario a la vez.
3. Cuando el propietario sale del ámbito (*scope*), el valor se destruye (*dropped*).

</div>

Si el programa viola alguna, no compila.

---
layout: center
---

## La regla 3 en código

```rust
fn main() {
    {
        let s = String::from("hola");   // s es dueña desde aquí
        println!("{s}");
    }                                   // sale de scope: se libera
    // aquí s ya no existe
}
```

Al cerrar la llave, Rust llama a `drop` sobre `s` y devuelve su memoria. No hay
recolector ni llamada escrita a mano. El punto de liberación se lee en el código: es
la llave que cierra el scope del dueño.

---
layout: center
---

## Qué se copia en `let s2 = s1`

Un `String` son dos piezas (3.1 Stack y heap): tres datos de tamaño fijo en el
stack, y los bytes del texto en el heap.

<div class="text-sm cp-table-compact">

| Dato en el stack | Qué guarda |
| :--- | :--- |
| `ptr` | la dirección del buffer en el heap |
| `len` | cuántos bytes están en uso |
| `cap` | cuántos bytes están reservados |

</div>

`let s2 = s1;` copia esos tres datos, 24 bytes en una máquina de 64 bits. El buffer
del heap no se toca, así que `s1` y `s2` apuntarían al mismo texto.

---
layout: center
---

## Por qué `s1` deja de valer

Con dos dueños del mismo buffer, la regla 3 se aplicaría dos veces. Al salir de
scope, `s2` liberaría el texto y después `s1` liberaría la misma memoria. Es la
*doble liberación* de C, y corrompe el heap.

<div class="important-note">

Rust lo evita en la asignación: `s1` queda invalidada y `s2` es la única dueña. El
texto no se duplica ni se destruye, solo cambia de dueño. Eso es **mover**.

</div>

La regla 2, un solo dueño a la vez, existe para que la regla 3 libere cada valor
una sola vez.

layout: center

## Usar un valor movido no compila

```rust
fn main() {
    let s1 = String::from("hola");
    let s2 = s1;
    println!("{s1} y {s2}");
}
```

```text
error[E0382]: borrow of moved value: `s1`
2 |     let s1 = String::from("hola");
  |         -- move occurs because `s1` has type `String`,
  |            which does not implement the `Copy` trait
3 |     let s2 = s1;
  |              -- value moved here
4 |     println!("{s1} y {s2}");
  |                ^^ value borrowed here after move
```

---
layout: center
---

## Cómo se lee *E0382*

El mensaje señala tres líneas del programa, y cada una responde una pregunta.

<div class="text-sm cp-table-compact">

| Anotación | Qué responde |
| :--- | :--- |
| *move occurs because... does not implement `Copy`* | por qué este valor se mueve y no se copia |
| *value moved here* | dónde perdió el valor la variable |
| *value borrowed here after move* | dónde se intentó usar después |

</div>

Dice *borrowed* porque `println!` toma prestado lo que imprime (3.3 Borrowing). Con
una función que recibe el valor, el mismo error dice *use of moved value*.

---
layout: center
---

## Dónde ocurre un move

El *ownership* define quién es responsable de liberar cada valor. Esa responsabilidad se puede transferir, y transferirla es lo que Rust llama **mover**.
La propiedad de la información se transfiere a través de:

* **Asociaciones** (ej. `y = x;`)
* **Asignaciones** (ej. `let y = x;`)
* **Paso de parámetros** (enviar variables a una función)
* **Retornos** (devolver valores desde una función)

---
layout: center
---

El comportamiento de los datos ante estos fenómenos variará dependiendo de dónde se almacene la información:

* **Si el tipo es `Copy`:** el valor se duplica. Ambas variables quedan con una copia independiente y siguen vivas.
* **Si no lo es:** se realiza una **transferencia (move)**. La propiedad pasa al nuevo destino y la variable original queda invalidada; el valor no se destruye, solo cambia de dueño.

---
layout: center
---

## Copiar o mover: la regla exacta

<div class="important-note">

Un tipo se **copia** si implementa el trait `Copy`, y puede implementarlo solo si
**todos sus campos son `Copy`** y **no implementa `Drop`**. Todo lo demás se **mueve**.

</div>

```rust
let a = (1, true);          // (i32, bool) es Copy: ambas viven
let b = a;

let c = (1, String::new()); // String no es Copy -> la tupla tampoco
let d = c;                  // c queda movida
```

Los dos pares viven en el stack: estar ahí es una consecuencia frecuente, no la causa.

## El move dentro de un bucle

```rust
fn imprimir(texto: String) {
    println!("{texto}");
}

fn main() {
    let saludo = String::from("hola");
    for _ in 0..2 {
        imprimir(saludo);   // E0382: value moved here,
    }                       //        in previous iteration of loop
}
```

La primera vuelta mueve `saludo` a `imprimir`, y la segunda ya no tiene qué pasar. El
compilador propone dos arreglos: clonar el valor, o cambiar el parámetro para que
tome prestado (3.3 Borrowing).

---
layout: center
---

## `.clone()`: la copia se pide

```rust
fn main() {
    let s1 = String::from("hola");
    let s2 = s1.clone();        // otro buffer, con los mismos bytes
    println!("{s1} y {s2}");    // dos dueñas, cada una de su texto
}
```

<div class="important-note">

Rust nunca duplica el heap por su cuenta. Una asignación cuesta siempre lo mismo: los
datos del stack. `.clone()` marca en el código el punto donde se paga una copia
completa.

</div>

---
layout: center
---

## Qué le pasa a `a`

<div class="text-sm cp-table-compact">

| Operación | Tipo `Copy` (`i32`, `bool`, `char`) | Tipo con heap (`String`) |
| :--- | :--- | :--- |
| `let b = a;` | se copia; `a` sigue válida | se mueve; `a` queda invalidada |
| `funcion(a)` | se copia; `a` sigue válida | se mueve; `a` queda invalidada |
| `a.clone()` | igual que copiar | duplica el heap; `a` sigue válida |
| el dueño sale de scope | se descarta del stack | corre `drop` y se libera el heap |

</div>

## El costo del ownership estricto

Pasar un `String` a una función lo consume. Para seguir usándolo, la función tiene
que devolverlo junto con su resultado.

```rust
fn longitud(s: String) -> (String, usize) {
    let n = s.len();
    (s, n)                           // devuelve el texto para no perderlo
}

fn main() {
    let s1 = String::from("hola");
    let (s1, n) = longitud(s1);      // se mueve, y regresa
    println!("{s1} mide {n} bytes");
}
```

Repetir eso en cada función no escala. Rust lo resuelve con un mecanismo
complementario: el **Borrowing**.
