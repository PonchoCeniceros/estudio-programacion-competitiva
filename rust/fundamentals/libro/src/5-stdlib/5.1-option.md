# 5.1 · Option

Una función que busca algo no siempre lo encuentra. En muchos lenguajes la
respuesta para «no hay» es `null`, y `null` cabe en cualquier variable. El tipo
de retorno dice «un entero» o «un usuario» aunque a veces no llegue nada. Nada
obliga a revisarlo, y el olvido aparece al ejecutar, como un error en otra parte
del programa.

Rust no tiene `null`. Cuando un valor puede no existir, lo dice su tipo:
`Option<i32>` en lugar de `i32`. El compilador no deja usar ese valor sin antes
decidir qué hacer si falta. `Option` no es un caso especial del lenguaje: es un
enum de dos variantes, como los de [2.3 Enums]{.ref}.

## Definiciones y reglas

Option
:   el enum de la biblioteca estándar para un valor que puede faltar. Tiene
    dos variantes: `Some(T)`, que lleva el valor, y `None`, que no lleva nada.

Desenvolver
:   *(unwrap)*: sacar el valor de un `Some`. Hay que decir qué pasa si en su
    lugar hay un `None`.

Combinador
:   un método de `Option` que lo transforma o lo desenvuelve sin escribir un
    `match`, como `map` o `unwrap_or`.

Modo de ligado
:   *(binding mode)*: cómo liga un patrón sus nombres. Por valor, por
    referencia o por referencia mutable.

::: {.reglas titulo="Las tres reglas de Option"}
1. Un valor que puede faltar es un `Option<T>`, y un `Option<T>` no es un `T`.
2. Para llegar al valor hay que decidir qué pasa con `None`.
3. Un patrón sobre `opt` mueve su contenido; sobre `&opt`, lo presta.
:::

## De un vistazo

Cada forma de desenvolver es una decisión distinta sobre `None`:

| Método | Si es `Some(x)` | Si es `None` |
| :--- | :--- | :--- |
| `unwrap_or(d)` | `x` | `d` |
| `unwrap_or_default()` | `x` | el default del tipo: `0`, `""` |
| `map(f)` | `Some(f(x))` | `None` |
| `is_some()` | `true` | `false` |
| `is_none()` | `false` | `true` |
| `unwrap()` | `x` | panic |
| `expect("msg")` | `x` | panic con el mensaje |
| `take()` | `Some(x)`, y deja `None` | `None` |
| `opt?` | `x` | la función devuelve `None` |

Criterio: si hay un valor de reemplazo razonable, `unwrap_or`; si la función
tampoco puede seguir sin él, `?`; `unwrap` y `expect`, solo si `None` es
imposible o es un error del programa.

## Las reglas, una por una

Antes de las reglas, cómo se declara y cómo se crea un `Option`.

### Un enum genérico

`enum Option<T> { None, Some(T) }` es la declaración de la biblioteca
estándar. Es un enum con una variante sin datos y una variante tupla, como el `Mensaje` de
[2.3 Enums]{.ref}. La `T` es un parámetro de tipo ([4.2 Generics]{.ref}):
`Option<i32>`, `Option<char>` y `Option<String>` son tipos distintos.

`Option`, `Some` y `None` están en el preludio, así que se usan sin `use` y
sin escribir `Option::` delante:

```rust
fn main() {
    let edad: Option<u32> = Some(31);
    let sin_edad: Option<u32> = None;
    let letra = Some('a');              // Option<char>
    println!("{edad:?} {sin_edad:?} {letra:?}");
}
```

El programa imprime `Some(31) None Some('a')`: `Option` implementa `Debug`
([4.4 Traits de la stdlib]{.ref}). En `letra`, el tipo se deduce del valor de
adentro. Un `None` solo no dice de qué tipo es, y `let nada = None;` no
compila: *E0282*, «type annotations needed for `Option<_>`».

### [Regla 1:]{.prefijo} un `Option<i32>` no es un `i32`

Con `null`, una variable de tipo entero puede no tener entero, y el tipo no
avisa. En Rust el aviso es el tipo mismo. `Option<i32>` y `i32` son tipos
distintos, y las operaciones de uno no sirven para el otro:

```rust,compile_fail
fn main() {
    let x: i32 = 5;
    let y: Option<i32> = Some(3);
    let suma = x + y;
    println!("{suma}");
}
```

```salida
error[E0277]: cannot add `Option<i32>` to `i32`
4 |     let suma = x + y;
  |                  ^ no implementation for
  |                    `i32 + Option<i32>`
  = help: the trait `Add<Option<i32>>` is not implemented
          for `i32`
```

El compilador no ve el `Some(3)`: ve un tipo que también puede ser `None`, y
para `5 + None` no hay respuesta. Alguien tiene que darla, por ejemplo con
un `match`: `match y { Some(v) => x + v, None => x }` vale 8, y la rama de
`None` deja escrito qué pasa sin `y`. Las demás formas de decidirlo son la
regla 2.

### Funciones que devuelven `Option`

Una función cuyo resultado puede no existir lo declara en su firma. La división
entre cero no tiene resultado, y en vez de tronar devuelve `None`:

```rust
fn dividir(a: i32, b: i32) -> Option<i32> {
    if b == 0 { None } else { Some(a / b) }
}

fn main() {
    println!("{:?}", dividir(10, 2));       // Some(5)
    println!("{:?}", dividir(10, 0));       // None
    println!("{:?}", "rama".find('m'));     // Some(2)
    let dias = [31, 28, 31];
    println!("{:?}", dias.get(1));          // Some(28)
    println!("{:?}", dias.get(5));          // None
}
```

`find` busca un carácter en un texto y da el byte donde empieza, si lo hay. `get` lee una
casilla de un arreglo sin el riesgo de panic de `dias[5]`
([2.1 Tuplas y arreglos]{.ref}). Devuelve `Option<&i32>`: una referencia a la
casilla, no una copia.

### [Regla 2:]{.prefijo} decidir qué pasa con `None`

`match` obliga a escribir las dos ramas. Cuando solo importa el `Some`, las
construcciones de [2.4 Patrones]{.ref} ahorran la otra. `if let` corre su
bloque si hay valor, y `while let` repite mientras lo haya:

```rust
fn main() {
    let texto = "ñu";
    if let Some(i) = texto.find('u') {
        println!("u en el byte {i}");   // u en el byte 2
    }

    let mut letras = texto.chars();
    while let Some(c) = letras.next() {
        print!("[{c}]");                // [ñ][u]
    }
    println!();
}
```

`.chars()` entrega los caracteres de uno en uno ([3.4 Strings]{.ref}). Cada
llamada a `.next()` devuelve el siguiente en un `Some`, y `None` cuando se
acaban. El `while let` se detiene en ese `None`. Es lo mismo que hace un `for`
por dentro ([5.6 Iteradores]{.ref}). Otro caso común es vaciar una pila con
`while let Some(x) = pila.pop()`, que se ve con `Vec` en [5.3 Vec]{.ref}.

Para el caso contrario, cuando sin el valor no tiene sentido seguir, está
`let Some(v) = opt else { return ...; };`, también de [2.4 Patrones]{.ref}.

### `unwrap` y `expect`

`unwrap()` saca el valor de un `Some` y hace panic con un `None`. `expect` hace
lo mismo, pero el panic lleva el mensaje que se le pasa:

```rust,should_panic
fn main() {
    let nombre: Option<&str> = None;
    let n = nombre.expect("falta el nombre");
    println!("{n}");
}
```

```salida
thread 'main' panicked at src/main.rs:3:20:
falta el nombre
```

Con `unwrap()` el mensaje es genérico: «called `Option::unwrap()` on a `None`
value». Por eso se prefiere `expect`, con un texto que diga qué se esperaba.

Los dos le quitan al compilador la decisión sobre `None`: el programa promete
que no llegará, y si llega, termina. Son aceptables en tres casos: en un test,
en un prototipo, o cuando el valor existe por construcción, como
`"a@b".find('@')`. Un programa con muchos `unwrap` está esquivando la regla 2,
no cumpliéndola.

### Combinadores

Los métodos de la tabla resuelven los casos frecuentes en una línea. `map`
recibe una closure ([4.3 Closures]{.ref}) y la aplica al valor de adentro, si
lo hay:

```rust
fn main() {
    let a: Option<i32> = Some(3);
    let b: Option<i32> = None;
    println!("{}", a.unwrap_or(0));             // 3
    println!("{}", b.unwrap_or(0));             // 0
    println!("{}", b.unwrap_or_default());      // 0
    println!("{:?}", a.map(|v| v * 2));         // Some(6)
    println!("{:?}", b.map(|v| v * 2));         // None
    println!("{:?}", a.map(|v| v > 1));         // Some(true)
    println!("{} {}", a.is_some(), b.is_none()); // true true
}
```

`map` no desenvuelve: entrega otro `Option`, y el de `None` sigue siendo
`None`. La decisión sobre la ausencia queda para después. El tipo de adentro
puede cambiar: `|v| v > 1` convierte un `Option<i32>` en un `Option<bool>`.
`unwrap_or_default` usa el trait `Default` de [4.4 Traits de la stdlib]{.ref}.

### El operador `?`

Dentro de una función que devuelve `Option`, hay casos en que un `None`
intermedio solo puede propagarse: si falta un dato, falta el resultado. `?`
escribe esa decisión con un carácter. Puesto después de un `Option`, saca el
valor si es `Some`, y si es `None` hace que la función devuelva `None` en ese
momento:

```rust
// el texto entre los dos primeros guiones
fn entre_guiones(s: &str) -> Option<&str> {
    let i = s.find('-')?;               // sin guion: None
    let resto = &s[i + 1..];
    let j = resto.find('-')?;           // sin segundo: None
    Some(&resto[..j])
}

fn main() {
    println!("{:?}", entre_guiones("mx-df-1"));  // Some("df")
    println!("{:?}", entre_guiones("mx-df"));    // None
}
```

Cada `?` equivale a un `match` cuya rama `Some(v)` da `v` y cuya rama `None`
hace `return None`. Las dos líneas que buscan quedan rectas, sin anidar. `?`
solo funciona en una función que devuelve `Option`; en `main`, que devuelve
`()`, no compila (*E0277*). El mismo operador sobre `Result` es tema de
[5.2 Result]{.ref}.

### [Regla 3:]{.prefijo} examinar sin mover

Un `match` sobre un `Option<String>` liga el `String` de adentro a un nombre de
la rama. Ligarlo es moverlo, con las reglas de [3.2 Ownership]{.ref}. Después
del `match`, `opt` ya no está completo:

```rust,compile_fail
fn main() {
    let opt: Option<String> = Some(String::from("hola"));
    match opt {
        Some(s) => println!("{} letras", s.len()),
        None => println!("vacío"),
    }
    println!("{opt:?}");
}
```

```salida
error[E0382]: borrow of partially moved value: `opt`
4 |         Some(s) => println!("{} letras", s.len()),
  |              - value partially moved here
...
7 |     println!("{opt:?}");
  |                ^^^ value borrowed here after partial move
```

Con un `Option<i32>` no hay error: `i32` es `Copy`, y el patrón copia en vez de
mover. Para leer el `String` sin quitárselo a `opt`, se examina una
referencia. Con `&mut opt`, además, se puede modificar en su lugar:

```rust
fn main() {
    let mut opt = Some(String::from("hola"));
    match &opt {                    // examina &Option<String>
        Some(s) => println!("{} letras", s.len()), // 4 letras
        None => println!("vacío"),
    }
    if let Some(s) = &mut opt {     // s: &mut String
        s.push_str(" mundo");
    }
    println!("{opt:?}");            // Some("hola mundo")
}
```

::: {.figura src="figuras/5.1-match-ref.html"}
:::

El patrón no cambió: sigue siendo `Some(s)`, que describe un `Option` y no una
referencia a uno. Las formas no coinciden, y aun así compila. El compilador
atraviesa el `&` por su cuenta y liga `s` como `&String`, un préstamo
([3.3 Borrowing]{.ref}). Esa regla se llama *match ergonomics*, y su efecto es
el modo de ligado:

| Valor examinado | Patrón | Qué liga `s` |
| :--- | :--- | :--- |
| `Option<String>` | `Some(s)` | `String`, movido fuera de `opt` |
| `&Option<String>` | `Some(s)` | `&String`, prestado |
| `&mut Option<String>` | `Some(s)` | `&mut String`, prestado |

El patrón se escribe una vez, y el valor examinado decide el modo. En el
programa, el mismo `Some(s)` liga primero un `&String` y luego un
`&mut String`.

### `take`: sacar y dejar `None`

A veces sí hay que sacar el valor, pero desde un lugar prestado, como un campo
detrás de `&mut self`. Mover desde una referencia no compila: `self.cliente` a
secas da *E0507*, «cannot move out of `self.cliente` which is behind a mutable
reference». El campo quedaría sin valor, y el dueño no se enteraría.

`take()` resuelve el hueco: devuelve el contenido y deja `None` en su lugar.
El campo siempre tiene un valor válido:

```rust
struct Turno {
    cliente: Option<String>,
}

impl Turno {
    fn atender(&mut self) -> Option<String> {
        self.cliente.take()
    }
}

fn main() {
    let mut t = Turno { cliente: Some(String::from("Ana")) };
    println!("{:?}", t.atender());      // Some("Ana")
    println!("{:?}", t.atender());      // None
}
```

La segunda llamada encuentra el `None` que dejó la primera. Las listas
enlazadas de [6.1 Box]{.ref} usan `take` en cada operación que mueve un nodo.

## Aplicación

Tres ejercicios del curso *Aprende Rust*. El primero calcula un precio con un
descuento opcional. Sin descuento, se descuenta cero, y eso es `unwrap_or(0)`.
La solución original tiene un defecto que solo aparece con ciertos datos:

```rust,should_panic
fn precio_final(precio: u32, descuento: Option<u32>) -> u32 {
    let descuento = descuento.unwrap_or(0);
    precio - descuento
}

fn main() {
    println!("{}", precio_final(100, Some(20)));    // 80
    println!("{}", precio_final(100, None));        // 100
    println!("{}", precio_final(10, Some(25)));
}
```

```salida
thread 'main' panicked at src/main.rs:3:5:
attempt to subtract with overflow
```

`10 - 25` no cabe en un `u32`, que no tiene negativos. En modo *debug* el
programa truena; en *release*, el resultado da la vuelta a un número enorme
([1.2 Tipos escalares]{.ref}). `saturating_sub` se queda en cero:

```rust
fn precio_final(precio: u32, descuento: Option<u32>) -> u32 {
    precio.saturating_sub(descuento.unwrap_or(0))
}

fn main() {
    println!("{}", precio_final(100, Some(20)));    // 80
    println!("{}", precio_final(100, None));        // 100
    println!("{}", precio_final(10, Some(25)));     // 0
}
```

Los otros dos son una función antes y después de `?`: lo que sigue a la
`@` de un correo, o `None`. La primera busca a mano; la segunda usa `find`,
que hace la búsqueda, y `?`, que escribe el `None` del final:

```rust
fn dominio_a_mano(email: &str) -> Option<&str> {
    for (i, c) in email.char_indices() {
        if c == '@' {
            return Some(&email[i + 1..]);
        }
    }
    None
}

fn dominio(email: &str) -> Option<&str> {
    let pos = email.find('@')?;
    Some(&email[pos + 1..])
}

fn main() {
    let a = dominio_a_mano("ferris@rust-lang.org");
    let b = dominio("sin-arroba");
    println!("{}", a.unwrap_or("ninguno"));   // rust-lang.org
    println!("{}", b.unwrap_or("ninguno"));   // ninguno
}
```

La original de la primera recorría bytes; aquí usa `.char_indices()`
([3.4 Strings]{.ref}). Como `@` ocupa un byte, `i + 1` es frontera segura.

## A fondo

**Un `Option` de una referencia no ocupa más que la referencia.** Una
referencia nunca vale cero, así que el compilador usa el cero para representar
`None`. `Option<&i32>` mide 8 bytes, igual que `&i32`: el *niche* de
[2.3 Enums]{.ref}.

**Antes de 2018, `match &opt` se escribía con `&Some(ref s)`.** `ref` liga
por préstamo; el compilador lo sugiere en el *E0382* de arriba.
