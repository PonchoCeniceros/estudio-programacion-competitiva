# 5.4 · HashMap y HashSet

Un `Vec` busca por posición: `v[2]` es el tercer elemento. Pero muchas
preguntas llegan con un nombre y no con un número. ¿Cuántas peras hay? ¿Cuántas
veces aparece «el» en un texto? Con un `Vec` de pares, responder obliga a
recorrerlo entero y comparar cada nombre.

Un `HashMap` busca por nombre. Guarda pares llave → valor y llega al valor de una
llave sin recorrer la colección: el costo es constante en promedio, tenga el mapa
diez elementos o un millón. El precio es que el mapa pone condiciones a la llave y
no guarda ningún orden.

## Definiciones y reglas

`HashMap<K, V>`
:   colección que asocia cada llave de tipo `K` con un valor de tipo `V`.

Llave
:   *(key)*: el dato por el que se busca. No se repite dentro del mapa.

Hash
:   número que se calcula a partir de la llave y decide en qué lugar de la tabla
    se guarda el par.

`HashSet<T>`
:   colección de elementos sin repetir: un `HashMap` donde solo importa la llave.

::: {.reglas titulo="Las tres reglas del mapa"}
1. Cada llave aparece una sola vez: insertarla de nuevo reemplaza su valor.
2. El mapa es dueño de lo que guarda: insertar mueve lo que no es `Copy`.
3. El tipo de la llave implementa `Hash` y `Eq`.
:::

## De un vistazo

| Operación | Devuelve | Si la llave no está |
| :--- | :--- | :--- |
| `m.insert(k, v)` | `Option<V>`, el valor anterior | inserta el par |
| `m.get(&k)` | `Option<&V>` | `None` |
| `m[&k]` | el valor | panic |
| `m.contains_key(&k)` | `bool` | `false` |
| `m.remove(&k)` | `Option<V>`, el valor quitado | `None` |
| `m.entry(k).or_insert(v)` | `&mut V` | inserta `v` |
| `s.insert(x)`, en un set | `bool`: `false` si ya estaba | inserta `x` |

Criterio: `get` cuando la llave puede faltar; los corchetes solo cuando su
ausencia sería un bug.

## Las reglas, una por una

Antes de las reglas, cómo se crea un mapa y cómo se consulta.

### Crear, insertar y buscar

`HashMap` no está en el preludio, el conjunto de nombres que todo programa ve sin
pedirlos. Se trae con `use std::collections::HashMap;`. El `use` se explica a
fondo en [7.1 Módulos]{.ref}.

```rust
use std::collections::HashMap;

fn main() {
    let mut edades = HashMap::new();
    edades.insert(String::from("Ana"), 30);
    edades.insert(String::from("Luis"), 25);

    match edades.get("Ana") {
        Some(e) => println!("Ana tiene {e}"),  // Ana tiene 30
        None => println!("Ana no está"),
    }
    println!("{:?}", edades.get("Eva"));       // None
    println!("{}", edades.contains_key("Luis")); // true

    edades.remove("Luis");
    println!("{}", edades.len());              // 1
}
```

`HashMap::new()` no dice los tipos. El compilador los deduce del primer
`insert`: una llave `String` y un valor `i32` hacen un `HashMap<String, i32>`.

`get` devuelve `Option<&V>` porque la llave puede no existir
([5.1 Option]{.ref}). Si existe, entrega una referencia al valor, que sigue en el
mapa. Las llaves son `String`, pero se busca con un literal `&str`: no hace falta
construir un `String` solo para preguntar. Lo mismo vale para `contains_key` y
`remove`.

Los corchetes también buscan, sin el `Option`. Si la llave no está, el programa
truena:

```rust,should_panic
use std::collections::HashMap;

fn main() {
    let mut edades = HashMap::new();
    edades.insert(String::from("Ana"), 30);
    println!("{}", edades["Eva"]);
}
```

```salida
thread 'main' panicked at src/main.rs:6:26:
no entry found for key
```

### [Regla 1:]{.prefijo} una llave, un valor

Insertar una llave que ya existe no agrega un segundo par: reemplaza el valor.
Cuando eso no es lo que se quiere, `entry(k).or_insert(v)` inserta solo si la
llave falta:

```rust
use std::collections::HashMap;

fn main() {
    let mut puntos = HashMap::new();
    puntos.insert("ana", 10);
    puntos.insert("ana", 25);           // sobrescribe el 10

    puntos.entry("ana").or_insert(99);  // ya existe: no toca
    puntos.entry("eva").or_insert(5);   // falta: inserta 5

    println!("{:?}", puntos.get("ana")); // Some(25)
    println!("{:?}", puntos.get("eva")); // Some(5)
}
```

`entry` busca la llave una vez y recuerda dónde quedó. `or_insert` decide con
ese resultado, sin una segunda búsqueda.

### [Regla 2:]{.prefijo} el mapa es dueño de lo que guarda

`insert` recibe la llave y el valor por valor. Un `i32` es `Copy` y se copia.
Un `String` se mueve al mapa, y la variable original deja de valer:

```rust,compile_fail
use std::collections::HashMap;

fn main() {
    let mut edades = HashMap::new();
    let nombre = String::from("Ana");
    let edad = 30;
    edades.insert(nombre, edad);
    println!("{nombre}: {edad}");
}
```

```salida
error[E0382]: borrow of moved value: `nombre`
5 |     let nombre = String::from("Ana");
  |         ------ move occurs because `nombre` has type
  |                `String`, which does not implement
  |                the `Copy` trait
...
7 |     edades.insert(nombre, edad);
  |                   ------ value moved here
8 |     println!("{nombre}: {edad}");
  |                ^^^^^^ value borrowed here after move
```

Es la regla de [3.2 Ownership]{.ref}: el mapa pasa a ser el dueño, y libera el
texto cuando él mismo sale de scope. `edad` sigue disponible porque se copió.
Si el original hace falta después, se inserta `nombre.clone()`, o se consulta al
mapa con `edades.get("Ana")`.

### Contar con `entry`

Un uso frecuente de un mapa es contar. La pieza que lo hace posible es lo que
devuelve `or_insert`: una referencia mutable al valor de la llave, exista desde
antes o recién insertado.

```rust
use std::collections::HashMap;

fn main() {
    let texto = "el gato y el perro y el pez";
    let mut conteo = HashMap::new();

    for palabra in texto.split_whitespace() {
        *conteo.entry(palabra).or_insert(0) += 1;
    }

    println!("{:?}", conteo.get("el"));    // Some(3)
    println!("{:?}", conteo.get("y"));     // Some(2)
    println!("{:?}", conteo.get("pez"));   // Some(1)
}
```

`split_whitespace` entrega las palabras de un texto, y el `for` las recorre como
recorre los caracteres de `.chars()` en [3.4 Strings]{.ref}. La línea del medio
se lee en dos ramas:

- **Llave nueva.** `or_insert(0)` inserta un 0 y devuelve un `&mut` a ese 0. El
  `+= 1` lo deja en 1.
- **Llave existente.** `or_insert(0)` no inserta nada: el 0 se ignora. Devuelve un
  `&mut` al valor que ya estaba, y el `+= 1` lo incrementa.

El `*` del inicio es el de [3.3 Borrowing]{.ref}: `+= 1` modifica el entero al
que apunta la referencia, no la referencia.

### [Regla 3:]{.prefijo} la llave implementa `Hash` y `Eq`

Para ubicar una llave, el mapa calcula su hash y luego la compara con `==`
contra las que caen en el mismo lugar. Lo primero pide `Hash`; lo segundo, `Eq`
([4.4 Traits de la stdlib]{.ref}). Un tipo propio no los trae:

```rust,compile_fail
use std::collections::HashMap;

struct Punto {
    x: i32,
    y: i32,
}

fn main() {
    let mut nombres = HashMap::new();
    nombres.insert(Punto { x: 0, y: 0 }, "origen");
}
```

```salida
error[E0277]: the trait bound `Punto: Eq` is not satisfied
10 |     nombres.insert(Punto { x: 0, y: 0 }, "origen");
   |             ^^^^^^ the trait `Eq` is not implemented
   |                    for `Punto`
note: required by a bound in `HashMap::<K, V, S, A>::insert`
   |     K: Eq + Hash,
   |        ^^ required by this bound
help: consider annotating `Punto` with `#[derive(Eq)]`
```

El compilador da un segundo E0277 igual, con `Hash` en lugar de `Eq`. Se arregla
con `#[derive(PartialEq, Eq, Hash)]` sobre `Punto`; `Eq` exige además
`PartialEq`. Con eso el `insert` compila, y `nombres.get(&Punto { x: 0, y: 0 })`
devuelve `Some("origen")`.

Un `f64` no puede ser llave. `NaN` no es igual a sí mismo, así que `f64` no
implementa `Eq` ([4.4 Traits de la stdlib]{.ref}), y tampoco `Hash`:
`insert(1.5, "pan")` falla con los mismos dos E0277.

### Recorrer: el orden no está definido

Un `for` sobre `&mapa` entrega cada par como una tupla de referencias. Pero el
orden de esos pares no está definido. Para imprimir en orden, se juntan las
llaves en un `Vec`, se ordena ([5.3 Vec]{.ref}) y se recorre el `Vec`,
consultando el mapa con cada llave:

```rust
use std::collections::HashMap;

fn main() {
    let mut conteo = HashMap::new();
    for palabra in "el gato y el perro".split_whitespace() {
        *conteo.entry(palabra).or_insert(0) += 1;
    }

    for (palabra, n) in &conteo {
        print!("{palabra}={n} ");     // orden variable
    }
    println!();

    let mut llaves = Vec::new();
    for (palabra, _) in &conteo {
        llaves.push(*palabra);
    }
    llaves.sort();

    for palabra in llaves {
        print!("{palabra}={} ", conteo[palabra]);
    }
    println!();   // el=2 gato=1 perro=1 y=1
}
```

La primera línea que imprime cambia de una ejecución a otra. Tres ejecuciones
seguidas dieron `y=1 perro=1 el=2 gato=1`, `y=1 el=2 perro=1 gato=1` y
`gato=1 y=1 el=2 perro=1`. La segunda línea sale siempre igual.

`palabra` es un `&&str`, una referencia a la llave guardada; el `*` copia el
`&str`. El `for` con `push` tiene una forma corta, `.keys().collect()`, que se
explica en [5.6 Iteradores]{.ref}. Si el orden importa siempre, la colección
adecuada es `BTreeMap`, que guarda las llaves ordenadas
([5.5 Otras colecciones]{.ref}).

### `HashSet`: solo la llave

Un `HashSet<T>` responde una sola pregunta: ¿está o no está? Internamente es un
`HashMap<T, ()>`, con el valor vacío, así que pide lo mismo a sus elementos:
`Hash` y `Eq`. Su `insert` devuelve `false` si el elemento ya estaba, lo que
detecta duplicados sin un `contains` aparte:

```rust
use std::collections::HashSet;

fn main() {
    let mut vistos = HashSet::new();

    for n in [1, 2, 2, 3, 1] {
        if !vistos.insert(n) {
            println!("repetido: {n}");   // 2, luego 1
        }
    }
    println!("{}", vistos.len());        // 3
    println!("{}", vistos.contains(&3)); // true
}
```

## Aplicación

Dos ejercicios del curso *Aprende Rust*. El primero actualiza el inventario de
una frutería: sobrescribe las peras, retira las uvas, agrega kiwis e imprime en
orden alfabético.

```rust
use std::collections::HashMap;

fn main() {
    let mut stock = HashMap::new();
    stock.insert("manzanas", 10);
    stock.insert("peras", 4);
    stock.insert("uvas", 0);

    stock.insert("peras", 6);    // regla 1: ahora hay 6
    stock.remove("uvas");        // se retiran las uvas
    stock.insert("kiwis", 12);   // llegan 12 kiwis

    println!("Productos: {}", stock.len());

    let mut nombres = Vec::new();
    for (nombre, _) in &stock {
        nombres.push(*nombre);
    }
    nombres.sort();

    for nombre in nombres {
        println!("{nombre}: {}", stock[nombre]);
    }
}
```

```salida
Productos: 3
kiwis: 12
manzanas: 10
peras: 6
```

Los corchetes de `stock[nombre]` no pueden tronar: cada nombre salió del propio
mapa.

El segundo agrupa palabras por su inicial. El valor de cada llave es un `Vec`, y
`entry` lo crea vacío la primera vez que aparece la letra. `chars().next()`
entrega el primer carácter como `Option<char>`, porque un texto vacío no tiene.

```rust
use std::collections::HashMap;

fn agrupar(palabras: &[&str]) -> HashMap<char, Vec<String>> {
    let mut grupos = HashMap::new();
    for palabra in palabras {
        if let Some(letra) = palabra.chars().next() {
            grupos
                .entry(letra)
                .or_insert(Vec::new())
                .push(palabra.to_string());
        }
    }
    grupos
}

fn main() {
    let nombres = ["ana", "bea", "alba", "bruno", "carlos"];
    let grupos = agrupar(&nombres);

    let mut letras = Vec::new();
    for (letra, _) in &grupos {
        letras.push(*letra);
    }
    letras.sort();

    for letra in letras {
        println!("{letra}: {:?}", grupos[&letra]);
    }
}
```

```salida
a: ["ana", "alba"]
b: ["bea", "bruno"]
c: ["carlos"]
```

Es la línea del contador con otro valor: `or_insert` devuelve un `&mut Vec`, y
`push` agrega la palabra en las dos ramas. Cuando el valor inicial es el default
del tipo, hay una forma corta: `or_default()`, que usa `Default`
([4.4 Traits de la stdlib]{.ref}). El default de un `Vec` es el vector vacío, y
el de un entero es 0:

```rust
use std::collections::HashMap;

fn main() {
    let mut grupos: HashMap<char, Vec<&str>> = HashMap::new();
    grupos.entry('a').or_default().push("ana");
    println!("{:?}", grupos.get(&'a'));   // Some(["ana"])
}
```

Con `or_default` el tipo del valor ya no sale de un argumento, así que el mapa
lo declara. El contador se escribe igual:
`*conteo.entry(palabra).or_default() += 1`.

## A fondo

**`insert` devuelve el valor que reemplazó.** Es un `Option<V>`: `None` si la
llave era nueva y `Some(anterior)` si ya existía. Sirve para saber si hubo
sobrescritura sin un `contains_key` previo.

**`get_mut` modifica un valor sin `entry`.** Devuelve `Option<&mut V>`. Con
`if let Some(n) = stock.get_mut("peras") { *n -= 1; }` se descuenta una pera
solo si la llave existe, sin insertarla cuando falta.

**Por qué el costo es constante en promedio.** El hash de la llave indica una
casilla de la tabla, y el mapa va directo a ella. Dos llaves distintas pueden
caer en la misma casilla; entonces el mapa las distingue con `==`. Mientras esas
colisiones son pocas, buscar no depende del tamaño. Cuando la tabla se llena,
el mapa la agranda y reubica todo, como un `Vec` que crece. `with_capacity(n)`
reserva espacio desde el inicio.

**Por qué el orden cambia entre ejecuciones.** El hash por default, SipHash,
usa una semilla aleatoria distinta en cada ejecución. Así nadie puede preparar
llaves que caigan todas en la misma casilla y vuelvan lento al mapa. La
semilla cambia las casillas, y con ellas el orden de recorrido.

**Por qué un `&str` busca llaves `String`.** `get` no pide un `&K`: acepta
cualquier `&Q` tal que `K` se pueda prestar como `Q`, con el trait `Borrow`. Un
`String` se presta como `str`, y los dos dan el mismo hash para el mismo texto.
