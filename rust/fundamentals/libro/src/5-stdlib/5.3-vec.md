# 5.3 · Vec

Un arreglo fija su tamaño al compilar: `[i32; 7]` guarda siete números, ni uno
más. Eso alcanza para los días de la semana, pero no para las líneas de un
archivo o las compras de un cliente. Cuántos elementos habrá se sabe hasta
ejecutar.

`Vec<T>` es la secuencia que crece mientras el programa corre. Como su tamaño
no se conoce al compilar, sus elementos viven en el heap, igual que el texto de
un `String` ([3.1 Stack y heap]{.ref}). Todo lo que [3.2 Ownership]{.ref} y
[3.3 Borrowing]{.ref} dijeron del texto vale aquí, y una regla del borrow
checker encuentra su causa física.

## Definiciones y reglas

`Vec<T>`
:   *(vector)*: secuencia de valores del mismo tipo `T`, uno junto al otro en
    el heap, que crece y se encoge al ejecutar.

Longitud
:   cuántos elementos guarda el vector: `v.len()`.

Capacidad
:   cuántos elementos caben en el bloque que tiene reservado sin pedir otro:
    `v.capacity()`. Nunca es menor que la longitud.

Slice
:   *(slice)*: préstamo de una porción contigua de un `Vec` o de un arreglo.
    Su tipo es `&[T]`.

::: {.reglas titulo="Las tres reglas del Vec"}
1. Los elementos viven en el heap; en el stack quedan `ptr`, `len` y `cap`.
2. Mientras viva un préstamo de un elemento, el vector no se puede modificar.
3. `v[i]` hace panic si el índice no existe; `v.get(i)` devuelve `Option`.
:::

## De un vistazo

| | Arreglo | `Vec` | Slice |
| :--- | :--- | :--- | :--- |
| Tipo | `[T; N]` | `Vec<T>` | `&[T]` |
| ¿Es dueño? | sí | sí | no: lo toma prestado |
| ¿Puede crecer? | no | sí, si el binding es `mut` | no |
| Dónde están los elementos | donde esté el arreglo | en el heap | en el dueño |
| Qué hay en el stack | los elementos | `ptr`, `len`, `cap` | `ptr`, `len` |
| Se construye con | `[1, 2, 3]` | `vec![1, 2, 3]` | `&v`, `&v[a..b]` |

Criterio para una firma: una función que solo lee una secuencia recibe `&[T]`.
Así acepta un `Vec` prestado, un arreglo o un pedazo de cualquiera de los dos.

## Las reglas, una por una

Antes de las reglas, cómo se construye un vector y cómo se le agregan y quitan
elementos.

### Construir un `Vec`

Hay dos formas. `Vec::new()` crea un vector vacío; la macro `vec!` lo crea con
valores iniciales, con la misma sintaxis que un arreglo:

```rust
fn main() {
    let mut nombres: Vec<String> = Vec::new();  // anotado
    let mut medidas = Vec::new();               // por el push
    medidas.push(2.5);
    let primos = vec![2, 3, 5, 7];              // Vec<i32>
    let ceros = vec![0; 4];                     // 4 ceros

    nombres.push(String::from("Ana"));
    println!("{nombres:?} {medidas:?}");
    println!("{primos:?} {ceros:?}");
}
```

`vec!` saca el tipo de los valores. `Vec::new()` no tiene valores de dónde
sacarlo, y el compilador lo deduce de la anotación o del primer `push`. Sin
ninguna de las dos, no compila:

```rust,compile_fail
fn main() {
    let v = Vec::new();   // E0282: type annotations needed
}                         //        for `Vec<_>`
```

`{:?}` imprime el vector completo entre corchetes, como un arreglo.

### Agregar y quitar al final: `push` y `pop`

`push` agrega un elemento al final y `pop` quita el último. Los dos piden un
binding `mut`, porque modifican el vector.

```rust
fn main() {
    let mut pila = vec![1, 2];
    pila.push(3);
    println!("{pila:?}");          // [1, 2, 3]

    println!("{:?}", pila.pop());  // Some(3)
    println!("{:?}", pila.pop());  // Some(2)
    println!("{:?}", pila.pop());  // Some(1)
    println!("{:?}", pila.pop());  // None: estaba vacío
}
```

`pop` no devuelve el elemento a secas, sino un `Option` ([5.1 Option]{.ref}):
`Some(valor)` si había uno, `None` si el vector estaba vacío. El caso vacío
queda en el tipo y el compilador obliga a tratarlo.

### [Regla 1:]{.prefijo} los elementos viven en el heap

Un `Vec` tiene la misma anatomía que un `String`: en el stack quedan tres datos
de tamaño fijo, y los elementos están en un bloque del heap.

::: {.figura src="figuras/5.3-anatomia.html"}
:::

`ptr` apunta al bloque, `len` cuenta los elementos guardados y `cap` cuenta los
que caben. Como en el stack hay siempre tres números de 8 bytes, un `Vec<i32>`
mide 24 bytes con cero elementos o con un millón:

```rust
fn main() {
    let mut v = Vec::new();
    v.push(10);
    v.push(20);
    v.push(30);
    println!("{} {}", v.len(), v.capacity());           // 3 4
    println!("{}", std::mem::size_of::<Vec<i32>>());    // 24
}
```

La semejanza con `String` no es casual: un `String` es un `Vec<u8>` con la
garantía de que sus bytes son UTF-8 válido. La biblioteca estándar lo define
así, con un solo campo de tipo `Vec<u8>`.

De la regla salen las de ownership de [3.2 Ownership]{.ref}. Asignar un `Vec` o
pasarlo a una función copia los tres datos del stack y mueve la propiedad: el
bloque del heap no se duplica, y el binding original queda movido. Para una
copia independiente está `.clone()`.

### [Regla 2:]{.prefijo} un préstamo congela el vector

Este programa toma una referencia al primer elemento, agrega otro y después
usa la referencia. No compila:

```rust,compile_fail
fn main() {
    let mut v = vec![1, 2, 3];
    let primero = &v[0];
    v.push(4);
    println!("{primero}");
}
```

```salida
error[E0502]: cannot borrow `v` as mutable
              because it is also borrowed as immutable
3 |     let primero = &v[0];
  |                    - immutable borrow occurs here
4 |     v.push(4);
  |     ^^^^^^^^^ mutable borrow occurs here
5 |     println!("{primero}");
  |                ------- immutable borrow later used here
```

Es la regla 1 de [3.3 Borrowing]{.ref}: `push` necesita `&mut v`, y `primero`
es un préstamo compartido todavía vivo. Aquí la regla tiene una causa que se
puede dibujar. `vec![1, 2, 3]` reserva un bloque justo para tres elementos, y
el cuarto no cabe. `push` pide entonces un bloque mayor, copia ahí los
elementos y libera el viejo.

Un programa que imprime `len`, `capacity()` y `as_ptr()` alrededor del `push`
lo confirma: antes valen 3, 3 y una dirección; después, 4, 6 y otra
dirección. Si el compilador aceptara el programa, `primero` leería memoria ya
devuelta al asignador. En C ese error compila y aparece al ejecutar, a veces.

::: {.figura src="figuras/5.3-realojar.html"}
:::

No importa que en este caso concreto hubiera o no capacidad libre. El
compilador no lleva la cuenta de `cap`: rechaza todo `&mut` mientras viva un
`&`. El arreglo es el de [3.3 Borrowing]{.ref}: terminar de leer antes de
escribir, o copiar el valor en lugar de prestarlo.

```rust
fn main() {
    let mut v = vec![1, 2, 3];
    let primero = v[0];   // i32 es Copy: se copia
    v.push(4);
    println!("{primero} {v:?}");   // 1 [1, 2, 3, 4]
}
```

### [Regla 3:]{.prefijo} índice o `get`

Hay dos formas de leer un elemento, y difieren en qué pasa si el índice no
existe. `v[i]` comprueba el índice al ejecutar, como en un arreglo
([2.1 Tuplas y arreglos]{.ref}), y fuera de rango el programa hace panic:

```rust,should_panic
fn main() {
    let v = vec![10, 20, 30];
    let x = v[9];
    println!("{x}");
}
```

```salida
thread 'main' panicked at src/main.rs:3:14:
index out of bounds: the len is 3 but the index is 9
```

`v.get(i)` no hace panic: devuelve un `Option<&T>`, con `None` si el índice no
existe.

```rust
fn main() {
    let v = vec![10, 20, 30];
    let pedido = 9;   // un índice que viene de fuera
    match v.get(pedido) {
        Some(x) => println!("el {pedido} es {x}"),
        None => println!("no hay elemento {pedido}"),
    }
}
```

El criterio sale de qué significa un índice inválido. Si sería un bug del
programa, `v[i]`: el panic lo señala en el lugar exacto. Si es un caso normal,
como un índice que viene del usuario o de un archivo, `get`, y el `None` se
trata como cualquier otro valor.

### Recorrer: tres formas de `for`

Un `for` sobre un vector se escribe de tres formas, y cada una corresponde a
una de las tres formas de recibir un valor de [3.3 Borrowing]{.ref}:

```rust
fn main() {
    let mut precios = vec![100, 250, 40];

    for p in &precios {         // &i32: solo lee
        print!("{p} ");
    }
    println!();

    for p in &mut precios {     // &mut i32: modifica
        *p += 10;
    }

    for p in precios {          // i32: consume el vector
        print!("{p} ");         // 110 260 50
    }
    println!();
}
```

Con `&precios`, cada `p` es un `&i32`. Con `&mut precios`, cada `p` es un
`&mut i32`, y para cambiar el elemento hace falta `*p`, como con cualquier
referencia mutable. Con `precios` a secas, el `for` se queda con el vector:
cada elemento sale por valor y, al terminar, el vector ya no existe.

```rust,compile_fail
fn main() {
    let v = vec![1, 2, 3];
    for x in v {
        println!("{x}");
    }
    println!("{}", v.len());
}
```

```salida
error[E0382]: borrow of moved value: `v`
2 |     let v = vec![1, 2, 3];
  |         - move occurs because `v` has type `Vec<i32>`,
  |           which does not implement the `Copy` trait
3 |     for x in v {
  |              - `v` moved due to this implicit call
  |                to `.into_iter()`
6 |     println!("{}", v.len());
  |                    ^ value borrowed here after move
help: consider iterating over a slice of the `Vec<i32>`'s
      content to avoid moving into the `for` loop
3 |     for x in &v {
  |              +
```

El mensaje menciona `.into_iter()`. Cada forma del `for` llama a un método:
`&v` a `.iter()`, `&mut v` a `.iter_mut()` y `v` a `.into_iter()`.
[5.6 Iteradores]{.ref} explica esos tres métodos.

### Otros métodos y lo que cuestan

Como los elementos están contiguos, lo que pasa al final del vector es barato
y lo que pasa al principio o en medio cuesta mover a los demás.

| Método | Qué hace | Costo |
| :--- | :--- | :--- |
| `len()`, `is_empty()` | lee `len` | constante |
| `push(x)`, `pop()` | agrega o quita al final | constante (`push`, en promedio) |
| `first()`, `last()` | el primero o el último, en `Option<&T>` | constante |
| `contains(&x)` | busca `x` uno por uno | proporcional a `len` |
| `insert(i, x)` | pone `x` en `i` y recorre el resto | proporcional a lo que hay después |
| `remove(i)` | quita el de `i` y recorre el resto | proporcional a lo que hay después |
| `sort()` | ordena de menor a mayor | proporcional a *n* log *n* |

```rust
fn main() {
    let mut v = vec![30, 10, 20];
    v.insert(0, 5);                  // [5, 30, 10, 20]
    let quitado = v.remove(1);       // 30; queda [5, 10, 20]
    println!("{quitado} {v:?}");
    println!("{}", v.contains(&10)); // true
    v.push(1);
    v.sort();
    println!("{v:?}");               // [1, 5, 10, 20]
}
```

`insert(0, x)` en un vector de un millón de elementos recorre un millón de
elementos un lugar a la derecha. Si un programa agrega y quita por los dos
extremos, la colección indicada es `VecDeque` ([5.5 Otras colecciones]{.ref}).
`sort` pide que los elementos implementen `Ord` ([4.4 Traits de la stdlib]{.ref}).

### Slices: prestar una parte

Un slice de elementos es la misma idea que el `&str` de [3.4 Strings]{.ref}:
un puntero al primer elemento de la porción y una longitud. Se escribe
`&v[a..b]`, con los mismos rangos y atajos que en el texto. Como los elementos
no son UTF-8, aquí no hay fronteras de carácter: cualquier rango dentro de
`0..=len` es válido.

Una función que recibe `&[i32]` acepta un vector prestado, una parte de él o
un arreglo:

```rust
fn suma(nums: &[i32]) -> i32 {
    let mut total = 0;
    for n in nums {
        total += n;
    }
    total
}

fn main() {
    let v = vec![1, 2, 3, 4];
    println!("{}", suma(&v));        // 10: el Vec entero
    println!("{}", suma(&v[1..3]));  // 5: solo 2 y 3
    println!("{}", suma(&[10, 20])); // 30: un arreglo
}
```

`&v` es un `&Vec<i32>` y se convierte solo a `&[i32]`, igual que un `&String`
se convierte a `&str`. El mecanismo es `Deref` ([4.5 Operadores y
conversiones]{.ref}). Al revés no funciona: una función que pide `&Vec<i32>`
rechaza arreglos y slices. Por eso la firma pide `&[T]`. En ninguno de los tres
casos se copian elementos, y `v` sigue siendo el dueño.

### Un solo tipo por vector

Todos los elementos de un `Vec<T>` son del mismo tipo `T`. `vec![1, "dos"]` no
compila (*E0308: mismatched types*, *expected integer, found `&str`*): el
primer valor fija el tipo y el segundo no encaja. Para guardar valores de
varias clases se define un enum con una variante por caso ([2.3 Enums]{.ref}),
y el vector es de ese enum. Cada elemento ocupa lo mismo, el tamaño del enum,
y al recorrerlo un `match` obliga a tratar todas las variantes. El segundo
programa de la aplicación lo hace con los movimientos de una cuenta.

## Aplicación

Dos ejercicios del curso *Aprende Rust*. El primero sube un punto cada nota
sin pasar de 10 y después las ordena. Modifica en el lugar con `&mut` y `*`:

```rust
fn main() {
    let mut notas = vec![4, 9, 10, 6, 7];

    for nota in &mut notas {
        if *nota < 10 {
            *nota += 1;
        }
    }
    notas.sort();

    println!("{notas:?}");   // [5, 7, 8, 10, 10]
}
```

El segundo calcula el saldo de una cuenta a partir de sus movimientos. El
vector es de un enum, cada elemento pasa por un `match`, y la función recibe
`&[Movimiento]` porque solo lee:

```rust
enum Movimiento {
    Ingreso(i32),
    Gasto(i32),
}

fn saldo(movimientos: &[Movimiento]) -> i32 {
    let mut saldo = 0;
    for m in movimientos {
        match m {
            Movimiento::Ingreso(n) => saldo += n,
            Movimiento::Gasto(n) => saldo -= n,
        }
    }
    saldo
}

fn main() {
    let mut movimientos = Vec::new();
    movimientos.push(Movimiento::Ingreso(1000));
    movimientos.push(Movimiento::Gasto(250));
    movimientos.push(Movimiento::Gasto(100));
    movimientos.push(Movimiento::Ingreso(50));

    println!("Saldo: {}", saldo(&movimientos));  // 700
}
```

## A fondo

**`push` cuesta poco en promedio.** Cuando no queda capacidad, el vector no
crece de uno en uno: en la implementación actual reserva el
doble. Con `Vec::new()` y `push` sucesivos de
`i32`, `capacity()` pasa por 0, 4, 8 y 16. Copiar todo es caro, pero ocurre
cada vez menos, y repartido entre todos los `push` sale a un costo constante.
Si se conoce el tamaño final, `Vec::with_capacity(n)` reserva desde el inicio y
evita las copias.

**`sort` es de los slices.** `sort`, `contains`, `first`, `last` y `get` están
definidos sobre `[T]`, no sobre `Vec<T>`. Un vector los alcanza por `Deref`, y
un arreglo también los tiene: `[3, 1, 2].sort()` funciona sobre un arreglo
`mut`.

**Ordenar por otra cosa.** `sort_by_key` recibe una closure que dice por qué
dato ordenar ([4.3 Closures]{.ref}). Un `Vec<f64>` no tiene `sort`, porque
`f64` no implementa `Ord`; se ordena con `sort_by` y `total_cmp`:

```rust
fn main() {
    let mut palabras = vec!["kiwi", "uva", "plátano"];
    palabras.sort_by_key(|p| p.len());
    println!("{palabras:?}");   // ["uva", "kiwi", "plátano"]

    let mut medidas: Vec<f64> = vec![2.5, -1.0, 0.3];
    medidas.sort_by(|a, b| a.total_cmp(b));
    println!("{medidas:?}");    // [-1.0, 0.3, 2.5]
}
```

**Un `String` se arma desde un `Vec<u8>`.** `String::from_utf8(bytes)` toma el
vector y devuelve un `Result` ([5.2 Result]{.ref}): `Ok` con el texto si los
bytes son UTF-8 válido, `Err` si no. No copia nada: el mismo bloque del heap
pasa a ser el del `String`. `.into_bytes()` hace el camino inverso.
