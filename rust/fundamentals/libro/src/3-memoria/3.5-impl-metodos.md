# 3.5 · impl y métodos

Los structs de [2.2 Structs]{.ref} solo guardan datos. Todo lo que se hace
con ellos vive en funciones sueltas, como `area(&r)`, y nada en el código
dice que esa función pertenece a `Rectangulo`. Con veinte funciones y cinco
tipos, encontrar qué opera sobre qué exige leerlas todas.

Un bloque `impl` pone las funciones junto a su tipo y permite llamarlas con
punto: `r.area()`. El capítulo llega hasta aquí, y no junto a los structs,
por una razón: el primer parámetro de un método es un préstamo o un *move*, y
eso se explicó en [3.2 Ownership]{.ref} y [3.3 Borrowing]{.ref}.

## Definiciones y reglas

Bloque `impl`
:   el lugar donde se escriben las funciones de un tipo. Se abre con
    `impl Tipo { ... }` y sirve igual para structs y enums.

Método
:   función de un bloque `impl` cuyo primer parámetro es `self`: la instancia
    sobre la que se llama. Se invoca con punto.

Función asociada
:   función de un bloque `impl` que no recibe `self`. Pertenece al tipo, no a
    una instancia, y se invoca con `::`.

`Self`
:   dentro de un `impl`, alias del tipo que se está implementando.

::: {.reglas titulo="Las tres reglas de los métodos"}
1. Un método es una función cuyo primer argumento es la instancia:
   `caja.ver()` es `Caja::ver(&caja)`.
2. La forma de `self` decide qué recibe el método: `&self` lee, `&mut self`
   modifica y `self` se queda con el valor.
3. Las reglas del borrow checker aplican igual a las llamadas de métodos.
:::

## De un vistazo

Las tres formas de `self` son las tres formas de recibir un valor de
[3.3 Borrowing]{.ref}, con la instancia en el lugar del parámetro.

| Firma | Recibe | La instancia, después | Se llama con |
| :--- | :--- | :--- | :--- |
| `fn f(&self)` | `&Tipo` | sigue válida, sin cambios | `x.f()` |
| `fn f(&mut self)` | `&mut Tipo` | sigue válida, modificada | `x.f()` |
| `fn f(self)` | `Tipo` | queda movida | `x.f()` |
| `fn f()` | nada | no hay instancia | `Tipo::f()` |

Criterio para escribir un método: empezar por `&self`, pasar a `&mut self`
si modifica la instancia, y usar `self` solo si la consume.

## Las reglas, una por una

Antes de las reglas, el paso de una función suelta a un método.

### De función suelta a método

```rust
struct Rectangulo { ancho: u32, alto: u32 }

fn area(r: &Rectangulo) -> u32 {
    r.ancho * r.alto
}

impl Rectangulo {
    fn area(&self) -> u32 {
        self.ancho * self.alto
    }
}

fn main() {
    let r = Rectangulo { ancho: 3, alto: 4 };
    println!("{}", area(&r));   // función suelta: 12
    println!("{}", r.area());   // método: 12
}
```

Las dos versiones hacen lo mismo y reciben lo mismo: un préstamo compartido
del rectángulo. En la función suelta el préstamo se llama `r` y su tipo se
escribe completo. En el método se llama `self` y `&self` lo abrevia. Los
campos se leen igual, con punto.

### [Regla 1:]{.prefijo} la llamada con punto es una llamada a función

```rust
struct Caja { valor: i32 }

impl Caja {
    fn ver(&self) -> &i32 {
        &self.valor
    }

    fn cambiar(&mut self, n: i32) {
        self.valor = n;
    }
}

fn main() {
    let mut caja = Caja { valor: 5 };

    caja.cambiar(10);
    Caja::cambiar(&mut caja, 20);   // la misma, desplegada

    println!("{}", caja.ver());        // 20
    println!("{}", Caja::ver(&caja));  // 20
}
```

Las dos formas de cada llamada compilan al mismo código. Con el punto, el
compilador busca el método en el tipo de `caja`, mira la forma de `self` en
la firma y toma el préstamo que esa firma pide. Lo que está antes del punto
pasa como primer argumento.

::: {.figura src="figuras/3.5-llamada.html"}
:::

En [3.3 Borrowing]{.ref}, `cambiar(&mut s)` avisaba en la llamada que la
función podía modificar el valor. Con un método ese aviso no se ve en la
llamada: `caja.cambiar(10)` y `caja.ver()` se escriben igual. El dato está
en la firma del método.

### [Regla 2:]{.prefijo} la forma de `self` decide qué recibe el método

::: {.figura src="figuras/3.5-self.html"}
:::

`&self` es la forma de `area` y de `ver`: el método lee y la instancia queda
intacta. `&mut self` es la forma de `cambiar`, y con él vuelve la exigencia
de siempre: el binding debe ser `mut`. Sin el `mut` de `let mut caja`, la
llamada `caja.cambiar(10)` da E0596: *cannot borrow `caja` as mutable*. El
mensaje dice *borrow* aunque el programa no escribe ningún `&`: el préstamo
lo tomó el punto.

La tercera forma, `self` sin `&`, mueve la instancia al método. Se usa
cuando, después de la operación, el valor original deja de tener sentido.
Una carta que ya se envió no se puede enviar otra vez:

```rust,compile_fail
struct Carta { texto: String }

impl Carta {
    fn enviar(self) {
        println!("Enviada: {}", self.texto);
    }   // self se libera aquí
}

fn main() {
    let carta = Carta { texto: String::from("Hola") };
    carta.enviar();
    carta.enviar();
}
```

```salida
error[E0382]: use of moved value: `carta`
10 |     let carta = Carta { texto: String::from("Hola") };
   |         ----- move occurs because `carta` has type
   |               `Carta`, which does not implement
   |               the `Copy` trait
11 |     carta.enviar();
   |           -------- `carta` moved due to this method call
12 |     carta.enviar();
   |     ^^^^^ value used here after move
note: `Carta::enviar` takes ownership of the receiver `self`,
      which moves `carta`
```

Es el mismo E0382 de [3.2 Ownership]{.ref}. La primera llamada es
`Carta::enviar(carta)`: pasa el valor, no un préstamo, y `carta` queda
movida. El error convierte una regla del dominio, "una carta se envía una
sola vez", en algo que el compilador revisa.

### Funciones asociadas: punto o dos puntos

Una función del bloque `impl` que no recibe `self` no opera sobre ninguna
instancia. El uso más común es construir una: por convención se llama `new`
y devuelve `Self`.

```rust
struct Rectangulo { ancho: u32, alto: u32 }

impl Rectangulo {
    fn new(ancho: u32, alto: u32) -> Self {
        Self { ancho, alto }
    }

    fn area(&self) -> u32 {
        self.ancho * self.alto
    }
}

fn main() {
    let hoja = Rectangulo::new(21, 30);   // se pide al tipo
    println!("{}", hoja.area());          // a la instancia
}
```

`String::from("hola")` y `String::new()` eran esto desde el principio:
funciones asociadas de `String`. El separador indica a quién se le pide el
trabajo: dos puntos al tipo, punto a una instancia. Cruzarlos no compila:
`hoja.new(1, 2)` da E0599, con la anotación *this is an associated
function, not a method*.

### [Regla 3:]{.prefijo} el borrow checker revisa las llamadas

Cada llamada a un método es un préstamo, y sigue la regla 1 de
[3.3 Borrowing]{.ref}. Mientras se use la referencia que devuelve `ver`,
el préstamo compartido de `caja` sigue vivo:

```rust,compile_fail
struct Caja { valor: i32 }

impl Caja {
    fn ver(&self) -> &i32 {
        &self.valor
    }

    fn cambiar(&mut self, n: i32) {
        self.valor = n;
    }
}

fn main() {
    let mut caja = Caja { valor: 5 };
    let v = caja.ver();    // préstamo compartido
    caja.cambiar(10);      // pide uno exclusivo
    println!("{v}");       // el compartido sigue en uso
}
```

```salida
error[E0502]: cannot borrow `caja` as mutable
              because it is also borrowed as immutable
15 |     let v = caja.ver();
   |             ---- immutable borrow occurs here
16 |     caja.cambiar(10);
   |     ^^^^^^^^^^^^^^^^ mutable borrow occurs here
17 |     println!("{v}");
   |                - immutable borrow later used here
```

Es el E0502 de [3.3 Borrowing]{.ref}, con los dos préstamos escritos como
llamadas. El arreglo también es el mismo: terminar de leer antes de
escribir. Varias llamadas a `ver` no chocan entre sí, porque todas piden
préstamos compartidos.

```rust
struct Caja { valor: i32 }

impl Caja {
    fn ver(&self) -> &i32 {
        &self.valor
    }

    fn cambiar(&mut self, n: i32) {
        self.valor = n;
    }
}

fn main() {
    let mut caja = Caja { valor: 5 };
    let a = caja.ver();
    let b = caja.ver();      // dos compartidos: válido
    println!("{a} y {b}");   // último uso de a y de b
    caja.cambiar(10);        // válido: no quedan préstamos
    println!("{}", caja.ver());   // 10
}
```

## Aplicación

Dos ejercicios del curso *Aprende Rust*. En el primero, un borrador se
escribe por partes y, al publicarse, se convierte en una publicación.

```rust
struct Borrador { texto: String }
struct Publicacion { texto: String }

impl Borrador {
    fn new() -> Self {
        Self { texto: String::new() }
    }

    fn escribir(&mut self, nuevo: &str) {
        self.texto.push_str(nuevo);
    }

    fn publicar(self) -> Publicacion {
        Publicacion { texto: self.texto }
    }
}

impl Publicacion {
    fn leer(&self) -> &str {
        &self.texto
    }
}

fn main() {
    let mut borrador = Borrador::new();
    borrador.escribir("Hola, ");
    borrador.escribir("Rust");

    let post = borrador.publicar();   // borrador queda movido
    println!("{}", post.leer());      // Hola, Rust
}
```

Cada firma sale del criterio de la tabla: `escribir` modifica, `leer`
consulta y `publicar` consume, porque un borrador publicado deja de ser
borrador. El `String` pasa de un struct al otro sin copiarse. `Publicacion`
no tiene método `escribir`: editar lo ya publicado no se puede ni escribir.

El segundo pone un método en un enum. El método empieza por averiguar qué
variante es `self`, con el `match` de [2.4 Patrones]{.ref}.

```rust
enum Operacion {
    Sumar(i32, i32),
    Multiplicar(i32, i32),
    Negar(i32),
}

impl Operacion {
    fn resultado(&self) -> i32 {
        match self {
            Operacion::Sumar(a, b) => a + b,
            Operacion::Multiplicar(a, b) => a * b,
            Operacion::Negar(n) => -n,
        }
    }
}

fn main() {
    let operaciones = [
        Operacion::Sumar(2, 3),
        Operacion::Multiplicar(4, 5),
        Operacion::Negar(7),
    ];

    for op in operaciones {
        println!("{}", op.resultado());   // 5, 20, -7
    }
}
```

Quien llama a `op.resultado()` no necesita saber qué variante tiene. El
`match` queda escrito una vez, dentro del tipo. Si el enum gana una
variante, el compilador señala este `match` como incompleto.

## A fondo

**`&self` es una abreviatura.** El parámetro se llama `self` y su tipo se
escribe en función de `Self`. Las formas largas son válidas y compilan
igual.

| Abreviado | Completo | Con `impl Caja` |
| :--- | :--- | :--- |
| `&self` | `self: &Self` | `self: &Caja` |
| `&mut self` | `self: &mut Self` | `self: &mut Caja` |
| `self` | `self: Self` | `self: Caja` |

**El punto también quita referencias.** Si lo que hay antes del punto ya es
una referencia, el compilador la sigue hasta encontrar el método. Por eso
con `c: &mut Caja` se escribe `c.cambiar(0)`, sin `*`: es la inserción
automática que [3.3 Borrowing]{.ref} anunció.

**Sacar un campo exige `self`.** Con `&self` el método solo tiene prestada
la instancia, y no puede mover un campo que no es suyo. Si `publicar`
recibiera `&self`, mover `self.texto` daría E0507: *cannot move out of
`self.texto` which is behind a shared reference*.

**`match self` detrás de `&self` entrega referencias.** En `resultado`,
`self` es un `&Operacion`, así que `a`, `b` y `n` son `&i32` y no `i32`. El
método no saca nada del enum: lo lee. La suma, el producto y el signo
aceptan referencias a enteros, y por eso no aparece ningún `*`.

**Un tipo admite varios bloques `impl`.** Todos se suman. Con lo visto
hasta aquí no hay motivo para separarlos. El motivo llega en
[4.1 Traits]{.ref}, donde cada trait que un tipo implementa lleva su bloque.
