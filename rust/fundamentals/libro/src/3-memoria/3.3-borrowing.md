# 3.3 · Borrowing

Con las reglas de [3.2 Ownership]{.ref}, pasar un `String` a una función lo
entrega para siempre. Para medir un texto había que devolverlo junto con su
longitud. Leer un valor no debería costar su propiedad.

Rust lo resuelve con el préstamo: una función puede usar un valor sin ser su
dueña. El compilador vigila que ningún préstamo deje al programa en un estado
inválido, y la parte que lo vigila se llama *borrow checker*.

## Definiciones y reglas

Referencia
:   un puntero a un valor que no es su dueño. `&T` permite leer; `&mut T`
    permite además modificar.

Prestar
:   *(borrow)*: crear una referencia. El dueño conserva el valor y lo
    recupera cuando la referencia deja de usarse.

::: {.reglas titulo="Las dos reglas del borrow checker"}
1. En cada momento puede haber una referencia `&mut`, o cualquier número de
   referencias `&`. Nunca las dos cosas a la vez.
2. Toda referencia debe ser siempre válida.
:::

## De un vistazo

Hay tres formas de recibir un valor, y la firma de la función dice cuál se usa.

| Escrito | Qué es | ¿Puede modificar? | ¿Cuántas a la vez? |
| :--- | :--- | :--- | :--- |
| `String` | el valor, con su dueño | sí, si el binding es `mut` | un solo dueño |
| `&String` | préstamo compartido | no | cualquier número |
| `&mut String` | préstamo exclusivo | sí | una, y ninguna otra |

Criterio para escribir una firma: `&T` por default, `&mut T` si la función
modifica el valor, y `T` solo si se queda con él.

## Las reglas, una por una

Antes de las reglas, los dos tipos de préstamo.

### El primer préstamo: `&`

La función que medía un texto ya no necesita devolverlo:

```rust
fn longitud(s: &String) -> usize {
    s.len()
}   // s desaparece aquí, y no libera nada: no es dueña

fn main() {
    let s1 = String::from("hola");
    let n = longitud(&s1);          // se presta, no se mueve
    println!("{s1} mide {n} bytes"); // s1 sigue siendo válida
}
```

El `&` aparece dos veces. En la llamada, `&s1` crea la referencia. En la
firma, `&String` es el tipo del parámetro: una referencia a un `String`.

### Prestar para modificar: `&mut`

Una referencia `&` solo permite leer. Modificar a través de ella no compila:

```rust,compile_fail
fn cambiar(texto: &String) {
    texto.push_str(", mundo");
}

fn main() {
    let s = String::from("hola");
    cambiar(&s);
}
```

```salida
error[E0596]: cannot borrow `*texto` as mutable,
              as it is behind a `&` reference
2 |     texto.push_str(", mundo");
  |     ^^^^^ `texto` is a `&` reference,
  |           so it cannot be borrowed as mutable
help: consider changing this to be a mutable reference
1 | fn cambiar(texto: &mut String) {
  |                    +++
```

El propio mensaje trae el arreglo. Con `&mut`, el préstamo permite modificar:

```rust
fn cambiar(texto: &mut String) {
    texto.push_str(", mundo");
}

fn main() {
    let mut s = String::from("hola");
    cambiar(&mut s);
    println!("{s}");   // hola, mundo
}
```

El `mut` se escribe en tres lugares: en el binding (`let mut s`), al prestar
(`&mut s`) y en el tipo del parámetro (`&mut String`). La llamada
`cambiar(&mut s)` avisa por sí sola que la función puede cambiar el valor.

Para llegar al valor detrás de una referencia se usa `*`. Con los métodos no
hace falta, porque Rust lo inserta solo:

```rust
fn sumar(acc: &mut i32, n: i32) {
    *acc += n;   // modifica el i32 prestado
}

fn main() {
    let mut total = 0;
    sumar(&mut total, 5);
    println!("{total}");   // 5
}
```

### [Regla 1:]{.prefijo} una exclusiva o varias compartidas

::: {.figura src="figuras/3.3-regla1.html"}
:::

Quien tiene una referencia `&` cuenta con que el valor no cambie mientras lo
lee. Una `&mut` viva al mismo tiempo rompería esa garantía:

```rust,compile_fail
fn main() {
    let mut s = String::from("hola");
    let r1 = &s;
    let r2 = &mut s;
    r2.push('!');
    println!("{r1}");
}
```

```salida
error[E0502]: cannot borrow `s` as mutable
              because it is also borrowed as immutable
3 |     let r1 = &s;
  |              -- immutable borrow occurs here
4 |     let r2 = &mut s;
  |              ^^^^^^ mutable borrow occurs here
6 |     println!("{r1}");
  |                -- immutable borrow later used here
```

Dos `&mut` a la vez tampoco se admiten, por la misma razón: cada una asumiría
que nadie más escribe.

```rust,compile_fail
fn main() {
    let mut s = String::from("hola");
    let r1 = &mut s;
    let r2 = &mut s;   // E0499: cannot borrow `s` as mutable
    r1.push('!');      //        more than once at a time
    r2.push('?');
}
```

Es la misma condición que evita una carrera de datos entre hilos: dos accesos
al mismo dato, al menos uno de escritura, sin coordinación. Rust la rechaza al
compilar, también en programas de un solo hilo.

### Un préstamo dura hasta su último uso

Un préstamo no dura hasta la llave que cierra el bloque. Termina en la última
línea que usa la referencia. Este programa compila:

```rust
fn main() {
    let mut s = String::from("hola");

    let r1 = &s;
    let r2 = &s;
    println!("{r1} y {r2}");   // último uso de r1 y r2

    let r3 = &mut s;           // válido: no quedan préstamos
    r3.push('!');
    println!("{r3}");
}
```

Por eso muchos errores de préstamo se arreglan reordenando: terminar de leer
antes de empezar a escribir.

### [Regla 2:]{.prefijo} toda referencia es válida

Una referencia no puede sobrevivir al valor al que apunta. El caso típico es
devolver una referencia a una variable local:

```rust,compile_fail
fn colgante() -> &String {
    let s = String::from("hola");
    &s   // s se libera al terminar la función
}

fn main() {
    let r = colgante();
    println!("{r}");
}
```

```salida
error[E0106]: missing lifetime specifier
1 | fn colgante() -> &String {
  |                  ^ expected named lifetime parameter
help: this function's return type contains a borrowed value,
      but there is no value for it to be borrowed from
help: instead, you are more likely to want to return
      an owned value
```

`s` se libera al cerrar la función, y la referencia apuntaría a memoria ya
devuelta. En C eso compila y falla al ejecutar. El mensaje habla de
*lifetimes*, que es la herramienta con la que el compilador mide cuánto vive
cada referencia ([3.6 Lifetimes]{.ref}). El arreglo que propone es el correcto:
devolver el `String` y mover la propiedad a quien llama.

## Aplicación

Una carta se firma y después se mide. La firma decide qué recibe cada función
con el criterio de la tabla: `firmar` modifica la carta, así que pide `&mut`;
al autor solo lo lee, así que pide `&`.

```rust
fn firmar(carta: &mut String, autor: &String) {
    carta.push_str("\nAtentamente, ");
    carta.push_str(autor);
}

fn longitud(texto: &String) -> usize {
    texto.len()
}

fn main() {
    let autor = String::from("Ferris");
    let mut carta = String::from("Hola, Rust.");

    firmar(&mut carta, &autor);
    println!("{carta}");
    println!("{} bytes, por {autor}", longitud(&carta));
}
```

Ninguna función se quedó con nada. Al final de `main`, `carta` y `autor`
siguen siendo las dueñas y se pueden seguir usando. El préstamo exclusivo de
`firmar` terminó al volver de la llamada, y por eso `longitud` puede pedir uno
compartido en la línea siguiente.

## A fondo

**`mut` es del binding, no del tipo.** No existe un `String` mutable y otro
inmutable. Existe un valor al que un binding concreto permite o no permite
modificar. Al mover el valor, la decisión se toma de nuevo.

```rust
fn main() {
    let a = String::from("hola");   // binding inmutable
    let mut b = a;                  // se mueve a uno mutable
    b.push('!');                    // válido: decide el nuevo
    println!("{b}");
}
```

**`let mut x` y `&mut x` no son lo mismo.** El primero declara qué puede
hacer el dueño. El segundo presta el derecho a modificar, y exige que el
binding sea `mut`.

| Escrito | Qué declara | Quién puede modificar |
| :--- | :--- | :--- |
| `let x` | binding inmutable | nadie |
| `let mut x` | binding mutable | el dueño |
| `&x` | referencia compartida | nadie mientras viva |
| `&mut x` | referencia exclusiva | quien la recibe |

**Una referencia también es un valor.** Su binding puede ser mutable a su
vez, y entonces la referencia se puede reapuntar.

```rust
fn main() {
    let mut a = 1;
    let mut b = 2;
    let mut r = &mut a;   // binding mutable de una referencia
    *r += 10;             // modifica a
    r = &mut b;           // reapunta: lo permite `let mut r`
    *r += 10;             // modifica b
    println!("{a} {b}");  // 11 12
}
```

`*r += 10` cambia el dato prestado. `r = &mut b` cambia a dónde apunta el
binding.
