# 3.4 · Strings

El texto en Rust sorprende dos veces. Hay dos tipos donde otros lenguajes
tienen uno, `String` y `&str`. Y lo más básico, pedir la primera letra con
`s[0]`, no compila.

Ninguna de las dos cosas es un capricho. La primera es la distinción entre
dueño y préstamo de [3.2 Ownership]{.ref} y [3.3 Borrowing]{.ref}, aplicada al
texto. La segunda sale de que el texto es UTF-8, y en UTF-8 una letra no
siempre ocupa un byte.

## Definiciones y reglas

`String`
:   texto con dueño. Vive en el heap y puede crecer.

`&str`
:   *(string slice)*: préstamo de una porción de texto que posee alguien más.
    No puede crecer ni modificarse.

::: {.reglas titulo="Las tres reglas del texto"}
1. Todo texto es UTF-8: cada carácter ocupa de uno a cuatro bytes.
2. `.len()` y los índices cuentan bytes, no caracteres.
3. Un slice debe cortar en la frontera entre dos caracteres.
:::

## De un vistazo

| | `String` | `&str` |
| :--- | :--- | :--- |
| ¿Es dueño del texto? | sí | no: lo toma prestado |
| ¿Puede crecer? | sí, si el binding es `mut` | no |
| Dónde está el texto | en el heap | en el heap o en el binario |
| Qué hay en el stack | `ptr`, `len`, `cap` | `ptr`, `len` |
| Cómo se obtiene | `String::from("x")` | `"x"`, `&s`, `&s[a..b]` |

Criterio para una firma: una función que solo lee texto recibe `&str`. Así
acepta un literal, un `String` prestado o un pedazo de cualquiera de los dos.

## Las reglas, una por una

Antes de las reglas, los dos tipos y cómo se pasa de uno al otro.

### Dos tipos para un solo texto

```rust
fn main() {
    let prestado: &str = "hola";                // en el binario
    let propio: String = String::from("hola");  // en el heap
    let otra_vez: &str = &propio;               // préstamo
    println!("{prestado} {propio} {otra_vez}");
}
```

Un literal como `"hola"` queda grabado en el ejecutable. No tiene dueño que lo
libere, así que solo se puede tomar prestado: por eso su tipo es `&str`.

Un `&String` se convierte a `&str` solo. La última línea de asignación lo
muestra: `&propio` es un `&String`, y se guarda en un `&str` sin escribir nada
más.

### Construir un `String` y hacerlo crecer

```rust
fn main() {
    let nombre = String::from("Ferris");
    let patas = 8;

    let mut saludo = String::new();   // vacío
    saludo.push_str("Hola, ");        // agrega un &str
    saludo.push_str(&nombre);         // presta nombre
    saludo.push('!');                 // agrega un solo char

    let ficha = format!("{nombre} tiene {patas} patas");

    println!("{saludo}");   // Hola, Ferris!
    println!("{ficha}");    // Ferris tiene 8 patas
}
```

`push_str` recibe un `&str`: toma prestado el texto que agrega, y `nombre`
sigue disponible para el `format!`. `format!` funciona como `println!`, pero
devuelve el `String` en lugar de imprimirlo, y tampoco mueve nada.

### Slices: prestar una parte

El problema que resuelven aparece al buscar la primera palabra de una frase.
Una primera versión devuelve la posición donde termina:

```rust
fn fin_primera_palabra(s: &String) -> usize {
    for (i, c) in s.char_indices() {
        if c == ' ' {
            return i;
        }
    }
    s.len()
}

fn main() {
    let mut frase = String::from("hola mundo");
    let fin = fin_primera_palabra(&frase);   // 4
    frase.clear();                           // queda vacía
    println!("{fin}");                       // sigue diciendo 4
}
```

El programa compila y está mal. El `4` es un número suelto: nada lo ata a
`frase`, y cuando la frase cambia nadie avisa.

Un slice es una referencia a una porción del texto. Se escribe `&s[a..b]`, con
`a` incluido y `b` excluido, y los dos extremos se pueden omitir.

| Escrito | Equivale a | Sobre `"hola mundo"` |
| :--- | :--- | :--- |
| `&s[0..4]` | | `hola` |
| `&s[..4]` | `&s[0..4]` | `hola` |
| `&s[5..]` | `&s[5..10]` | `mundo` |
| `&s[..]` | `&s[0..10]` | `hola mundo` |

::: {.figura src="figuras/3.4-slice.html"}
:::

Con un slice, la función devuelve la palabra y no su posición:

```rust,compile_fail
fn primera_palabra(s: &String) -> &str {
    for (i, c) in s.char_indices() {
        if c == ' ' {
            return &s[..i];
        }
    }
    &s[..]
}

fn main() {
    let mut frase = String::from("hola mundo");
    let palabra = primera_palabra(&frase);
    frase.clear();
    println!("{palabra}");
}
```

```salida
error[E0502]: cannot borrow `frase` as mutable
              because it is also borrowed as immutable
12 |     let palabra = primera_palabra(&frase);
   |                                   ------ immutable borrow
13 |     frase.clear();
   |     ^^^^^^^^^^^^^ mutable borrow occurs here
14 |     println!("{palabra}");
   |                ------- immutable borrow later used here
```

`palabra` es un préstamo de `frase`, y `clear` necesita modificarla. Es la
regla 1 del borrow checker. El mismo descuido que antes pasaba en silencio es
ahora un error de compilación.

### [Regla 1:]{.prefijo} un carácter no es un byte

::: {.figura src="figuras/3.4-utf8.html"}
:::

En UTF-8 las letras sin acento ocupan un byte. La `ñ` y las vocales con
acento ocupan dos, el signo `€` tres, y un emoji cuatro. Por eso pedir "la
posición 0" es ambiguo: puede ser el primer byte o el primer carácter. Rust no
elige, y quita la operación:

```rust,compile_fail
fn main() {
    let s = String::from("hola");
    let c = s[0];
}
```

```salida
error[E0277]: the type `str` cannot be indexed by `{integer}`
3 |     let c = s[0];
  |               ^ string indices are ranges of `usize`
  = note: you can use `.chars().nth()` or `.bytes().nth()`
```

### [Regla 2:]{.prefijo} `.len()` y los índices cuentan bytes

```rust
fn main() {
    let s = String::from("café");
    println!("{}", s.len());             // 5: bytes
    println!("{}", s.chars().count());   // 4: caracteres
}
```

Para recorrer un texto hay tres vistas, y cada una responde una pregunta
distinta:

```rust
fn main() {
    let s = "año";
    for c in s.chars() {
        print!("[{c}]");      // [a][ñ][o]
    }
    println!();
    for (i, c) in s.char_indices() {
        print!("{i}:{c} ");   // 0:a 1:ñ 3:o
    }
    println!();
}
```

`.chars()` entrega caracteres y `.bytes()` entrega bytes. `.char_indices()`
entrega cada carácter con el índice del byte donde empieza: de la `ñ` a la `o`
salta del 1 al 3.

### [Regla 3:]{.prefijo} un slice corta en frontera de carácter

Los rangos de un slice también cuentan bytes. Si un extremo cae a media
letra, el compilador no puede saberlo y el programa falla al ejecutar:

```rust,should_panic
fn main() {
    let s = String::from("ñandú");
    let primera = &s[0..1];   // la ñ ocupa los bytes 0 y 1
    println!("{primera}");
}
```

```salida
thread 'main' panicked at src/main.rs:3:21:
byte index 1 is not a char boundary;
it is inside 'ñ' (bytes 0..2) of `ñandú`
```

En español esto aparece con la primera `ñ` o el primer acento. Los índices
seguros son los que entrega `.char_indices()`, como en `primera_palabra`.

## Aplicación

Dos ejercicios del curso *Aprende Rust*. El primero quita la extensión de un
nombre de archivo. Recibe `&str` para aceptar literales y `String` prestados,
y devuelve un slice del mismo texto: no copia nada.

```rust
fn sin_extension(nombre: &str) -> &str {
    for (i, c) in nombre.char_indices() {
        if c == '.' {
            return &nombre[..i];   // i es una frontera segura
        }
    }
    nombre
}

fn main() {
    let archivo = String::from("foto.png");
    println!("{}", sin_extension(&archivo));      // foto
    println!("{}", sin_extension("notas.txt"));   // notas
    println!("{}", sin_extension("README"));      // README
}
```

El segundo cuenta vocales sin distinguir mayúsculas y contando las que llevan
acento. Recorre con `.chars()` por la regla 1: comparar bytes no encontraría
la `é`.

```rust
fn contar_vocales(texto: &str) -> usize {
    let mut cuenta = 0;
    for c in texto.to_lowercase().chars() {
        if matches!(c, 'a' | 'e' | 'i' | 'o' | 'u'
                     | 'á' | 'é' | 'í' | 'ó' | 'ú') {
            cuenta += 1;
        }
    }
    cuenta
}

fn main() {
    println!("{}", contar_vocales("Murciélago"));   // 5
}
```

`"Murciélago"` mide 11 bytes y tiene 10 caracteres, de los cuales 5 son
vocales.

## A fondo

**Un `&str` mide el doble que un `&String`.** Una referencia normal es un
puntero: 8 bytes. Un `&str` lleva además la longitud de su porción, así que
ocupa 16. Es lo que le permite apuntar a la mitad de un texto sin copiarlo.

**Por qué `&str` y no `&String` en los parámetros.** `&String` se convierte
a `&str` solo, pero no al revés: un literal no es un `String`. Una función que
pide `&String` rechaza los literales y los slices; una que pide `&str` acepta
todo.

**Qué métodos prestan y cuáles crean.** Un método que solo recorta devuelve
un `&str`, una vista del texto original. Uno que cambia letras no puede
hacerlo, porque el resultado no existe en ningún buffer: tiene que crear un
`String` nuevo.

| Método | Devuelve | Por qué |
| :--- | :--- | :--- |
| `.trim()` | `&str` | es una porción del mismo texto |
| `.to_uppercase()` | `String` | las letras cambian |
| `.replace(a, b)` | `String` | el largo puede cambiar |

**`+` consume el operando izquierdo.** La concatenación con `+` reutiliza el
buffer del primer `String`: lo toma, le agrega el segundo y lo devuelve. El
primero queda movido.

```rust,compile_fail
fn main() {
    let hola = String::from("hola");
    let mundo = String::from(", mundo");
    let saludo = hola + &mundo;   // hola se mueve
    println!("{hola} {saludo}");  // E0382: hola ya no es válida
}
```

`format!("{hola}{mundo}")` hace lo mismo sin mover ninguno de los dos.

**Los literales viven todo el programa.** Como están en el binario, nunca se
liberan. Su tipo completo es `&'static str`, donde `'static` es el lifetime
que dura toda la ejecución ([3.6 Lifetimes]{.ref}).
