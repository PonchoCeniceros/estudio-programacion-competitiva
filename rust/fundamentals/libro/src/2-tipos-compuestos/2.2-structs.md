# 2.2 · Structs

Una tupla agrupa valores de tipos distintos, pero no les da nombre
([2.1 Tuplas y arreglos]{.ref}). En `let u = ("Ana", 31, true);` el código
lee `u.1` y `u.2`, y quien lo revisa tiene que preguntarse qué era `.1`. Con
dos tuplas de la misma forma, nada impide confundir una con otra.

El *struct* resuelve las dos cosas. Le pone nombre a cada dato y nombre al
conjunto. El resultado es un tipo propio, con la forma fija que el
compilador revisa en cada uso.

## Definiciones y reglas

Struct
:   un tipo definido por el programa que agrupa varios valores bajo un
    nombre. Su definición lista los campos y no guarda ningún valor.

Campo
:   *(field)*: cada uno de los valores de un struct, con su nombre y su
    tipo. Se lee con un punto: `u.edad`.

Instancia
:   un valor concreto del struct, con un valor para cada campo.

::: {.reglas titulo="Las tres reglas de un struct"}
1. Una instancia da un valor a cada campo, en el orden que sea.
2. La mutabilidad es de la instancia entera, no de cada campo.
3. Cada struct es un tipo distinto, aunque otro tenga la misma forma.
:::

## De un vistazo

Hay tres clases de struct. Se distinguen por cómo nombran sus campos.

| Clase | Definición | Instancia | Acceso |
| :--- | :--- | :--- | :--- |
| con campos | `struct P { x: i32 }` | `P { x: 1 }` | `p.x` |
| *tuple struct* | `struct C(u8, u8);` | `C(255, 0)` | `c.0` |
| *unit struct* | `struct M;` | `M` | sin campos |

Criterio: campos con nombre por default; tuple struct cuando el nombre del
tipo ya explica los datos; unit struct cuando no hay datos que guardar.

## Las reglas, una por una

Primero la definición y la instancia; después, cada regla.

### Definir y crear una instancia

La definición va fuera de `main`, con la palabra `struct`, el nombre del tipo
en *PascalCase* y los campos entre llaves:

```rust
struct Usuario {
    nombre: String,
    edad: u8,
    activo: bool,
}

fn main() {
    let ana = Usuario {
        nombre: String::from("Ana"),
        edad: 31,
        activo: true,
    };
    println!("{} tiene {} años", ana.nombre, ana.edad);
    println!("activo: {}", ana.activo);
}
```

La instancia repite el nombre del tipo y da `campo: valor` para cada campo.
Cada campo se lee con un punto, por su nombre, sin depender de su posición.

### [Regla 1:]{.prefijo} todos los campos, en cualquier orden

El orden de los campos en la instancia no tiene que seguir al de la
definición. `Usuario { edad: 31, activo: true, nombre: ... }` es la misma
instancia. Lo que no se admite es dejar un campo sin valor:

```rust,compile_fail
struct Usuario {
    nombre: String,
    edad: u8,
    activo: bool,
}

fn main() {
    let u = Usuario {
        nombre: String::from("Ana"),
        edad: 31,
    };
}
```

```salida
error[E0063]: missing field `activo` in initializer of
              `Usuario`
8 |     let u = Usuario {
  |             ^^^^^^^ missing `activo`
```

No existe un valor implícito para un campo olvidado. Una instancia siempre
está completa, y por eso leer cualquiera de sus campos es seguro.

### [Regla 2:]{.prefijo} la mutabilidad es de la instancia

Igual que con cualquier variable ([1.3 Variables]{.ref}), una instancia sin
`mut` no cambia. Eso incluye a cada uno de sus campos:

```rust,compile_fail
struct Punto {
    x: i32,
    y: i32,
}

fn main() {
    let p = Punto { x: 1, y: 2 };
    p.x = 10;
}
```

```salida
error[E0594]: cannot assign to `p.x`, as `p` is not
              declared as mutable
8 |     p.x = 10;
  |     ^^^^^^^^ cannot assign
help: consider changing this to be mutable
7 |     let mut p = Punto { x: 1, y: 2 };
  |         +++
```

Con `let mut p`, todos los campos se pueden asignar. No hay forma de marcar
un solo campo como mutable: escribir `mut y: i32` dentro de la definición es
un error de sintaxis. La decisión se toma una vez, al crear el binding.

### Sintaxis abreviada de campos

Una función que construye la instancia suele recibir parámetros con los
mismos nombres que los campos. Entonces `nombre: nombre` se puede escribir
solo `nombre`:

```rust
struct Usuario {
    nombre: String,
    edad: u8,
    activo: bool,
}

fn nuevo_usuario(nombre: String, edad: u8) -> Usuario {
    Usuario { nombre, edad, activo: true }
}

fn main() {
    let u = nuevo_usuario(String::from("Beto"), 27);
    println!("{} tiene {} años", u.nombre, u.edad);
}
```

Las dos formas se mezclan sin problema: `nombre` y `edad` van abreviados,
`activo` lleva su valor explícito. Una función así hace el papel de un
constructor. En [3.5 impl y métodos]{.ref} pasa a vivir dentro del tipo.

### Actualización con `..otra`

Para crear una instancia parecida a otra se escriben solo los campos que
cambian. `..base` al final toma el resto de `base`:

```rust
struct Config {
    ancho: u32,
    alto: u32,
    vsync: bool,
}

fn main() {
    let base = Config { ancho: 800, alto: 600, vsync: true };
    let grande = Config { ancho: 1920, alto: 1080, ..base };
    println!("{} x {}", grande.ancho, grande.alto);
    println!("{} x {}", base.ancho, base.alto);
}
```

`..base` va siempre al final, y no se le pone coma después. Aquí los campos
que toma son números y booleanos, que se copian: `base` sigue completa y se
puede usar.

Si `..base` tomara un campo `String`, ese campo pasaría a la instancia nueva
y `base` dejaría de poder usarse como un todo. El mecanismo es el *move* de
[3.2 Ownership]{.ref}.

### [Regla 3:]{.prefijo} tuple structs: tipos distintos

Un tuple struct tiene nombre de tipo, pero sus campos no tienen nombre. Se
leen por posición, como en una tupla:

```rust
struct Color(u8, u8, u8);

fn main() {
    let naranja = Color(255, 165, 0);
    println!("{} {} {}", naranja.0, naranja.1, naranja.2);
}
```

La diferencia con una tupla está en el tipo. Abajo, `Color` y `Punto`
tienen la misma forma, y aun así el compilador no acepta uno donde se pide
el otro:

```rust,compile_fail
struct Color(u8, u8, u8);
struct Punto(u8, u8, u8);

fn brillo(c: Color) -> u8 {
    c.0 / 3 + c.1 / 3 + c.2 / 3
}

fn main() {
    let p = Punto(10, 20, 30);
    println!("{}", brillo(p));
}
```

```salida
error[E0308]: mismatched types
10 |     println!("{}", brillo(p));
   |                    ------ ^ expected `Color`,
   |                    |        found `Punto`
   |                    arguments to this function are
   |                    incorrect
```

Con una tupla `(u8, u8, u8)` las dos cosas serían el mismo tipo, y el error
pasaría inadvertido. La regla vale igual para los structs con campos: dos
definiciones con los mismos campos son dos tipos.

### Unit structs

Un unit struct no tiene campos. Se declara sin llaves ni paréntesis, y su
única instancia se escribe con el puro nombre:

```rust
struct Marcador;

fn main() {
    let _m = Marcador;
}
```

No guarda datos, pero es un tipo con identidad propia. Sirve de marcador: un
concepto al que más adelante se le da comportamiento, con los métodos de
[3.5 impl y métodos]{.ref} y los traits de [4.1 Traits]{.ref}.

### Imprimir un struct

`println!` con `{}` imprime números y texto. Con un struct no compila:

```rust,compile_fail
struct Punto {
    x: i32,
    y: i32,
}

fn main() {
    let p = Punto { x: 1, y: 2 };
    println!("{}", p);
}
```

```salida
error[E0277]: `Punto` doesn't implement
              `std::fmt::Display`
8 |     println!("{}", p);
  |               --   ^ `Punto` cannot be formatted
  |               |      with the default formatter
  |               required by this formatting parameter
  = note: in format strings you may be able to use `{:?}`
          (or {:#?} for pretty-print) instead
```

`{}` pide un formato para personas, y Rust no adivina cómo mostrar un tipo
nuevo. `{:?}` pide el formato de depuración, que se puede generar solo. Para
eso se escribe `#[derive(Debug)]` encima de la definición:

```rust
#[derive(Debug)]
struct Punto {
    x: i32,
    y: i32,
}

fn main() {
    let p = Punto { x: 1, y: 2 };
    println!("{:?}", p);   // Punto { x: 1, y: 2 }
    println!("{:#?}", p);
    // Punto {
    //     x: 1,
    //     y: 2,
    // }
}
```

`{:?}` imprime todo en una línea. `{:#?}` pone un campo por línea, con
sangría, y se lee mejor cuando el struct es grande. `#[...]` es un
*atributo*, una anotación para el compilador. `Debug` es un trait, y
`derive` lo implementa sin escribir código; los dos temas vuelven en
[4.4 Traits de la stdlib]{.ref}.

### `dbg!`

La macro `dbg!` imprime el archivo, la línea, la expresión y su valor. Además
devuelve el valor, así que se puede meter en medio de una expresión sin
cambiar lo que calcula:

```rust
#[derive(Debug)]
struct Rectangulo {
    ancho: u32,
    alto: u32,
}

fn main() {
    let escala = 2;
    let r = Rectangulo {
        ancho: dbg!(30 * escala),
        alto: 50,
    };
    println!("{:?}", r);
}
```

Al correr, `dbg!` imprime `[src/main.rs:10:16] 30 * escala = 60`
y devuelve el 60, que queda en `ancho`. El `println!` muestra después
`Rectangulo { ancho: 60, alto: 50 }`.

`dbg!` escribe en la salida de errores, no en la estándar, así que no se
mezcla con lo que el programa produce. Aplicado a una variable, `dbg!` se
queda con ella; la forma habitual de usarla con un struct es `dbg!(&r)`, que
necesita las referencias de [3.3 Borrowing]{.ref}.

## Aplicación

Un plano registra cuartos con su largo y su ancho en centímetros. Un struct
con campos guarda cada cuarto, y una función suelta calcula su área.

```rust
#[derive(Debug)]
struct Cuarto {
    nombre: String,
    largo: u32, // cm
    ancho: u32, // cm
}

fn cuarto(nombre: String, largo: u32, ancho: u32) -> Cuarto {
    Cuarto { nombre, largo, ancho }
}

fn describir(c: Cuarto) {
    let m2 = (c.largo * c.ancho) as f64 / 10_000.0;
    println!("{}: {m2} m²", c.nombre);
}

fn main() {
    let sala = cuarto(String::from("sala"), 450, 380);
    let mut estudio = Cuarto {
        nombre: String::from("estudio"),
        ..sala
    };
    estudio.ancho = 300;

    println!("{:?}", estudio);
    // Cuarto { nombre: "estudio", largo: 450, ancho: 300 }
    describir(sala);      // sala: 17.1 m²
    describir(estudio);   // estudio: 13.5 m²
}
```

`cuarto` usa la sintaxis abreviada. `estudio` da su propio `nombre` y toma
de `sala` solo los dos números, así que `sala` sigue completa. `estudio`
lleva `mut` para poder cambiar su ancho. `describir` recibe el cuarto entero,
y `main` no lo vuelve a usar después de la llamada: la razón está en
[3.2 Ownership]{.ref}. Escrita como método, la llamada sería
`sala.describir()` ([3.5 impl y métodos]{.ref}).

## A fondo

**Un campo que nadie lee genera un aviso.** Si un campo se escribe pero
nunca se lee, `rustc` lo señala con `warning: field ... is never read`. El
aviso no impide compilar. `#[derive(Debug)]` no cuenta como lectura: imprimir
el struct con `{:?}` no lo silencia.

**El orden en memoria lo decide el compilador.** Rust no promete que los
campos queden en memoria en el orden de la definición. Puede reordenarlos
para ahorrar relleno: un struct con un `u8`, un `u32` y otro `u8`, en ese
orden, ocupa 8 bytes y no 12.

**Un tuple struct de un campo crea un tipo nuevo sin costo.** El patrón se
llama *newtype*: `struct Metros(f64);` ocupa lo mismo que un `f64`, pero el
compilador no acepta unos donde se piden los otros.

```rust
struct Metros(f64);
struct Pies(f64);

fn main() {
    let pared = Metros(3.5);
    let tabla = Pies(8.0);
    println!("{} m y {} ft", pared.0, tabla.0);
}
```

**Un unit struct ocupa cero bytes.** No tiene datos que guardar, así que su
tamaño es 0. Crear instancias de un unit struct no cuesta memoria.
