# 2.4 · Patrones

En [2.3 Enums]{.ref}, cada rama del `match` sacaba los datos de su variante:
`Forma::Circulo(r)` encajaba con un círculo y dejaba el radio en `r`. Esa mitad
izquierda de la rama es un patrón. Hasta aquí solo ha servido para distinguir
variantes.

Falta todo lo demás. Preguntar si la `x` de un punto vale cero, si una edad cae
entre 4 y 12, o sacar los campos de un struct sin escribir `p.x` y `p.y`. Sin
patrones, eso es una cadena de `if` y de accesos por campo. Con ellos es una
rama por caso, y el compilador revisa que no falte ninguno.

## Definiciones y reglas

Patrón
:   *(pattern)*: la forma contra la que se compara un valor. Si el valor
    encaja, los nombres del patrón quedan ligados a sus partes.

Desestructurar
:   *(destructuring)*: abrir un valor compuesto en sus partes con un patrón.

Ligar
:   *(binding)*: darle un nombre a una parte del valor. El nombre vale en la
    rama o en el resto del bloque, según dónde esté el patrón.

Irrefutable y refutable
:   un patrón irrefutable encaja con cualquier valor de su tipo, como `x` o
    `(a, b)`. Uno refutable puede no encajar, como `0` o `Estado::Activo(n)`.

Guard
:   *(guard)*: condición `if` agregada a una rama de `match`. Se evalúa después
    de ligar los nombres.

::: {.reglas titulo="Las tres reglas de los patrones"}
1. Un patrón se escribe como la expresión que construye el valor: donde van
   valores, van nombres.
2. `let`, `for` y los parámetros solo aceptan patrones irrefutables.
3. Las ramas de un `match` se prueban en orden y gana la primera que encaja.
:::

## De un vistazo

| Tipo | Construir | Destructurar |
| :--- | :--- | :--- |
| Tupla | `let p = (1, 2);` | `let (x, y) = p;` |
| Struct | `let p = Punto { x: 1, y: 2 };` | `let Punto { x, y } = p;` |
| Enum | `let e = Estado::Activo(3);` | `if let Estado::Activo(n) = e` |
| Arreglo | `let a = [1, 2, 3];` | `let [primero, .., ultimo] = a;` |

La columna derecha repite la izquierda con nombres donde había valores. El enum
es la excepción: su patrón puede fallar, y por eso no va en un `let` simple
(regla 2).

## Las reglas, una por una

### [Regla 1:]{.prefijo} un constructor al revés

[2.1 Tuplas y arreglos]{.ref} ya abrió una tupla con `let (n, c, activo) = t;`.
El mismo mecanismo sirve para cualquier tipo compuesto. Con un struct:

```rust
struct Punto {
    x: i32,
    y: i32,
}

fn main() {
    let p = Punto { x: 3, y: 7 };       // construir
    let Punto { x, y } = p;             // destructurar
    println!("{x} {y}");                // 3 7

    let Punto { x: ancho, y: alto } = p;
    println!("{ancho} {alto}");         // 3 7
}
```

`Punto { x, y }` es la forma corta de `Punto { x: x, y: y }`: cada campo se
liga a una variable con su mismo nombre. La forma larga elige el nombre. A la
izquierda de los dos puntos va el campo y a la derecha, la variable nueva.

Un arreglo se abre por posiciones: `let [a, b, c] = [1, 2, 3];`. La fila del
arreglo en la tabla usa `..`, que salta los elementos de en medio; se trata
abajo, con las demás piezas.

El patrón tiene que tener la misma forma que el valor. Un `let (a, b)` sobre
una tupla de tres elementos no compila: no hay a dónde mandar el tercero.

### Dónde aparecen los patrones

`match` es el uso más visible, pero un patrón cabe en cualquier lugar donde se
liga un nombre:

```rust
fn suma((a, b): (i32, i32)) -> i32 {   // en un parámetro
    a + b
}

fn main() {
    let punto = (3, 7);
    let (x, y) = punto;                // en un let
    println!("{x} {y} {}", suma(punto));

    for (i, letra) in [(1, 'a'), (2, 'b')] {   // en un for
        println!("{i}{letra}");
    }
}
```

Todo `let` lleva un patrón. `let x = 5` es el caso trivial: un patrón de un solo
nombre, que encaja con cualquier valor. El parámetro `n: i32` de una función es
lo mismo.

### Campos que filtran y campos que ligan

Dentro de un patrón, cada campo puede llevar un valor o un nombre. Un valor
filtra: la rama solo encaja si el campo vale eso. Un nombre liga: encaja con
cualquier valor y lo guarda.

```rust
struct Punto {
    x: i32,
    y: i32,
}

fn describir(p: Punto) {
    match p {
        Punto { x: 0, y: 0 } => println!("el origen"),
        Punto { x: 0, y } => println!("eje Y, a {y}"),
        Punto { x, y: 0 } => println!("eje X, a {x}"),
        Punto { x, y } => println!("({x}, {y})"),
    }
}

fn main() {
    describir(Punto { x: 0, y: 7 });    // eje Y, a 7
}
```

:::

Con las variantes de un enum pasa lo mismo. Una variante con campos con nombre
se abre igual que un struct, y una con datos entre paréntesis, igual que una
tupla:

```rust
enum Evento {
    Clic { x: i32, y: i32 },
    Tecla(char),
}

fn atender(e: Evento) {
    match e {
        Evento::Tecla('q') => println!("salir"),
        Evento::Tecla(c) => println!("tecla {c}"),
        Evento::Clic { x: 0, y } => println!("borde: {y}"),
        Evento::Clic { x, y } => println!("clic: {x}, {y}"),
    }
}

fn main() {
    atender(Evento::Tecla('q'));             // salir
    atender(Evento::Clic { x: 0, y: 40 });   // borde: 40
}
```

`Evento::Tecla('q')` filtra por la letra; `Evento::Tecla(c)` acepta cualquier
otra y la liga a `c`.

### [Regla 2:]{.prefijo} refutables e irrefutables

Cada construcción decide qué pasa si el valor no encaja. Si no tiene a dónde ir,
solo acepta patrones que no puedan fallar.

| Construcción | Admite | Si el valor no encaja |
| :--- | :--- | :--- |
| `let`, `for`, parámetros | solo irrefutables | no hay otro camino |
| `match`, `if let`, `while let` | también refutables | otra rama, o se salta el bloque |
| `let … else` | refutables | corre el `else`, que debe salir |

Un `let` con el patrón de una sola variante no compila:

```rust,compile_fail
enum Estado {
    Activo(u32),
    Inactivo,
}

fn main() {
    let e = Estado::Activo(90);
    let Estado::Activo(minutos) = e;
    println!("{minutos}");
}
```

```salida
error[E0005]: refutable pattern in local binding
8 |     let Estado::Activo(minutos) = e;
  |         ^^^^^^^^^^^^^^^^^^^^^^^ pattern `Estado::Inactivo`
  |                                 not covered
```

El compilador no ve el valor `Activo(90)`: ve el tipo `Estado`, y un `Estado`
puede ser `Inactivo`. En ese caso `minutos` no tendría valor.

Un `if let` lo resuelve, pero `minutos` solo existe dentro de sus llaves, y el
resto de la función queda anidado. `let … else` da la otra salida sin anidar:

```rust
enum Estado {
    Activo(u32),
    Inactivo,
}

fn horas(e: Estado) -> u32 {
    let Estado::Activo(minutos) = e else {
        return 0;                   // sin minutos, no sigue
    };
    minutos / 60                    // minutos vive aquí
}

fn main() {
    println!("{}", horas(Estado::Activo(150)));   // 2
    println!("{}", horas(Estado::Inactivo));      // 0
}
```

Si el patrón encaja, los nombres quedan ligados para el resto de la función. Si
no, corre el bloque del `else`, que tiene que salir con `return`, `break`,
`continue` o un *panic*. Esa salida obligatoria es lo que garantiza que
`minutos` tenga valor en la línea siguiente.

Entre las tres construcciones refutables, el criterio es cuántos casos
importan:

| Construcción | Cuándo |
| :--- | :--- |
| `match` | todos los casos importan y cada uno hace algo |
| `if let` | solo importa uno; los demás no hacen nada |
| `let … else` | sin ese dato no tiene sentido continuar |

### [Regla 3:]{.prefijo} el orden de las ramas

En `describir`, el origen encaja con las cuatro ramas, y gana la primera. Por
eso los casos particulares van arriba y los generales abajo. Al revés, el caso
general se come a los demás, y el compilador avisa:

```rust
fn describir(n: i32) {
    match n {
        _ => println!("otro"),
        0 => println!("cero"),
    }
}

fn main() {
    describir(0);                       // otro
}
```

<span class="g">3 |</span>         _ =&gt; println!(&quot;otro&quot;),
<span class="g">  |         - matches any value</span>
<span class="g">4 |</span>         0 =&gt; println!(&quot;cero&quot;),
<span class="g">  |         </span><span class="x">^ no value can reach this</span></code></pre>

Es un aviso y no un error: el programa compila e imprime `otro` para el cero.
`_` encaja con cualquier valor, así que la rama del `0` nunca se prueba.

### Guards, rangos, alternativas y `@`

Además de valores y nombres, un patrón tiene piezas para describir conjuntos de
valores:

---------------  -------------------------------------------
Sintaxis         Qué hace
---------------  -------------------------------------------
`1..=9`          rango inclusivo: del 1 al 9

`65..`           rango abierto: del 65 en adelante

`10 | 20`        alternativa: encaja con cualquiera de los dos

`d @ 1..=9`      liga el valor **y** comprueba el patrón

`x if cond`      *guard*: condición extra sobre lo ya ligado

`_`              descarta sin ligar

`..`             ignora el resto de los campos o elementos
---------------  -------------------------------------------

Todas juntas en un solo `match`:

```rust
fn clasificar(n: i32) {
    match n {
        0 => println!("cero"),
        x if x < 0 => println!("negativo"),
        d @ 1..=9 => println!("un dígito: {d}"),
        10 | 100 | 1000 => println!("potencia de diez"),
        _ => println!("otro"),
    }
}

fn main() {
    clasificar(7);                      // un dígito: 7
    clasificar(-3);                     // negativo
    clasificar(100);                    // potencia de diez
}
```

Sin `@`, la rama `1..=9` sabría que `n` es un dígito pero no tendría un nombre
para él dentro del patrón. `d @` le pone el nombre sin perder la comprobación.
Con alternativas lleva paréntesis, `n @ (1 | 2 | 3)`: sin ellos, `n` solo
quedaría ligado en la primera, y el compilador lo rechaza (`E0408`).

La rama `x if x < 0` también se podría escribir como un rango, `..0`. El guard
hace falta de verdad cuando la condición depende de algo que no es un literal.
Un nombre en un patrón siempre liga; nunca compara contra una variable que ya
existe:

```rust
fn main() {
    let limite = 10;
    let n = 3;
    match n {
        limite => println!("llegó al límite"),
        _ => println!("debajo del límite"),
    }
}
```

<pre class="salida" style="margin: 14px 0; border-radius: 6px;"><code style="background: none; padding: 0; font-size: inherit;"><span class="e">warning</span><span class="em">: unreachable pattern</span>
<span class="g">5 |</span>         limite =&gt; println!(&quot;llegó al límite&quot;),
<span class="g">  |         ------ matches any value</span>
<span class="g">6 |</span>         _ =&gt; println!(&quot;debajo del límite&quot;),
<span class="g">  |         </span><span class="x">^ no value can reach this</span>
note: there is a binding of the same name; if you meant to
      pattern match against the value of that binding, that
      is a feature of constants that is not available for
      `let` bindings</code></pre>

La primera rama crea un `limite` nuevo, que vale 3, y encaja siempre. Para
comparar contra la variable, la comparación va en un guard, y la rama
queda como `x if x == limite`.

`_` y `..` descartan sin ligar. `_` ocupa el lugar de un solo valor; `..`, el
de todos los que faltan. Un nombre como `_rojo`, en cambio, sí liga: el guion
bajo inicial solo apaga el aviso de variable sin usar.

```rust
fn main() {
    let color = (200, 120, 40);
    let (rojo, _, _) = color;
    let (r, ..) = color;
    println!("{rojo} {r}");             // 200 200

    let [primera, .., ultima] = [7, 9, 6, 10];
    println!("{primera} {ultima}");     // 7 10
}
```

### `matches!`

A veces solo importa si un valor encaja, sin ligar nada. Para un enum propio,
`==` no sirve: `Semaforo::Rojo == Semaforo::Rojo` no compila (`E0369`), porque
el operador no está definido para los tipos que declara el programa.

`matches!` recibe un valor y un patrón, y devuelve un `bool`. Acepta
alternativas, rangos y guards:

```rust
enum Semaforo {
    Verde,
    Amarillo,
    Rojo,
}

fn puede_pasar(s: Semaforo) -> bool {
    matches!(s, Semaforo::Verde | Semaforo::Amarillo)
}

fn main() {
    println!("{}", puede_pasar(Semaforo::Rojo));    // false
    println!("{}", matches!(7, 1..=9));             // true
}
```

Equivale a un `match` con dos ramas: el patrón da `true` y `_` da `false`.

## Aplicación

Un ejercicio del curso *Aprende Rust*: el precio de una entrada según la edad y
si quien la compra es estudiante. De 0 a 3 años no paga. De 4 a 12 años, o de
65 en adelante, paga 5 €. Un estudiante paga 6 €, salvo que por edad le toque
menos, y el resto paga 9 €.

Los dos datos se juntan en una tupla, y cada regla se vuelve una rama:

```rust
fn precio_entrada(edad: u32, estudiante: bool) -> u32 {
    match (edad, estudiante) {
        (0..=3, _) => 0,
        (4..=12, _) | (65.., _) => 5,
        (_, true) => 6,
        _ => 9,
    }
}

fn main() {
    println!("{}", precio_entrada(2, true));     // 0
    println!("{}", precio_entrada(8, false));    // 5
    println!("{}", precio_entrada(20, true));    // 6
    println!("{}", precio_entrada(40, false));   // 9
    println!("{}", precio_entrada(70, true));    // 5
}
```

La regla «salvo que le toque menos» no se programa: sale de la regla 3. Un
estudiante de 2 o de 70 años encaja antes en una rama más barata, y la rama
`(_, true)` ya no se prueba. Si se sube al principio, el niño estudiante paga 6.

La solución original escribía la tercera edad como guard, `x if x > 64`. El
rango `65..` dice lo mismo como patrón, y así cabe en la alternativa con
`4..=12`.

## A fondo

**Los guards no cuentan para la exhaustividad.** El compilador no analiza la
condición de un guard, así que no sabe que estas dos ramas cubren todos los
enteros:

```rust,compile_fail
fn signo(n: i32) -> i32 {
    match n {
        x if x < 0 => -1,
        x if x >= 0 => 1,
    }
}

fn main() {
    println!("{}", signo(-4));
}
```

```salida
error[E0004]: non-exhaustive patterns: `i32::MIN..=i32::MAX`
              not covered
  = note: match arms with guards don't count towards
          exhaustivity
```

Con rangos sí lo sabe: `..0 => -1` y `0.. => 1` compilan sin `_`.

**El `else` de `let … else` no puede terminar normal.** Si el bloque solo
imprime y sigue, no compila (`E0308`): el compilador espera el tipo `!`, el de
una expresión que nunca produce valor, como `return` o `panic!`.
