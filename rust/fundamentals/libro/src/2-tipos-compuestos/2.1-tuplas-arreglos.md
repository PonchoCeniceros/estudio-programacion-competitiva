# 2.1 · Tuplas y arreglos

Una variable escalar guarda un solo valor. Eso alcanza hasta que una función
tiene que devolver dos resultados, o un programa tiene que guardar las siete
temperaturas de una semana. Con escalares hacen falta siete variables y siete
nombres, y no hay forma de recorrerlas con un `for`.

Rust tiene dos tipos compuestos para agrupar valores cuyo número se conoce al
compilar. La tupla junta valores de tipos distintos; el arreglo junta valores
del mismo tipo. Los dos tienen tamaño fijo, y de eso salen sus reglas.

## Definiciones y reglas

Tupla
:   grupo ordenado de valores que pueden ser de tipos distintos. Su tipo lista
    los tipos de cada posición: `(i32, char, bool)`.

Arreglo
:   *(array)*: secuencia de `N` valores del mismo tipo `T`, uno junto al otro
    en memoria. Su tipo es `[T; N]`.

Desestructurar
:   separar una tupla en variables sueltas con un patrón en el `let`:
    `let (a, b) = t;`.

Unit
:   la tupla vacía, `()`. Es el tipo y el único valor de lo que no devuelve
    nada.

::: {.reglas titulo="Las tres reglas de los tipos de tamaño fijo"}
1. El tamaño es parte del tipo: ni una tupla ni un arreglo crecen.
2. Una tupla se lee por posición (`t.0`); un arreglo, por índice (`a[i]`).
3. Todo índice se comprueba: fuera de rango, el programa hace panic.
:::

## De un vistazo

| | Tupla | Arreglo |
| :--- | :--- | :--- |
| Tipos de sus elementos | distintos | uno solo |
| Tipo escrito | `(i32, char)` | `[i32; 5]` |
| Construir | `(42, 'z')` | `[3, 1, 4, 1, 5]` o `[0; 5]` |
| Leer un elemento | `t.0` | `a[i]` |
| Posición inválida | no compila | panic al ejecutar |
| Recorrer con `for` | no | `for x in a` |

Criterio: una tupla agrupa pocos valores que significan cosas distintas, como
el área y el perímetro de un rectángulo. Un arreglo guarda muchos valores
que significan lo mismo y se recorren.

## Las reglas, una por una

Antes de las reglas, cómo se escriben y cómo se imprimen.

### Construir y anotar

```rust
fn main() {
    let t: (i32, char, bool) = (42, 'z', true);
    let a: [i32; 5] = [3, 1, 4, 1, 5];
    let ceros = [0; 5];        // [0, 0, 0, 0, 0]
    let inferida = (2.5, 'x'); // (f64, char)

    println!("{} {} {}", t.0, a[0], ceros.len());
    println!("{}", inferida.1);
}
```

Una tupla se escribe entre paréntesis y un arreglo entre corchetes, con los
elementos separados por comas. Como en cualquier `let`, la anotación es
opcional: el compilador deduce el tipo de los valores.

`[0; 5]` repite un valor: cinco ceros. El punto y coma separa el valor de la
cantidad, igual que en el tipo `[i32; 5]`. `.len()` devuelve la longitud del
arreglo como `usize`.

### Imprimir con `{:?}`

`{}` es el formato para el usuario final, y no sabe imprimir una tupla ni un
arreglo completos: `println!("{}", t)` no compila (*E0277*), y el mensaje
sugiere `{:?}`. Ese es el formato de depuración, y tuplas y arreglos lo
tienen:

```rust
fn main() {
    let t = (1, 'a', true);
    let a = [0; 3];
    println!("{:?}", t);   // (1, 'a', true)
    println!("{a:?}");     // [0, 0, 0]
}
```

### [Regla 1:]{.prefijo} el tamaño es parte del tipo

`[i32; 3]` y `[i32; 4]` son tipos distintos, igual que `i32` y `i64`. Un
arreglo de cuatro elementos no cabe en una variable de tres:

```rust,compile_fail
fn main() {
    let a: [i32; 3] = [1, 2, 3, 4];
}
```

```salida
error[E0308]: mismatched types
2 |     let a: [i32; 3] = [1, 2, 3, 4];
  |            --------   ^^^^^^^^^^^^ expected an array with
  |            |                       a size of 3, found one
  |            |                       with a size of 4
  |            expected due to this
```

Por la misma razón no hay forma de agregarle un elemento:

```rust,compile_fail
fn main() {
    let mut a = [1, 2, 3];
    a.push(4);   // E0599: no method named `push` found
}
```

Lo que sí se puede es cambiar un elemento, si el binding es `mut`. Cuando el
número de elementos se conoce hasta ejecutar, el tipo es `Vec`, la secuencia
que crece ([5.3 Vec]{.ref}).

### [Regla 2:]{.prefijo} posición para la tupla, índice para el arreglo

```rust
fn main() {
    let mut punto = (3, 4);
    punto.0 = 10;                // cambia una posición

    let mut dias = [0; 7];
    let hoy = 2;
    dias[hoy] = 25;              // el índice es una variable

    println!("{:?}", punto);     // (10, 4)
    println!("{:?}", dias);      // [0, 0, 25, 0, 0, 0, 0]
}
```

En la tupla, la posición va después de un punto y es un número escrito en el
código: `punto.0`, `punto.1`. Cada posición tiene su propio tipo, así que el
compilador tiene que saber cuál se lee. Una posición que no existe no compila:

```rust,compile_fail
fn main() {
    let t = (1, 'a');
    println!("{}", t.2);   // E0609: no field `2`
}
```

En el arreglo todos los elementos son del mismo tipo, así que el índice puede
calcularse al ejecutar. Va entre corchetes, empieza en 0 y es de tipo `usize`.
Un arreglo se recorre con un rango de índices, `for i in 0..a.len()`, o sin
índice: `for x in a` entrega cada elemento en orden.

### Desestructurar una tupla

Leer una tupla posición por posición es tedioso. Un `let` con paréntesis la
separa en variables de una vez:

```rust
fn main() {
    let ficha = (7, 'B', true);
    let (salon, grupo, activo) = ficha;
    println!("{salon}{grupo} {activo}");   // 7B true
}
```

Del lado izquierdo no hay una variable sino un patrón: la forma de la tupla
con un nombre en cada posición. El número de nombres debe coincidir con el de
posiciones. Los patrones a fondo están en [2.4 Patrones]{.ref}.

### [Regla 3:]{.prefijo} un índice fuera de rango es un panic

El error clásico con arreglos es recorrer uno de más. Aquí el rango `0..=`
incluye el 3, y el arreglo solo tiene las posiciones 0, 1 y 2:

```rust,should_panic
fn main() {
    let notas = [8, 9, 7];
    for i in 0..=notas.len() {
        println!("{}", notas[i]);
    }
}
```

```salida
thread 'main' panicked at src/main.rs:4:24:
index out of bounds: the len is 3 but the index is 3
```

El programa imprime 8, 9 y 7, y se detiene en el cuarto acceso. Antes de cada
`notas[i]`, Rust compara `i` con la longitud. Si se pasa, el programa hace
panic, igual que con el desbordamiento de [1.2 Tipos escalares]{.ref}.

El mismo programa en C compila sin advertencias, aun con `-Wall`:

```c
int notas[3] = {8, 9, 7};
for (int i = 0; i <= 3; i++)
    printf("%d\n", notas[i]);
```

C no comprueba el índice. El cuarto acceso lee la memoria que sigue al
arreglo, y el programa imprime lo que haya ahí: en una ejecución salió un
`1`. Con escritura en lugar de lectura, el mismo descuido modifica otra
variable sin que nadie avise. Rust cambia ese comportamiento indefinido por
un error con el índice y la longitud.

### La tupla vacía

Una tupla sin elementos se escribe `()` y se llama unit. [1.2 Tipos
escalares]{.ref} la presenta como tipo; aquí se ve de dónde sale su forma: es
una tupla de cero posiciones. Una función sin `->` devuelve `()`, y un bloque
que termina en `;` vale `()` ([1.4 Todo es una expresión]{.ref}).

## Aplicación

Una función devuelve un solo valor, pero ese valor puede ser una tupla. El
ejemplo es de la lección de funciones del curso *Aprende Rust*:

```rust
fn rectangulo(ancho: u32, alto: u32) -> (u32, u32) {
    let area = ancho * alto;
    let perimetro = 2 * (ancho + alto);
    (area, perimetro)
}

fn main() {
    let (area, perimetro) = rectangulo(3, 4);
    println!("área {area}, perímetro {perimetro}");
}
```

La firma anuncia los dos resultados y su orden. Quien llama los separa con un
`let` y les pone nombre.

El segundo programa junta las tres reglas. Recibe las temperaturas de una
semana en un arreglo de siete y devuelve la mínima y la máxima en una tupla:

```rust
fn extremos(temps: [i32; 7]) -> (i32, i32) {
    let mut min = temps[0];
    let mut max = temps[0];
    for t in temps {
        if t < min { min = t; }
        if t > max { max = t; }
    }
    (min, max)
}

fn main() {
    let semana = [18, 21, 25, 24, 19, 16, 22];
    let (min, max) = extremos(semana);
    println!("{} días: de {min} a {max}", semana.len());
}
```

El tipo `[i32; 7]` del parámetro obliga a pasar exactamente siete valores:
un arreglo de seis no compila. `temps[0]` existe siempre por la misma razón,
así que no puede hacer panic.

## A fondo

**El índice constante se rechaza al compilar.** Si el índice es un literal o
una variable que nunca cambia, el compilador ve el error y no espera a la
ejecución. El acceso `notas[3]` sobre un arreglo de tres da `error: this
operation will panic at runtime`. El panic queda para los índices que
dependen de la ejecución, como el de un bucle.

**Un arreglo no guarda su longitud.** `[i32; 5]` ocupa 20 bytes: cinco
enteros de 4 bytes, juntos y sin cabecera. La longitud vive en el tipo, así
que `.len()` no lee memoria: el compilador ya conoce el 5.

**El compilador puede reordenar una tupla.** Rust no promete el orden de las
posiciones en memoria, y las acomoda para desperdiciar menos relleno.
`(u8, u32, u8)` ocupa 8 bytes, donde el orden escrito necesitaría 12.

**Una tupla de un elemento lleva coma.** `(5)` es el número 5 entre
paréntesis; `(5,)` es una tupla de tipo `(i32,)`, y `{:?}` la imprime con
su coma.

**Los arreglos se anidan.** `[[0; 3]; 2]` es un arreglo de dos filas de tres
columnas, de tipo `[[i32; 3]; 2]`, y `m[1][2]` lee la última casilla. Es la
forma de guardar una cuadrícula de tamaño fijo.

**Preguntar sin arriesgar un panic.** Los arreglos tienen `.get(i)`, que no
truena con un índice inválido. Devuelve un `Option`, que se explica en
[5.1 Option]{.ref}.
