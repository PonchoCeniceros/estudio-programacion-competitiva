# 2.3 · Enums

Un programa que maneja rumbos necesita guardar hacia dónde apunta algo. Con lo
que hay hasta [2.2 Structs]{.ref}, las opciones son un número o un texto: `0`
para norte, `1` para este, o `"norte"`. Nada impide escribir `7` o `"nrote"`.
El compilador no lo detecta, porque los dos son valores válidos de su tipo.

Un struct tampoco resuelve el problema. Un struct junta campos que existen
todos a la vez: un `Punto` siempre tiene `x` y `y`. Un rumbo no es norte y
este al mismo tiempo: es uno solo de cuatro. Para ese caso Rust tiene un tipo
propio, el enum.

## Definiciones y reglas

Enum
:   *(enumeration)*: un tipo cuyos valores forman una lista cerrada de
    variantes.

Variante
:   cada uno de los valores posibles de un enum. Se escribe
    `Tipo::Variante`.

Datos asociados
:   los valores que una variante lleva dentro, como los campos de un struct.

Exhaustivo
:   dicho de un `match`: que cubre todas las variantes posibles.

::: {.reglas titulo="Las tres reglas de los enums"}
1. Un valor de un enum es exactamente una de sus variantes, nunca dos.
2. Cada variante lleva sus propios datos: ninguno, una tupla o campos con
   nombre.
3. Un `match` sobre un enum debe cubrir todas sus variantes.
:::

## De un vistazo

| Forma | Se declara | Se crea |
| :--- | :--- | :--- |
| sin datos | `Salir` | `Mensaje::Salir` |
| tupla | `Escribir(String)` | `Mensaje::Escribir(s)` |
| con campos | `Mover { x: i32, y: i32 }` | `Mensaje::Mover { x: 3, y: 0 }` |

El patrón que abre una variante en un `match` tiene la misma forma que la
expresión que la crea, con nombres en lugar de valores. Criterio de diseño:
si los datos existen todos a la vez, struct; si el valor es uno entre varios
casos, enum.

## Las reglas, una por una

Antes de las reglas, cómo se declara un enum y cómo se crea un valor.

### Declarar un enum y crear un valor

La declaración empieza con `enum` y el nombre del tipo, y enumera las
variantes entre llaves, separadas por comas. Los nombres de tipo y de variante
van en *CamelCase*, como los de los structs. Para crear un valor se nombra la
variante con el tipo delante y `::` en medio:

```rust
enum Direccion {
    Norte,
    Este,
    Sur,
    Oeste,
}

fn main() {
    let rumbo: Direccion = Direccion::Norte;
}
```

El tipo de `rumbo` es `Direccion`, y su variante es `Norte`. Otro valor del
mismo tipo podría ser `Direccion::Oeste`: cambia la variante, no el tipo.

### [Regla 1:]{.prefijo} un valor es una sola variante

La lista de variantes es cerrada. Un valor de tipo `Direccion` solo puede ser
una de las cuatro, y pedir una quinta no compila:

```rust,compile_fail
enum Direccion { Norte, Este, Sur, Oeste }

fn main() {
    let rumbo = Direccion::Noroeste;
}
```

```salida
error[E0599]: no variant or associated item named
              `Noroeste` found for enum `Direccion`
              in the current scope
4 |     let rumbo = Direccion::Noroeste;
  |                            ^^^^^^^^ variant or associated
  |                                     item not found in
  |                                     `Direccion`
```

Con el número o el texto del principio, `7` y `"nrote"` compilaban. Con el
enum, el error aparece antes de ejecutar. Una función que recibe una
`Direccion` tiene garantizado que llega una de las cuatro variantes, y solo
una.

### [Regla 2:]{.prefijo} cada variante lleva sus datos

Un programa recibe mensajes de distintas clases. Unos no traen nada, otros
traen una posición, un texto o un color. Cada variante declara lo que lleva:

```rust
enum Mensaje {
    Salir,                     // sin datos
    Mover { x: i32, y: i32 },  // campos con nombre
    Escribir(String),          // tupla de un elemento
    CambiarColor(u8, u8, u8),  // tupla de tres
}

fn main() {
    let a = Mensaje::Salir;
    let b = Mensaje::Mover { x: 3, y: -1 };
    let c = Mensaje::Escribir(String::from("hola"));
    let d = Mensaje::CambiarColor(255, 128, 0);
}
```

Cada forma se parece a algo de [2.1 Tuplas y arreglos]{.ref} o de
[2.2 Structs]{.ref}. `Salir` se escribe como un *unit struct*, sin nada más.
`Mover` se escribe como un struct con campos. `Escribir` y `CambiarColor` son
tuplas con nombre: sus datos se identifican por posición.

Las tres formas conviven en el mismo enum. `a`, `b`, `c` y `d` son todas de
tipo `Mensaje`, aunque cada una guarde datos distintos.

### Por qué un enum y no cuatro structs

Los mismos cuatro casos se podrían escribir como cuatro structs: `Salir`,
`Mover`, `Escribir` y `CambiarColor`. El problema aparece al escribir una
función que los procese. Su parámetro necesita un tipo, y cada struct es un
tipo distinto:

```rust,compile_fail
struct Salir;
struct Mover { x: i32, y: i32 }

fn procesar(m: Salir) {}

fn main() {
    procesar(Mover { x: 3, y: -1 });
}
```

```salida
error[E0308]: mismatched types
7 |     procesar(Mover { x: 3, y: -1 });
  |     -------- ^^^^^^^^^^^^^^^^^^^^^ expected `Salir`,
  |     |                              found `Mover`
  |     arguments to this function are incorrect
```

`procesar` acepta un `Salir` y nada más. Con el enum, los cuatro casos son
variantes de un solo tipo, y la firma `fn procesar(m: Mensaje)` acepta un
mensaje cualquiera. Lo mismo vale para un arreglo: sus elementos deben ser de
un mismo tipo, así que `[Mensaje; 3]` puede mezclar variantes.

### Abrir un enum con `match`

Un valor de un enum no dice qué variante es hasta que alguien lo pregunta. La
forma de preguntarlo es `match`, presentado en [1.6 Control de flujo]{.ref}.
Cada rama tiene la forma `patrón => expresión`:

```rust
enum Direccion { Norte, Este, Sur, Oeste }

fn grados(d: Direccion) -> u32 {
    match d {
        Direccion::Norte => 0,
        Direccion::Este => 90,
        Direccion::Sur => 180,
        Direccion::Oeste => 270,
    }
}

fn main() {
    println!("{}", grados(Direccion::Sur));   // 180
}
```

`match` es una expresión: vale lo que vale la rama que encaja. Por eso es la
última expresión de `grados` y no lleva `return`. Todas las ramas deben dar un
valor del mismo tipo, aquí `u32`.

Cuando la variante lleva datos, el patrón les pone nombre. Esos nombres son
variables nuevas, válidas solo dentro de su rama:

```rust
enum Mensaje {
    Salir,
    Mover { x: i32, y: i32 },
    Escribir(String),
    CambiarColor(u8, u8, u8),
}

fn describir(m: Mensaje) {
    match m {
        Mensaje::Salir => println!("salir"),
        Mensaje::Mover { x, y } => println!("mover {x},{y}"),
        Mensaje::Escribir(t) => println!("escribir {t}"),
        Mensaje::CambiarColor(r, g, b) => {
            println!("color {r},{g},{b}")
        }
    }
}

fn main() {
    describir(Mensaje::Mover { x: 3, y: -1 });
}
```

:::

En una variante con campos, `{ x, y }` toma cada campo en una variable del
mismo nombre. En una variante tupla, los nombres se asignan por posición: `r`,
`g` y `b` reciben los tres `u8` en orden. Los patrones admiten mucho más que
esto: rangos, alternativas, comodines y condiciones. Todo eso está en
[2.4 Patrones]{.ref}.

### [Regla 3:]{.prefijo} el `match` debe ser exhaustivo

El compilador conoce todas las variantes, así que comprueba que el `match`
las cubra. Esta comprobación paga cuando el enum crece. Si se agrega la
variante `Noreste` y nadie actualiza `grados`, el programa deja de compilar:

```rust,compile_fail
enum Direccion { Norte, Noreste, Este, Sur, Oeste }

fn grados(d: Direccion) -> u32 {
    match d {
        Direccion::Norte => 0,
        Direccion::Este => 90,
        Direccion::Sur => 180,
        Direccion::Oeste => 270,
    }
}

fn main() {
    println!("{}", grados(Direccion::Sur));
}
```

```salida
error[E0004]: non-exhaustive patterns: `Direccion::Noreste`
              not covered
4 |     match d {
  |           ^ pattern `Direccion::Noreste` not covered
...
1 | enum Direccion { Norte, Noreste, Este, Sur, Oeste }
  |      ^^^^^^^^^          ------- not covered
  = note: the matched value is of type `Direccion`
```

El error señala el `match` incompleto y la variante que falta. En un programa
con veinte funciones que abren `Direccion`, el compilador produce un error por
cada una que no cubra `Noreste`. La lista de errores es la lista de lugares
por actualizar, y ninguno se queda olvidado.

## Aplicación

Un ejercicio del curso *Aprende Rust*: el valor en céntimos de una moneda de
euro. El `match` no lleva ninguna rama comodín, de modo que una moneda nueva
obliga a decir cuánto vale. Esta versión suma además un monedero, guardado en
un arreglo de cuatro monedas.

```rust
enum Moneda {
    UnCentimo,
    DiezCentimos,
    UnEuro,
    DosEuros,
}

fn valor(moneda: Moneda) -> u32 {
    match moneda {
        Moneda::UnCentimo => 1,
        Moneda::DiezCentimos => 10,
        Moneda::UnEuro => 100,
        Moneda::DosEuros => 200,
    }
}

fn main() {
    let monedero = [Moneda::DosEuros, Moneda::UnEuro,
                    Moneda::DiezCentimos, Moneda::UnCentimo];
    let mut total = 0;
    for moneda in monedero {
        total += valor(moneda);
    }
    println!("{total} céntimos");   // 311 céntimos
}
```

El segundo programa usa variantes con datos. Cada figura guarda sus medidas,
y `area` las extrae para calcular. Mezcla las tres formas de variante: un
círculo con un campo con nombre, un rectángulo con dos, y un triángulo como
tupla de base `b` y altura `h`.

```rust
enum Figura {
    Circulo { radio: f64 },
    Rectangulo { ancho: f64, alto: f64 },
    Triangulo(f64, f64),
}

fn area(f: Figura) -> f64 {
    match f {
        Figura::Circulo { radio } => {
            std::f64::consts::PI * radio * radio
        }
        Figura::Rectangulo { ancho, alto } => ancho * alto,
        Figura::Triangulo(b, h) => b * h / 2.0,
    }
}

fn main() {
    let figuras = [
        Figura::Circulo { radio: 1.0 },
        Figura::Rectangulo { ancho: 3.0, alto: 2.0 },
        Figura::Triangulo(4.0, 5.0),
    ];
    for f in figuras {
        println!("{:.2}", area(f));   // 3.14, 6.00, 10.00
    }
}
```

## A fondo

**Un enum no se compara con `==` por default.** Para saber si un rumbo es
`Norte`, la comparación `d == Direccion::Norte` no compila: el error es
*E0369*, «binary operation `==` cannot be applied to type `Direccion`».
`==` existe solo para los tipos que implementan el *trait* `PartialEq`, y un
enum nuevo no lo implementa. Las salidas son un `match`, la macro `matches!`
de [2.4 Patrones]{.ref}, o agregar `#[derive(PartialEq)]` sobre el enum
([4.4 Traits de la stdlib]{.ref}).

**Una variante sin datos es un entero.** El compilador numera las variantes
desde 0, y `Direccion::Sur as i32` vale 2. El número se puede fijar a mano,
como en `enum Http { Ok = 200, NoEncontrado = 404 }`, solo si ninguna variante
lleva datos. La conversión con `as` está en
[4.5 Operadores y conversiones]{.ref}.

**Un enum ocupa lo que su variante más grande, más una etiqueta.** La
etiqueta guarda qué variante es. `Direccion` ocupa un byte. `Mensaje` ocupa 24
bytes, lo mismo que un `String`: el compilador esconde la etiqueta en valores
que un `String` nunca usa. Esa optimización se llama *niche*.

**El comodín `_` apaga la regla 3.** Una rama `_ => …` encaja con cualquier
variante, así que un `match` con comodín siempre es exhaustivo. El precio es
que una variante nueva cae en el comodín sin ningún error. Por eso conviene
listar las variantes cuando son pocas, como en `valor`.

**Los dos enums más usados vienen en la biblioteca estándar.** Uno representa
un valor que puede faltar y el otro una operación que puede fallar. Los dos
son enums con datos como `Mensaje`, y se abren con `match`
([5.1 Option]{.ref} y [5.2 Result]{.ref}).
