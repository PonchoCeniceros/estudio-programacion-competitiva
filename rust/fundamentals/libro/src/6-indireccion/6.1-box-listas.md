# 6.1 · Box y listas enlazadas

Hasta aquí cada valor vivía donde vivía su dueño: una variable local en su
marco, un campo dentro de su struct. Las excepciones fueron `String` y `Vec`,
que guardan sus datos en el heap y dejan en el stack una parte fija con un
puntero. Los dos son punteros con dueño, hechos para un uso concreto.

Hay tipos que necesitan lo mismo sin ser texto ni secuencia. El caso típico
es una lista enlazada: cada nodo contiene al siguiente, y un tipo que se
contiene a sí mismo no tiene tamaño ([3.1 Stack y heap]{.ref}). `Box<T>` es el
puntero con dueño en su forma mínima: pone un valor cualquiera en el heap y
no agrega nada más.

## Definiciones y reglas

Indirección
:   llegar a un valor a través de un puntero, en lugar de tenerlo en el
    sitio.

Puntero inteligente
:   *(smart pointer)*: un tipo que se usa como un puntero y además es dueño
    de lo que apunta. `String`, `Vec<T>` y `Box<T>` lo son.

`Box<T>`
:   el dueño de un `T` guardado en el heap. `Box::new(valor)` reserva el
    bloque y mueve el valor a él.

Tipo recursivo
:   un tipo que se nombra a sí mismo en uno de sus campos o variantes.

::: {.reglas titulo="Las tres reglas de Box"}
1. Un `Box<T>` guarda su `T` en el heap. En el stack ocupa un puntero, sea
   cual sea el tamaño de `T`.
2. El `Box` es el único dueño de su `T`. Moverlo copia el puntero; al salir
   de scope libera el valor y su bloque.
3. A través de un `&mut` no se saca un valor: se intercambia por otro
   válido.
:::

Ninguna es nueva. La 2 es [3.2 Ownership]{.ref} aplicada a un puntero, y la 3
sale de la regla 2 del borrow checker ([3.3 Borrowing]{.ref}).

## De un vistazo

`Box<T>` es un struct genérico de la biblioteca estándar, con un parámetro de
tipo como los de [4.2 Generics]{.ref}. Lo que lo distingue es lo que hace con
`T`.

| | Un struct genérico cualquiera | `Box<T>` |
| :--- | :--- | :--- |
| El parámetro `T` | igual | igual |
| Dónde vive el dato | donde viva el struct | siempre en el heap |
| Tamaño en el stack | depende de `T` | un puntero; dos si `T` no tiene tamaño |
| Al salir de scope | libera sus campos | libera además el bloque del heap |
| `T` sin tamaño conocido | no se admite | se admite |

Sigue habiendo un solo dueño. Cambian tres cosas: dónde está el dato, cuánto
ocupa el dueño, y que `T` puede no tener tamaño conocido
([6.3 Despacho dinámico]{.ref}).

## Las reglas, una por una

### [Regla 1:]{.prefijo} el dato en el heap, un puntero en el stack

```rust
fn main() {
    let x = 5;                // el 5, en el marco de main
    let caja = Box::new(5);   // el 5, en el heap
    println!("{}", x + *caja);                      // 10
    println!("{}", std::mem::size_of_val(&caja));   // 8
}
```

Este programa no gana nada con el `Box`. Un `i32` cabe en el stack, y ponerlo
en el heap cuesta una reserva y un salto para leerlo. `Box<T>` se justifica
en tres casos:

1. Un tipo recursivo, que sin indirección no tiene tamaño.
2. Un dato grande que cambia de dueño: mover el `Box` copia 8 bytes, no el
   dato.
3. Un valor del que solo se conoce el trait que implementa, y no su tipo
   concreto. Es el tema de [6.3 Despacho dinámico]{.ref}.

El `*caja` del ejemplo funciona porque `Box<T>` implementa `Deref` con
`Target = T` ([4.5 Operadores y conversiones]{.ref}). Por la misma coerción
un `Box<String>` responde a `caja.len()`, y un `&Box<String>` se acepta
donde se pide un `&str`. Un `Box<T>` se usa como si fuera el `T`.

### El tipo recursivo

Un nodo de una lista guarda un valor y el nodo que sigue. Escrito tal cual,
no compila:

```rust,compile_fail
struct Nodo {
    valor: i32,
    siguiente: Nodo,
}

fn main() {}
```

```salida
error[E0072]: recursive type `Nodo` has infinite size
1 | struct Nodo {
  | ^^^^^^^^^^^
2 |     valor: i32,
3 |     siguiente: Nodo,
  |                ---- recursive without indirection
help: insert some indirection (e.g., a `Box`, `Rc`, or `&`)
      to break the cycle
3 |     siguiente: Box<Nodo>,
  |                ++++    +
```

El compilador necesita el tamaño de cada tipo para reservar su lugar en el
marco ([3.1 Stack y heap]{.ref}, regla 1). El de `Nodo` sería 4 bytes más el
tamaño de un `Nodo`, que a su vez contiene otro. La cuenta no termina.

Con `siguiente: Box<Nodo>`, como propone la ayuda, el campo pasa a ser un
puntero. Un puntero mide 8 bytes sin importar a qué apunte, y la cuenta se
cierra. `size_of::<Nodo>()` da 16: 4 del `i32`, 4 de relleno y 8 del `Box`.

El tipo ya tiene tamaño, pero no se puede construir ningún valor: cada `Nodo`
exige otro `Nodo` ya hecho para su campo `siguiente`. Falta una forma de
decir que la lista termina.

### El final de la lista: `Option<Box<Nodo>>`

El último nodo no tiene siguiente. Esa ausencia se modela con `Option`
([5.1 Option]{.ref}), no con un valor especial: Rust no tiene `null`.

```rust
struct Nodo {
    valor: i32,
    siguiente: Option<Box<Nodo>>,
}

fn main() {
    let tercero = Nodo { valor: 3, siguiente: None };
    let segundo = Nodo {
        valor: 2,
        siguiente: Some(Box::new(tercero)),
    };
    let primero = Nodo {
        valor: 1,
        siguiente: Some(Box::new(segundo)),
    };
    println!("{}", primero.valor);   // 1
}
```

`None` marca el final. `Some(Box::new(nodo))` mueve el nodo al heap y guarda
su dirección. La lista se arma de atrás hacia adelante, porque cada nodo
necesita tener listo al que le sigue.

::: {.figura src="figuras/6.1-lista.html"}
:::

El `Option` no cuesta espacio: `Option<Box<Nodo>>` mide 8 bytes, igual que
`Box<Nodo>`. La razón está en «A fondo».

### El tamaño se uniforma, el tipo no

Cualquier `Box<T>` de un `T` con tamaño conocido ocupa lo mismo. Los números
son los que devuelve `size_of` en una máquina de 64 bits:

| Tipo | Bytes en el stack | Qué queda en el stack |
| :--- | ---: | :--- |
| `[u8; 1024]` | 1024 | el arreglo entero |
| `Box<[u8; 1024]>` | 8 | un puntero al arreglo |
| `Box<u8>` | 8 | un puntero |
| `Box<String>` | 8 | un puntero a los 24 bytes del `String` |
| `Box<dyn Figura>` | 16 | dos punteros: al dato y a una tabla |

La última fila es el caso de un `T` sin tamaño conocido, y se explica en
[6.3 Despacho dinámico]{.ref}.

El cajón uniforma el tamaño, no el tipo. `Box<u8>` y `Box<String>` miden lo
mismo y siguen siendo tipos distintos. Un `vec![Box::new(7u8),
Box::new(String::new())]` da E0308, *mismatched types*: ``expected `u8`,
found `String` ``. Uniformar el tipo también es trabajo de `dyn`.

### [Regla 2:]{.prefijo} un solo dueño, que libera al salir

Un `Box` se mueve como un `String`. Tras `let b = a;` la variable `a` queda
invalidada, y pasarla a `println!` da el E0382 de [3.2 Ownership]{.ref}:
``borrow of moved value: `a` ``. El move copia los 8 bytes del puntero. El dato no cambia de
lugar en el heap, mida 4 bytes o 4 MiB.

Al salir de scope, el `Box` destruye su valor y devuelve el bloque al
asignador. En una lista eso ocurre en cadena. Un `Drop` con un mensaje
([4.4 Traits de la stdlib]{.ref}) deja ver el orden:

```rust
struct Nodo { valor: i32, siguiente: Option<Box<Nodo>> }

impl Drop for Nodo {
    fn drop(&mut self) {
        println!("suelto {}", self.valor);
    }
}

fn main() {
    let n3 = Nodo { valor: 3, siguiente: None };
    let n2 = Nodo { valor: 2, siguiente: Some(Box::new(n3)) };
    let n1 = Nodo { valor: 1, siguiente: Some(Box::new(n2)) };
    println!("fin de main, con {}", n1.valor);
}
```

```salida
fin de main, con 1
suelto 1
suelto 2
suelto 3
```

`main` solo tiene un dueño que soltar: `n1`. Las variables `n2` y `n3`
quedaron movidas. Al destruirse, `n1` destruye su campo `siguiente`; ese `Box` destruye al segundo nodo y libera su bloque, y así
hasta el `None`. Cada nodo es dueño del resto de la lista.

### Recorrer sin mover

Leer la lista no debe consumirla. Se recorre con una referencia que avanza de
nodo en nodo:

```rust
struct Nodo { valor: i32, siguiente: Option<Box<Nodo>> }

fn imprimir(lista: &Option<Box<Nodo>>) {
    let mut actual = lista;
    while let Some(nodo) = actual {
        println!("{}", nodo.valor);
        actual = &nodo.siguiente;
    }
}

fn main() {
    let n3 = Nodo { valor: 3, siguiente: None };
    let n2 = Nodo { valor: 2, siguiente: Some(Box::new(n3)) };
    let lista = Some(Box::new(n2));
    imprimir(&lista);   // 2 y 3
    imprimir(&lista);   // la lista sigue entera
}
```

`actual` es un `&Option<Box<Nodo>>`: un préstamo, no un dueño. Al encajar
`Some(nodo)` contra una referencia, `nodo` se liga como `&Box<Nodo>` y nada
se mueve ([5.1 Option]{.ref}). `nodo.valor` atraviesa la referencia y el
`Box` por la coerción de deref.

`let mut actual` hace mutable al binding, no a la lista. En cada vuelta la
referencia se reapunta al campo `siguiente` del nodo en turno, como la `r` del
«A fondo» de [3.3 Borrowing]{.ref}. Los nodos no cambian de dueño ni de lugar.

### [Regla 3:]{.prefijo} detrás de un `&mut` no queda un hueco

Para quitar un nodo no alcanza con leerlo: quien lo quita se queda con él. La
función recibe la lista por `&mut` y devuelve el nodo. El intento directo es
mover el valor fuera del préstamo:

```rust,compile_fail
struct Nodo { valor: i32, siguiente: Option<Box<Nodo>> }

fn quitar_primero(
    lista: &mut Option<Box<Nodo>>,
) -> Option<Box<Nodo>> {
    let primero = *lista;
    primero
}

fn main() {
    let nodo = Nodo { valor: 1, siguiente: None };
    let mut lista = Some(Box::new(nodo));
    quitar_primero(&mut lista);
}
```

```salida
error[E0507]: cannot move out of `*lista`
              which is behind a mutable reference
6 |     let primero = *lista;
  |                   ^^^^^^ move occurs because `*lista`
  |                          has type `Option<Box<Nodo>>`,
  |                          which does not implement
  |                          the `Copy` trait
```

`lista` es un préstamo. La dueña es la variable `lista` de `main`, que al
volver de la llamada seguirá ahí y se destruirá al final. Si la función se
llevara el valor, esa variable quedaría con un hueco: memoria que ya es de
otro dueño. La regla 2 del borrow checker exige que la referencia apunte
siempre a un valor válido, y un hueco no lo es.

La salida es no dejar el hueco. En lugar de sacar el valor, se intercambia
por otro válido en un solo paso. Eso hace `std::mem::replace`: escribe el
valor nuevo en el destino y devuelve el que había. Si `nombre` guarda
`"Ana"`, la llamada `std::mem::replace(&mut nombre, String::new())` devuelve
`"Ana"` y deja en `nombre` un texto vacío. En ningún momento `nombre` deja de
tener un `String` completo.

Para un `Option` el valor de reemplazo natural es `None`, y esa operación
tiene nombre propio: `take()` ([5.1 Option]{.ref}). En esencia, su cuerpo es
`std::mem::replace(self, None)`. Devuelve lo que había y deja `None` en su
lugar.

Con `take()`, quitar el primer nodo son dos intercambios encadenados:

```rust
struct Nodo { valor: i32, siguiente: Option<Box<Nodo>> }

fn quitar_primero(
    lista: &mut Option<Box<Nodo>>,
) -> Option<Box<Nodo>> {
    match lista.take() {
        Some(mut primero) => {
            *lista = primero.siguiente.take();
            Some(primero)
        }
        None => None,
    }
}

fn main() {
    let n3 = Nodo { valor: 3, siguiente: None };
    let n2 = Nodo { valor: 2, siguiente: Some(Box::new(n3)) };
    let n1 = Nodo { valor: 1, siguiente: Some(Box::new(n2)) };
    let mut lista = Some(Box::new(n1));

    if let Some(nodo) = quitar_primero(&mut lista) {
        println!("quitado: {}", nodo.valor);   // quitado: 1
    }
    if let Some(nodo) = &lista {
        println!("ahora empieza en {}", nodo.valor);   // 2
    }
}
```

::: {.figura src="figuras/6.1-quitar.html"}
:::

El estado del dueño en cada punto:

1. Al entrar, `lista` posee la cadena completa.
2. Tras `lista.take()`, `lista` vale `None` y la cadena entera es de
   `primero`. Ya no está detrás del préstamo: `primero` es una variable
   local y dueña, y por eso se puede modificar y devolver.
3. Tras `primero.siguiente.take()`, el resto de la cadena vuelve a `lista`.
   El nodo quitado queda suelto, con `siguiente` en `None`.

El segundo `take()` hace falta por la misma razón que el primero. Escribir
`*lista = primero.siguiente;` mueve el campo y deja a `primero` incompleto, y
devolverlo da E0382: ``use of partially moved value: `primero` ``. Con
`take()` el nodo se queda con un `None` y sigue entero. Las dos reglas del
borrow checker se cumplen en cada línea, y nada se comprueba al ejecutar.

## Aplicación

Este es un ejercicio del curso *Aprende Rust*: una lista escrita como enum
recursivo, y una función que multiplica sus valores.
El `use` de la primera línea permite escribir `Nodo` y `Vacia` sin el
prefijo `Lista::` ([7.1 Módulos]{.ref}).

```rust
use Lista::{Nodo, Vacia};

enum Lista {
    Nodo(i32, Box<Lista>),
    Vacia,
}

fn producto(lista: &Lista) -> i32 {
    match lista {
        Vacia => 1,
        Nodo(valor, siguiente) => valor * producto(siguiente),
    }
}

fn main() {
    let cola = Nodo(4, Box::new(Vacia));
    let lista = Nodo(2, Box::new(Nodo(3, Box::new(cola))));
    println!("Producto: {}", producto(&lista));   // 24
}
```

Sin el `Box`, `Lista` es el tipo de tamaño infinito de
[3.1 Stack y heap]{.ref}. `producto` recibe un préstamo y recorre con
recursión: el `match` decide entre el caso vacío y el caso con nodo, y en
este se llama a sí misma con el resto. `siguiente` es un `&Box<Lista>`, y la
coerción de deref lo entrega como el `&Lista` que pide la firma.

Las dos formas representan la misma lista. Difieren en dónde se dice que la
lista termina:

| | Struct con `Option<Box<Nodo>>` | Enum con `Box<Lista>` |
| :--- | :--- | :--- |
| Qué es un nodo | un tipo propio, `Nodo` | una variante de `Lista` |
| La lista vacía | `None` | la variante `Vacia` |
| El final | `None`, sin reserva | un `Box` con una `Vacia` dentro |
| Recorrerla | `while let` sobre el `Option` | `match` sobre las variantes |
| Intercambiar | `take()` | `std::mem::replace` con `Vacia` |

El struct reutiliza `Option` y sus métodos. El enum deja la definición
completa en un solo tipo, y cuesta una reserva más para el final.

**Donde un dueño no alcanza.** En las dos formas cada nodo tiene un solo
dueño: el nodo anterior. Dos listas no pueden compartir la misma cola. El
segundo `Box::new(cola)` da E0382, *use of moved value*, porque la primera
lista ya se la llevó. Tampoco se puede armar un árbol donde cada hijo apunte
de vuelta a su padre. Para eso hacen falta varios dueños, y es el tema de
[6.2 Rc, RefCell y árboles]{.ref}.

## A fondo

**`Option<Box<T>>` mide lo mismo que `Box<T>`.** Un `Box` nunca guarda la
dirección cero: un puntero con dueño siempre apunta a algo. El compilador usa ese
valor sobrante para representar `None`, sin etiqueta aparte. Es la
optimización de *niche* de [2.3 Enums]{.ref}, y también aplica a `Option<&T>`.

Un `i32` usa todos sus valores, así que `Option<i32>` sí paga por su
etiqueta: mide 8 bytes, no 4.

**De un `Box` sí se puede mover hacia afuera.** El E0507 aparece al mover a
través de una referencia. Un `Box` es dueño, y por eso `let texto: String =
*caja;` compila con un `Box<String>`: el valor sale, `caja` queda movida y
su bloque se libera.

**`take()` tiene dos parientes.** `std::mem::take(&mut x)` deja en `x` el
valor de `Default` de su tipo y devuelve el anterior: sirve con `String`,
`Vec` y cualquier tipo con `Default`. `std::mem::swap(&mut a, &mut b)`
intercambia dos valores. Los tres parten de la misma idea que `replace`: el
destino siempre queda con un valor completo.

**Un `Box` de un tipo sin tamaño mide dos punteros.** Un slice `[i32]` no
tiene tamaño conocido al compilar, y aun así existe `Box<[i32]>`: 16 bytes,
la dirección y la longitud. `Box<str>` mide lo mismo. En `Box<dyn Trait>` el
segundo puntero lleva a la tabla de métodos del tipo concreto
([6.3 Despacho dinámico]{.ref}).

**Una lista enlazada cuesta una reserva por nodo.** Recorrerla es saltar de
bloque en bloque por el heap. Un `Vec` guarda sus elementos contiguos en un
solo bloque ([5.3 Vec]{.ref}), y por eso es la secuencia de uso general. La
biblioteca estándar trae una lista ya hecha, `LinkedList`
([5.5 Otras colecciones]{.ref}).

**Una lista larga desborda el stack al destruirse.** La destrucción en cadena
de la regla 2 es recursiva: soltar un nodo llama a soltar el siguiente antes
de terminar. Cada nodo apila un marco ([3.1 Stack y heap]{.ref}). Con un
millón de nodos el programa imprime `lista construida` y aborta al cerrar
`main`: *thread 'main' has overflowed its stack*.

El arreglo es un struct que envuelve la lista, con un `Drop` propio que
suelta los nodos en un ciclo. Cada vuelta separa un nodo del resto con
`take()`, y el nodo se destruye ya sin cola.

```rust
struct Nodo { valor: i32, siguiente: Option<Box<Nodo>> }
struct Lista { cabeza: Option<Box<Nodo>> }

impl Drop for Lista {
    fn drop(&mut self) {
        let mut actual = self.cabeza.take();
        while let Some(mut nodo) = actual {
            actual = nodo.siguiente.take();
        }   // nodo se destruye aquí, con siguiente en None
    }
}

fn main() {
    let mut lista = Lista { cabeza: None };
    for valor in 0..1_000_000 {
        let siguiente = lista.cabeza.take();
        let nodo = Nodo { valor, siguiente };
        lista.cabeza = Some(Box::new(nodo));
    }
    println!("lista construida");
}   // termina sin desbordar
```
