# 1.6 · Control de flujo

Los programas de [1.1 Tokens]{.ref} a [1.5 Funciones]{.ref} corren de arriba
abajo, una línea tras otra, una sola vez. No eligen entre dos caminos ni
repiten un paso. Para imprimir los números del 1 al 100 habría que escribir
cien líneas.

Rust tiene las construcciones de siempre para eso: `if`, `match` y tres
bucles. Las diferencias con otros lenguajes están en los detalles. La
condición no lleva paréntesis y tiene que ser un `bool`. `for` no cuenta con
un índice sino que recorre un rango. Y un `break` dentro de dos bucles puede
decir de cuál sale.

## Definiciones y reglas

Condición
:   expresión de tipo `bool` que decide si corre un bloque o si un bucle da
    otra vuelta.

Rama
:   cada uno de los caminos posibles de un `if` o de un `match`.

Bucle
:   bloque que se repite: `loop`, `while` o `for`.

Rango
:   *(range)*: la secuencia de enteros entre dos extremos, como `1..4` o
    `1..=4`.

Etiqueta
:   *(label)*: nombre de un bucle, escrito con apóstrofo inicial
    (`'externo:`), al que `break` y `continue` pueden apuntar.

::: {.reglas titulo="Las tres reglas del control de flujo"}
1. La condición de `if` y de `while` tiene que ser un `bool`. Ningún otro
   tipo se convierte solo.
2. `a..b` llega hasta `b` sin incluirlo; `a..=b` incluye `b`.
3. `break` y `continue` actúan sobre el bucle más interno, salvo que nombren
   una etiqueta.
:::

## De un vistazo

| Construcción | Qué hace | Forma |
| :--- | :--- | :--- |
| `if` | corre la primera rama que se cumple | `if c { } else { }` |
| `match` | compara un valor contra patrones | `match v { … }` |
| `loop` | repite hasta un `break` | `loop { … break; }` |
| `while` | repite mientras se cumpla | `while c { }` |
| `for` | recorre un rango | `for i in 1..=3 { }` |
| `if let`, `while let` | combinan un patrón y una condición | ver [2.4 Patrones]{.ref} |

## Las reglas, una por una

### `if`, `else if`, `else`

La condición va sin paréntesis y el bloque va siempre entre llaves, aunque
tenga una sola línea. Con varias ramas, Rust las prueba de arriba abajo y
corre solo la primera que se cumple. Un reto del curso *Aprende Rust*
clasifica el nivel de una batería:

```rust
fn estado_bateria(nivel: u8) {
    if nivel >= 80 {
        println!("cargada");
    } else if nivel >= 20 {
        println!("normal");
    } else if nivel > 0 {
        println!("baja");
    } else {
        println!("agotada");
    }
}

fn main() {
    estado_bateria(95);     // cargada
    estado_bateria(50);     // normal
    estado_bateria(0);      // agotada
}
```

Un nivel de 95 cumple también `nivel >= 20`, pero esa rama ya no se prueba.
Por eso el orden importa: la condición más estricta va arriba. El `else`
final es opcional; si falta y ninguna rama se cumple, no corre nada.

`if` también produce un valor, como `let s = if n > 0 { "+" } else { "-" };`.
Eso, y la regla de que las dos ramas den el mismo tipo, se trata en
[1.4 Todo es una expresión]{.ref}.

### [Regla 1:]{.prefijo} la condición es un `bool`

En JavaScript o en Python, un número sirve de condición: el 0 cuenta como
falso y lo demás como verdadero. Rust no tiene esa conversión:

```rust,compile_fail
fn main() {
    let mensajes = 3;
    if mensajes {
        println!("hay mensajes nuevos");
    }
}
```

```salida
error[E0308]: mismatched types
3 |     if mensajes {
  |        ^^^^^^^^ expected `bool`, found integer
```

El compilador esperaba un `bool` y encontró un entero. La pregunta se
escribe completa: `if mensajes > 0`. Una comparación produce un `bool`, y
también lo producen `&&`, `||` y `!` de [1.2 Tipos escalares]{.ref}. Así, la
condición dice qué se pregunta y no depende de qué valores cuentan como
falsos.

### `match` sobre valores

Cuando la pregunta es «¿cuál de estos valores es?», una cadena de `else if`
repite la variable en cada línea. `match` la escribe una vez y pone cada caso
en una rama de la forma `valor => expresión`:

```rust
fn mover(tecla: char) {
    match tecla {
        'w' => println!("arriba"),
        's' => println!("abajo"),
        'a' => println!("izquierda"),
        'd' => println!("derecha"),
        _ => println!("tecla sin uso"),
    }
}

fn main() {
    mover('a');             // izquierda
    mover('x');             // tecla sin uso
}
```

Las ramas se prueban en orden y corre la primera que encaja. `_` encaja con
cualquier valor: es la rama del resto, y va al final. A diferencia de una
cadena de `if`, `match` tiene que cubrir todos los valores posibles del tipo.
Sin la rama `_`, este ejemplo no compila: `error[E0004]: non-exhaustive
patterns`, con la lista de los `char` que faltan.

Lo que va a la izquierda de `=>` es un patrón, y puede ser mucho más que un
valor: rangos, alternativas, condiciones extra. Eso se trata en
[2.4 Patrones]{.ref}. Su uso principal, abrir un enum, está en
[2.3 Enums]{.ref}.

### `loop`, `break` y `continue`

`loop` repite su bloque sin condición. Sale con `break`. `continue` salta lo
que queda del bloque y empieza la vuelta siguiente:

```rust
fn main() {
    let mut n = 0;
    loop {
        n += 1;
        if n % 2 == 0 {
            continue;       // los pares no se imprimen
        }
        if n > 7 {
            break;          // sale del bucle
        }
        println!("{n}");    // 1, 3, 5, 7
    }
}
```

Sin un `break` alcanzable, el programa no termina nunca. `loop` sirve cuando
la salida depende de algo que se calcula dentro del bucle. Además puede
devolver un valor con `break valor`, como se ve en
[1.4 Todo es una expresión]{.ref}.

### `while`

`while` revisa su condición antes de cada vuelta y se detiene cuando da
`false`. Si es falsa desde el inicio, el bloque no corre ni una vez. Una
cuenta atrás:

```rust
fn main() {
    let mut n = 3;
    while n > 0 {
        println!("{n}...");
        n -= 1;
    }
    println!("¡despegue!");     // 3... 2... 1... ¡despegue!
}
```

El contador lleva tres piezas: el valor inicial, la condición y la
actualización. Las tres están en lugares distintos, y la variable tiene que
ser `mut`. Si falta el `n -= 1`, la condición nunca cambia y el bucle no
termina.

### [Regla 2:]{.prefijo} `for` y los rangos

`for` recorre una secuencia y liga cada elemento a una variable. Con un
rango, la secuencia es de enteros. La misma cuenta atrás, con `for`:

```rust
fn main() {
    for n in (1..=3).rev() {
        println!("{n}...");
    }
    println!("¡despegue!");     // 3... 2... 1... ¡despegue!
}
```

No hay `mut`, ni actualización, ni condición que se pueda olvidar: el rango
dice de dónde a dónde, y `for` se encarga del resto. `n` es una variable
nueva en cada vuelta.

Un rango se escribe de tres maneras, según incluya el final o vaya al revés.
`print!` es `println!` sin el salto de línea:

```rust
fn main() {
    for i in 1..4 {
        print!("{i} ");     // 1 2 3
    }
    for i in 1..=4 {
        print!("{i} ");     // 1 2 3 4
    }
    for i in (1..=3).rev() {
        print!("{i} ");     // 3 2 1
    }
}
```

`1..4` es el rango semiabierto: incluye el 1 y se detiene antes del 4. Es la
forma natural de contar posiciones desde 0, y la que se usa con los índices
de un arreglo en [2.1 Tuplas y arreglos]{.ref}. `1..=4` incluye los dos
extremos.

`.rev()` invierte el rango, y los paréntesis hacen falta. Sin ellos, `.rev()`
se aplica al `3` y no al rango: `1..=3.rev()` no compila
(``error[E0689]: can't call method `rev` on type `{integer}` ``).

Cuando el valor no se usa, el nombre se cambia por `_`: `for _ in 0..3` repite
tres veces sin crear una variable, y el compilador no avisa de una variable
sin usar. Además de rangos, `for` recorre arreglos y
otras colecciones; eso empieza en [2.1 Tuplas y arreglos]{.ref}.

### [Regla 3:]{.prefijo} etiquetas de bucle

Con dos bucles anidados, `break` sale solo del interior. Para buscar en la
tabla del 1 al 9 el primer par cuyo producto da 12:

```rust
fn main() {
    for i in 1..=9 {
        for j in 1..=9 {
            if i * j == 12 {
                println!("{i} x {j}");
                break;
            }
        }
    }
}
```

```salida
2 x 6
3 x 4
4 x 3
6 x 2
```

El `break` termina la fila, pero el bucle de `i` sigue con la siguiente, y
el programa encuentra cuatro pares en vez de uno. Una etiqueta le pone nombre
al bucle exterior, y `break 'externo` sale de él:

```rust
fn main() {
    'externo: for i in 1..=9 {
        for j in 1..=9 {
            if i * j == 12 {
                println!("{i} x {j}");      // 2 x 6
                break 'externo;
            }
        }
    }
}
```

::: {.figura src="figuras/1.6-etiqueta.html"}
:::

La etiqueta empieza con un apóstrofo y termina con dos puntos antes del
bucle, sea `for`, `while` o `loop`. `continue 'externo` funciona igual: abandona el bucle interior y
empieza la vuelta siguiente del exterior, saltando lo que haya después del
interior.

```rust
fn main() {
    'externo: for fila in 1..=3 {
        for col in 1..=3 {
            if fila * col == 4 {
                println!("fila {fila}: hay un 4");
                continue 'externo;
            }
        }
        println!("fila {fila}: sin 4");
    }
}
```

```salida
fila 1: sin 4
fila 2: hay un 4
fila 3: sin 4
```

Un `break` simple en lugar del `continue 'externo` imprimiría también
`fila 2: sin 4`, que es falso.

### `if let` y `while let`

Son las dos formas que combinan un patrón con una condición. `if let` corre
su bloque si el valor encaja con el patrón; `while let` repite mientras siga
encajando:

```text
if let PATRÓN = VALOR {
    // corre si VALOR encaja; aquí valen los nombres
} else {
    // opcional: corre si no encaja
}

while let PATRÓN = VALOR {
    // se repite mientras VALOR encaje
}
```

Tienen sentido cuando el valor puede tener varias formas, y de ellas importa
una. Ese es el caso de los enums de [2.3 Enums]{.ref}. Los ejemplos están en
[2.4 Patrones]{.ref}, y su uso más común, con `Option`, en
[5.1 Option]{.ref}.

### Qué bucle usar

| Bucle | Cuándo |
| :--- | :--- |
| `for` | por default: se conoce de antemano qué se recorre |
| `while` | mientras se cumpla una condición que se revisa al inicio |
| `loop` | hasta que ocurra algo que se calcula dentro del bucle |

`for` es el default porque no deja cabos sueltos: no hay contador que
actualizar ni condición que se quede siempre en `true`.

## Aplicación

FizzBuzz: del 1 al 15, imprimir «Fizz» en los múltiplos de 3, «Buzz» en los
de 5, «FizzBuzz» en los de ambos, y el número en los demás. Un `for` recorre
el rango y un `if` elige qué imprimir:

```rust
fn main() {
    for n in 1..=15 {
        if n % 15 == 0 {
            print!("FizzBuzz ");
        } else if n % 3 == 0 {
            print!("Fizz ");
        } else if n % 5 == 0 {
            print!("Buzz ");
        } else {
            print!("{n} ");
        }
    }
    println!();
}
```

```salida
1 2 Fizz 4 Buzz Fizz 7 8 Fizz Buzz 11 Fizz 13 14 FizzBuzz
```

El caso de 15 va primero por la regla de `if`: un múltiplo de 15 también lo
es de 3, y con `n % 3` arriba nunca llegaría a «FizzBuzz».

El segundo programa busca el primer primo mayor que 90. Un `loop` prueba los
candidatos, porque no se sabe cuántos hacen falta. Un `for` busca un divisor
de cada uno, y una etiqueta salta al candidato siguiente en cuanto lo
encuentra:

```rust
fn main() {
    let mut n = 90;
    'candidatos: loop {
        n += 1;
        for d in 2..n {
            if n % d == 0 {
                continue 'candidatos;   // tiene divisor
            }
        }
        break;                          // ninguno lo dividió
    }
    println!("{n}");                    // 97
}
```

El rango `2..n` excluye a `n`, que siempre se divide a sí mismo (regla 2).
Sin la etiqueta, `continue` volvería al `for` y seguiría probando divisores
de un número que ya se sabe compuesto. Al terminar el `for` sin saltar, `n`
es primo y el `break` sale del `loop`.

## A fondo

**Un rango con el inicio mayor que el final está vacío.** `for i in 5..1` no
corre ni una vez, y no hay error ni aviso. Para contar hacia abajo hace falta
`(1..5).rev()`, que da 4, 3, 2, 1.

**Un rango es un valor.** `1..4` se puede guardar en una variable,
`let r = 1..4;`, y recorrerse después con `for i in r`. Sus extremos pueden
ser expresiones: `0..n * 2`.

**`for` no tiene la forma de C.** No existe `for (i = 0; i < n; i++)`. Un
paso distinto de 1 se pide con `(0..10).step_by(2)`; ver [5.6 Iteradores]{.ref}.
