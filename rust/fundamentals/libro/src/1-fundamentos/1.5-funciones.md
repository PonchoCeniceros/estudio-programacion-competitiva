# 1.5 · Funciones

Hasta aquí todo el programa vive dentro de `main`. Si el mismo cálculo hace
falta tres veces, se escribe tres veces, y un error se corrige en tres
lugares. Con cien líneas en un solo bloque ya no se distingue qué parte hace
qué.

Una función le pone nombre a un bloque de código y lo deja recibir valores.
[1.4 Todo es una expresión]{.ref} dejó la regla que la sostiene: un bloque
vale su última expresión. Una función es un bloque con nombre, con entradas
declaradas y con el tipo de su salida escrito en la firma.

## Definiciones y reglas

Función
:   bloque de código con nombre que se declara con `fn` y se ejecuta al
    llamarlo: `doble(21)`.

Parámetro
:   variable que la función declara en su firma para recibir un valor:
    `n: i32`.

Argumento
:   el valor concreto que la llamada entrega a un parámetro: el `21` de
    `doble(21)`.

Firma
:   `fn doble(n: i32) -> i32`: la primera línea de la función, con su
    nombre, sus parámetros con tipo y su tipo de retorno.

Valor de retorno
:   lo que la función entrega a quien la llamó. Su tipo va después de `->`.

::: {.reglas titulo="Las tres reglas de las funciones"}
1. Cada parámetro declara su nombre y su tipo. El compilador no los infiere.
2. La función devuelve el valor de su cuerpo: la última expresión, sin `;`.
   `return` sale antes con un valor.
3. La llamada pasa un argumento por parámetro, en orden y del tipo declarado.
:::

## De un vistazo

| Escrito | Qué es |
| :--- | :--- |
| `fn saludar() { ... }` | función sin parámetros; devuelve `()` |
| `fn doble(n: i32)` | un parámetro: nombre, `:` y tipo |
| `-> i32` | el tipo del valor de retorno |
| `n * 2` al final, sin `;` | el valor que se devuelve |
| `return 0;` | salida anticipada con el valor `0` |
| `doble(21)` | la llamada; vale lo que la función devuelve |

## Las reglas, una por una

Antes de las reglas, cómo se declara y se llama una función.

### Declarar y llamar

```rust
fn main() {
    bienvenida("Rust");   // ¡Hola, Rust!
    bienvenida("mundo");  // ¡Hola, mundo!
}

fn bienvenida(nombre: &str) {
    println!("¡Hola, {nombre}!");
}
```

`fn` abre la declaración. Le siguen el nombre, los parámetros entre
paréntesis y el cuerpo entre llaves. Para llamarla se escribe el nombre y,
entre paréntesis, los argumentos. Una función sin parámetros se llama con
paréntesis vacíos: `saludar()`.

`bienvenida` está declarada después de `main`, y la llamada funciona. El
compilador lee todo el archivo antes de resolver los nombres, así que el
orden de las funciones no importa. Se suelen acomodar para que el archivo se
lea bien, con `main` arriba o abajo.

El parámetro `nombre` es de tipo `&str`, el de los literales de texto. Es
una de las dos referencias adelantadas del libro ([1.2 Tipos
escalares]{.ref}): por ahora se lee como «una cadena».

Los nombres de función van en *snake_case*: minúsculas y palabras separadas
por guion bajo, como `precio_final`. No es una regla del lenguaje, pero el
compilador avisa si se rompe. Con `fn sumarDos` da ``warning: function
`sumarDos` should have a snake case name``, y sugiere `sumar_dos`.

`main` tampoco es una palabra reservada. Es el nombre que el compilador
busca para arrancar un programa ejecutable, y un programa sin `fn main` no
compila (*E0601*). Fuera de ese papel, `main` es un identificador como
cualquier otro.

### [Regla 1:]{.prefijo} cada parámetro lleva nombre y tipo

Dentro del cuerpo, Rust infiere los tipos de las variables. En la firma no:
cada parámetro lleva su tipo después de `:`. Sin él, el código ni siquiera
llega al análisis de tipos:

```rust,compile_fail
fn doble(n) -> i32 {
    n * 2
}

fn main() {
    println!("{}", doble(21));
}
```

```salida
error: expected one of `:`, `@`, or `|`, found `)`
1 | fn doble(n) -> i32 {
  |           ^ expected one of `:`, `@`, or `|`
help: if this is a parameter name, give it a type
1 | fn doble(n: TypeName) -> i32 {
  |           ++++++++++
```

La exigencia es deliberada. La firma es un contrato: dice qué recibe la
función y qué devuelve, y se lee sin abrir el cuerpo. Quien llama a `doble`
sabe que debe darle un `i32` y que recibirá un `i32`, aunque el cuerpo
tenga cincuenta líneas.

El contrato también protege a la función. Si el cuerpo cambia, el compilador
compara el resultado contra la firma, no contra cada llamada. Un error queda
señalado en la función que lo comete, y no en un lugar lejano del programa.

Dentro del cuerpo, la inferencia sigue intacta. En una función
`con_iva(precio: f64) -> f64`, la línea `let iva = precio * 0.16;` no
necesita anotación: el compilador ya conoce el tipo de `precio`, y deduce
que `iva` es `f64`.

### [Regla 2:]{.prefijo} la función devuelve el valor de su cuerpo

El tipo de retorno se declara con `->` después de los parámetros. El valor
devuelto es el del cuerpo: como cualquier bloque, vale su última expresión.

```rust
fn doble(n: i32) -> i32 {
    n * 2
}

fn main() {
    let r = doble(21);
    println!("{r}");   // 42
}
```

`n * 2` es la última línea y no lleva punto y coma: es la expresión final
del bloque, y su valor sale de la función. La llamada `doble(21)` es a su
vez una expresión, y vale `42`.

### El punto y coma de más

El error más común al escribir funciones en Rust es un `;` al final, por
costumbre de otros lenguajes:

```rust,compile_fail
fn doble(n: i32) -> i32 {
    n * 2;
}

fn main() {
    println!("{}", doble(21));
}
```

```salida
error[E0308]: mismatched types
1 | fn doble(n: i32) -> i32 {
  |    -----            ^^^ expected `i32`, found `()`
  |    |
  |    implicitly returns `()` as its body has no tail
  |    or `return` expression
2 |     n * 2;
  |          - help: remove this semicolon to return
  |            this value
```

La causa es la regla de [1.4 Todo es una expresión]{.ref}. El `;` convierte
`n * 2` en un enunciado: se calcula y su valor se descarta. El bloque queda
sin expresión final, y un bloque así vale `()`. La firma prometió un `i32`,
el cuerpo entrega `()`, y los tipos no coinciden.

El mensaje lo dice en sus tres anotaciones. `i32` es lo que se esperaba; el
nombre de la función marca que el cuerpo devuelve `()` de forma implícita;
el `help:` señala el punto y coma exacto que sobra. La corrección es
quitarlo.

### Sin `->`, la función devuelve `()`

Una función sin `->` también devuelve algo: `()`, el valor unit de [1.2
Tipos escalares]{.ref}. `bienvenida` es de ese tipo. Su cuerpo termina en
`println!(...);`, y con el `;` el bloque vale `()`, que es justo lo que la
firma promete.

Por eso su resultado no sirve como número. `let x: i32 = bienvenida("Ana");`
no compila: da *E0308*, ``expected `i32`, found `()` ``.

### `return` para salir antes

A veces la respuesta se conoce antes de llegar al final. `return` sale de la
función en ese punto y entrega su valor. El ejemplo usa un `if`, que se
explica en [1.6 Control de flujo]{.ref}: el bloque entre llaves se ejecuta
solo si la condición es verdadera.

```rust
fn dividir(a: i32, b: i32) -> i32 {
    if b == 0 {
        return 0;
    }
    a / b
}

fn main() {
    println!("{}", dividir(10, 2));   // 5
    println!("{}", dividir(10, 0));   // 0
}
```

Con `b` igual a cero, `return 0;` termina la función y `a / b` no llega a
calcularse. En cualquier otro caso, el valor es el de la expresión final.

`return 0;` sí lleva punto y coma, y no contradice el apartado anterior. El
valor no sale como expresión final del bloque, sino por el `return`, que
abandona la función en ese momento. El `;` solo cierra el enunciado. La
regla del punto y coma de más aplica a la última expresión, no a `return`.

### [Regla 3:]{.prefijo} los argumentos van en orden y con su tipo

El primer argumento llega al primer parámetro, el segundo al segundo. Cada
uno debe ser del tipo que declara la firma, y Rust no convierte tipos por su
cuenta:

```rust,compile_fail
fn area(ancho: u32, alto: u32) -> u32 {
    ancho * alto
}

fn main() {
    let a = area(3.5, 4);
}
```

```salida
error[E0308]: mismatched types
6 |     let a = area(3.5, 4);
  |             ---- ^^^ expected `u32`, found
  |             |        floating-point number
  |             |
  |             arguments to this function are incorrect
note: function defined here
1 | fn area(ancho: u32, alto: u32) -> u32 {
  |    ^^^^ ----------
```

La nota final muestra la firma y subraya el parámetro afectado. El contrato
de la regla 1 es lo que permite señalar el error en la llamada y no dentro
de `area`.

La cantidad también se comprueba. `sumar(3)`, con una firma de dos
parámetros, da *E0061*: `this function takes 2 arguments but 1 argument was
supplied`.

Lo que el compilador no puede revisar es el sentido. `area(4, 3)` y
`area(3, 4)` compilan igual, porque los dos parámetros son `u32`. En una
función como `dividir`, invertir los argumentos da otro resultado sin
ningún aviso. Los nombres de los parámetros son la única pista, y por eso
conviene que digan qué es cada uno.

## Aplicación

Una tienda aplica un descuento del 10 % a las compras de 500 o más. El
programa reparte el trabajo en tres funciones que se llaman entre sí, y la
primera tiene una salida temprana:

```rust
fn descuento(total: u32) -> u32 {
    if total < 500 {
        return 0;
    }
    total / 10
}

fn precio_final(total: u32) -> u32 {
    total - descuento(total)
}

fn ticket(cliente: &str, total: u32) {
    let pagar = precio_final(total);
    println!("{cliente}: {total} -> {pagar}");
}

fn main() {
    ticket("Ana", 320);
    ticket("Beto", 800);
}
```

```salida
Ana: 320 -> 320
Beto: 800 -> 720
```

Cada firma cuenta lo que hace su función sin leer el cuerpo. `descuento` y
`precio_final` reciben un `u32` y devuelven otro, y terminan en una
expresión sin `;`. `ticket` no tiene `->`: imprime y devuelve `()`. `main`
solo llama y no calcula nada.

Una función devuelve un solo valor. Cuando hacen falta dos, como el área y
el perímetro de un rectángulo, ese valor es una tupla ([2.1 Tuplas y
arreglos]{.ref}).

## A fondo

**`return` al final compila, pero no es el estilo.** `return n * 2;` como
última línea funciona igual que `n * 2`. La convención de Rust reserva
`return` para las salidas anticipadas y deja que la expresión final haga el
trabajo en el caso normal.

**Una función no ve las variables de quien la llama.** El cuerpo solo
conoce sus parámetros y sus propias variables. Si `main` declara `limite` y
otra función lo usa sin recibirlo, el compilador da *E0425*: ``cannot find
value `limite` in this scope``. Todo lo que una función necesita entra por
sus parámetros. Las closures de [4.3 Closures]{.ref} sí capturan su
entorno.

**Un parámetro es una variable local.** Puede declararse `mut`, como
cualquier `let`: `fn cuenta(mut n: u32)`. Con un escalar, la función recibe
una copia del argumento, y cambiar `n` no cambia la variable de quien llama.
Con los tipos que no se copian, pasar un valor lo mueve ([3.2
Ownership]{.ref}).

**No hay sobrecarga ni valores por default.** Dos funciones con el mismo
nombre no compilan, aunque sus parámetros sean de tipos distintos: *E0428*,
``the name `doble` is defined multiple times``. Tampoco hay parámetros
opcionales: cada llamada pasa todos los argumentos.
