# 1.1 · Tokens

Un programa en Rust es un archivo de texto. Antes de ejecutarse, el compilador lo
traduce a un binario, y el primer paso de esa traducción es partir el texto en
piezas. Una letra fuera de lugar en ese paso y el compilador ya no entiende nada
de lo que sigue.

Esas piezas se llaman tokens, y hay seis clases. Conocerlas sirve para leer los
mensajes del compilador: «expected identifier, found keyword» habla de tokens.
Este capítulo parte del primer programa y rotula cada una de sus piezas.

## Definiciones y reglas

Token
:   la unidad mínima de texto con significado para el compilador: `fn`, `main`,
    `(`, `"hola"`, `;`.

Palabra reservada
:   *(keyword)*: palabra con un significado fijo en el lenguaje, como `fn`,
    `let` o `if`.

Identificador
:   nombre que el programador le pone a algo: una variable, una función.

Literal
:   valor escrito tal cual en el código: `42`, `2.5`, `true`, `'a'`, `"hola"`.

Operador
:   símbolo que calcula un valor a partir de otros: `+`, `*`, `==`, `&&`.

Puntuación y delimitadores
:   símbolos que dan estructura. La puntuación separa (`;`, `,`, `:`); los
    delimitadores agrupan, siempre en pares (`( )`, `[ ]`, `{ }`).

Macro
:   código que genera código al compilar. Su nombre termina en `!`:
    `println!`.

::: {.reglas titulo="Las tres reglas de los tokens"}
1. Todo programa es una secuencia de tokens de seis clases.
2. Una palabra reservada no puede usarse como identificador.
3. Los delimitadores van en pares, y el `;` separa un enunciado del siguiente.
:::

## Las reglas, una por una

Antes de las reglas, el primer programa y las dos herramientas que todos los
capítulos siguientes usan: imprimir y comentar.

### El primer programa, pieza por pieza

```rust
// Mi primer programa
fn main() {
    println!("¡Hola, mundo!");
}
```

Al ejecutarse imprime `¡Hola, mundo!`. Cada pieza es un token, o un grupo de
ellos:

- `// Mi primer programa` es un comentario. Todo lo que sigue a `//` hasta el
  final de la línea se ignora: es texto para quien lee el código.
- `fn` es una palabra reservada. Anuncia que empieza una función; las funciones
  se explican en [1.5 Funciones]{.ref}.
- `main` es un identificador, el nombre de esa función. Ese nombre es especial:
  `main` es el punto de entrada, la función con la que arranca todo programa.
- `()` son delimitadores. Aquí van vacíos porque `main` no recibe nada.
- `{ }` son delimitadores que encierran el cuerpo de la función. El programa
  termina al llegar a la llave de cierre.
- `println!` es una macro. El `!` la distingue de una función: al compilar, la
  macro se expande en el código que da formato al texto y lo escribe en
  pantalla, seguido de un salto de línea. Las macros a fondo están en
  [7.6 Macros y atributos]{.ref}.
- `"¡Hola, mundo!"` es un literal de texto: los caracteres entre comillas, tal
  cual. Puede llevar acentos y signos de apertura.
- `;` es puntuación. Cierra el enunciado.

### Imprimir valores

El texto que recibe `println!` puede llevar huecos entre llaves. Un nombre dentro
de las llaves se reemplaza por el valor de la variable con ese nombre:

```rust
fn main() {
    let nombre = "Ferris";
    let edad = 8;
    println!("{nombre} tiene {edad} años");
    println!("{} tiene {} años", nombre, edad + 1);
}
```

`let` liga un nombre a un valor; [1.3 Variables]{.ref} lo explica. La primera
línea imprime `Ferris tiene 8 años`. En la segunda, las llaves vacías se llenan
en orden con los argumentos que siguen al texto, separados por comas. Un
argumento puede ser un cálculo, como `edad + 1`, así que imprime `Ferris tiene 9
años`.

El número de llaves vacías y el de argumentos deben coincidir. Si sobra una
llave, el programa no compila: `error: 2 positional arguments in format string,
but there is 1 argument`.

`format!` funciona igual, pero no imprime: devuelve el texto armado para
guardarlo en una variable, `let saludo = format!("Hola, {nombre}");`.

### [Regla 1:]{.prefijo} seis clases de token

El compilador lee el archivo de izquierda a derecha y lo corta en tokens. Los
espacios, los saltos de línea y los comentarios separan un token del siguiente,
pero no son tokens: `let doble=(n+1)*2;` produce la misma secuencia que la
versión con espacios de la figura.

La clase de un token depende de su forma. Una palabra de la lista reservada es
palabra reservada; cualquier otra palabra es identificador. Lo que empieza con
dígito o con comilla es literal. Los símbolos se reparten entre operadores,
puntuación y delimitadores.

### [Regla 2:]{.prefijo} una palabra reservada no es un nombre

Rust tiene alrededor de cuarenta palabras reservadas, y ninguna puede servir de
identificador. El error típico es querer llamar `type` a una variable que guarda
un tipo de usuario:

```rust,compile_fail
fn main() {
    let type = "admin";
}
```

```salida
error: expected identifier, found keyword `type`
2 |     let type = "admin";
  |         ^^^^ expected identifier, found keyword
```

El mensaje dice qué clase de token esperaba (un identificador) y cuál encontró
(una palabra reservada). Al final sugiere escribir `r#type`, un identificador
crudo (ver «A fondo»); un nombre distinto, como `rol`, se lee mejor.

Las reservadas que aparecen en los primeros capítulos son pocas: `fn` para
funciones, `let` y `mut` para variables, `if`, `else` y `match` para decidir, y
`loop`, `while`, `for` e `in` para repetir. Las demás llegan con su tema:
`struct` en [2.2 Structs]{.ref}, `impl` en [3.5 impl y métodos]{.ref}, `trait`
en [4.1 Traits]{.ref}.

### Los identificadores se escriben en snake_case

Un identificador empieza con letra o guion bajo y sigue con letras, dígitos o
guiones bajos. La convención de Rust para variables y funciones es *snake_case*:
minúsculas y palabras separadas por guion bajo, como `precio_final`. Con otra
forma el programa compila, pero el compilador avisa:

```rust
fn main() {
    let precioFinal = 120;
    println!("{precioFinal}");
}
```

```salida
warning: variable `precioFinal` should have a snake case
         name
2 |     let precioFinal = 120;
  |         ^^^^^^^^^^^ help: convert the identifier to snake
  |                     case: `precio_final`
```

Los tipos siguen otra convención, *UpperCamelCase* (`Rectangulo`), y las
constantes van en mayúsculas (`MAX_INTENTOS`). Las dos aparecen en sus
capítulos.

### [Regla 3:]{.prefijo} pares que cierran y enunciados que terminan

Un enunciado es una instrucción completa, como la llamada a `println!`. El `;`
marca dónde termina. Si falta entre dos enunciados, el compilador encuentra el
segundo pegado al primero:

```rust,compile_fail
fn main() {
    println!("uno")
    println!("dos");
}
```

```salida
error: expected `;`, found `println`
2 |     println!("uno")
  |                    ^ help: add `;` here
3 |     println!("dos");
  |     ------- unexpected token
```

El error señala dónde falta el `;` y el token que no esperaba. Sin `;` en la
última línea de un bloque, el bloque devuelve un valor: eso es tema de
[1.4 Todo es una expresión]{.ref}.

Los delimitadores van en pares, y un par puede contener a otro: `{()}`.
Una llave sin cierre no compila:

```rust,compile_fail
fn main() {
    println!("hola");
```

```salida
error: this file contains an unclosed delimiter
1 | fn main() {
  |           - unclosed delimiter
2 |     println!("hola");
  |                      ^
```

El compilador señala la llave que abrió el par, no el lugar donde faltó el
cierre: no puede saber dónde quería cerrarse. Con las comillas pasa lo mismo:
un texto sin comilla final se come el resto del archivo y da *E0765*,
`unterminated double quote string`.

## Aplicación

El programa calcula el total de una compra con 16 % de IVA. Usa las seis clases
de token:

```rust
// Total de una compra con IVA
fn main() {
    let precio = 250;
    let total = precio + precio * 16 / 100;
    println!("Precio: {precio}");
    println!("Total con IVA: {total}");
}
```

Imprime `Precio: 250` y `Total con IVA: 290`. Los tokens, por clase:

| Clase | Tokens del programa |
| :--- | :--- |
| Palabra reservada | `fn`, `let` |
| Identificador | `main`, `precio`, `total`, `println` |
| Literal | `250`, `16`, `100`, los dos textos entre comillas |
| Operador | `=`, `+`, `*`, `/` |
| Puntuación | `;`, el `!` de `println!` |
| Delimitador | `( )`, `{ }` |

El comentario no aparece en la tabla: no es un token. `println` es un
identificador; el `!` que lo sigue lo vuelve una macro. Delante de un `bool`, el
mismo carácter es el operador de negación ([1.2 Tipos escalares]{.ref}). Y
`{precio}` no es un token suelto: forma parte del literal, y la macro lo busca
al compilar.

## A fondo

**El compilador toma el token más largo posible.** `>=` es un solo token, no
`>` seguido de `=`; `==` es comparación y no dos asignaciones. Por eso
`a >= b` y `a > = b` no significan lo mismo: el segundo no compila.

**Algunas palabras están reservadas sin uso.** `abstract`, `become`, `box`,
`do`, `final`, `macro`, `override`, `priv`, `try`, `typeof`, `unsized`, `virtual` y
`yield` no hacen nada todavía, pero ya no sirven de nombre. La edición 2024
agregó `gen`: `let gen = 1;` compila en la edición 2021 y falla en la 2024 con
`expected identifier, found reserved keyword`.

**Un identificador crudo usa una palabra reservada como nombre.** El prefijo
`r#` le quita a la palabra su papel: `let r#match = 3;` compila. Existe para
llamar código escrito en ediciones anteriores, donde la palabra todavía no era
reservada.

**Las llaves literales se duplican.** Dentro del texto de `println!`, `{` abre
un hueco. Para imprimir una llave se escribe doble: `println!("{{}}")`
imprime `{}`.

**Un comentario con tres barras es documentación.** `///` antes de una función
la documenta, y la herramienta `rustdoc` convierte esos comentarios en páginas
de referencia. A diferencia de `//`, el compilador los conserva.
