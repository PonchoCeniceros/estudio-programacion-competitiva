# 1.4 · Todo es una expresión

En C o en Python, elegir un valor según una condición obliga a escoger entre
dos formas. Una es declarar la variable y asignarla dentro de un `if`. La otra
es un operador aparte, el ternario `c ? a : b`, que solo existe para ese caso.
Rust no tiene operador ternario, y no le hace falta.

La razón está en una distinción que el código de [1.3 Variables]{.ref} ya usaba
sin nombrarla. Unas líneas hacen algo; otras producen un valor. En Rust casi
todo pertenece al segundo grupo: los bloques, el `if`, el `match` y el `loop`.
Un solo carácter, el punto y coma, decide de qué lado cae una línea.

## Definiciones y reglas

Enunciado
:   *(statement)*: una instrucción que hace algo y no produce valor.
    `let x = 5;` es un enunciado.

Expresión
:   *(expression)*: un fragmento de código que se evalúa a un valor. `5`,
    `x + 1` y `x > 0` son expresiones.

Bloque
:   código entre llaves `{ ... }`. Abre su propio scope y es una expresión.

Unit
:   el tipo `()` y su único valor, también escrito `()`. Es el valor de
    «nada que devolver».

::: {.reglas titulo="Las tres reglas de las expresiones"}
1. Una expresión produce un valor; un enunciado no, y no puede ocupar el
   lugar de una expresión.
2. Un bloque vale lo que vale su última expresión. Si termina en `;`, vale
   `()`.
3. `if`, `match` y `loop` son expresiones: valen lo que vale el camino que se
   toma, y todos los caminos dan el mismo tipo.
:::

## De un vistazo

| Código | Clase | Valor |
| :--- | :--- | :--- |
| `let x = 5;` | enunciado | ninguno |
| `x + 1` | expresión | la suma |
| `{ let x = 3; x + 1 }` | expresión | `4` |
| `{ let x = 3; x + 1; }` | expresión | `()` |
| `if c { 1 } else { 2 }` | expresión | la rama elegida |
| `match n { 1 => 10, _ => 0 }` | expresión | la rama que encaja |
| `loop { break 8; }` | expresión | el valor del `break` |

Criterio de lectura: ante cualquier par de llaves, la pregunta es qué valor
deja la última línea y si lleva punto y coma.

## Las reglas, una por una

### [Regla 1:]{.prefijo} enunciado y expresión

Un `let` es un enunciado. Liga un nombre a un valor y termina ahí: el `let`
mismo no vale nada. Lo que va a la derecha del `=` sí es una expresión, y
puede ser tan simple como un literal o tan larga como una cuenta:

```rust
fn main() {
    let x = 5;             // enunciado
    let y = x + 1;         // x + 1 vale 6
    let positivo = x > 0;  // x > 0 vale true
    println!("{y} {positivo}");
}
```

Como el `let` no produce valor, no puede aparecer donde se espera uno. En C,
`a = (b = 1)` encadena asignaciones. En Rust, el equivalente con `let` ni
siquiera llega a la comprobación de tipos:

```rust,compile_fail
fn main() {
    let a = (let b = 1);
}
```

```salida
error: expected expression, found `let` statement
2 |     let a = (let b = 1);
  |              ^^^
  = note: only supported directly in conditions of `if`
          and `while` expressions
```

El mensaje lo dice con las mismas palabras de este capítulo: se esperaba una
expresión y llegó un enunciado. La nota se refiere a una forma especial de
`if` que se presenta en [2.4 Patrones]{.ref}.

### [Regla 2:]{.prefijo} un bloque vale su última expresión

Las llaves no solo agrupan líneas. Un bloque es una expresión: se puede poner
a la derecha de un `let`. Adentro admite enunciados, y su valor es el de la
última expresión, la que no lleva punto y coma:

```rust
fn main() {
    let y = {
        let x = 3;
        x + 1    // sin `;`: este es el valor del bloque
    };
    println!("{y}");   // 4
}
```

El bloque abre su propio scope, como los de [1.3 Variables]{.ref}: `x` existe
solo entre las llaves, y afuera queda `y` con el valor `4`. Este patrón sirve
para calcular un valor con pasos intermedios sin dejar esos pasos a la vista
del resto del programa.

Basta un punto y coma después de `x + 1` para que el resultado cambie. El `;`
convierte la expresión en enunciado: la suma se calcula y su valor se
descarta. El bloque termina entonces sin expresión final, y un bloque así
vale `()`.

::: {.figura src="figuras/1.4-punto-y-coma.html"}
:::

El cambio no es un aviso de estilo. Cambia el tipo de `y`, y el error aparece
donde `y` se usa como número:

```rust,compile_fail
fn main() {
    let y = {
        let x = 3;
        x + 1;
    };
    let doble = y * 2;
}
```

```salida
error[E0369]: cannot multiply `()` by `{integer}`
6 |     let doble = y * 2;
  |                 - ^ - {integer}
  |                 |
  |                 ()
```

El compilador no señala el punto y coma, sino la multiplicación: ahí descubre
que `y` es de tipo `()`. Al leer un error con `()` donde se esperaba un
número, lo primero es buscar un `;` de más al final de un bloque. El caso más
frecuente es el cuerpo de una función que debe devolver un valor, y está en
[1.5 Funciones]{.ref}.

### `()`: el valor de nada que devolver

[1.2 Tipos escalares]{.ref} presenta `()` como un tipo con un único valor. Aquí
aparece su papel: es lo que vale cualquier expresión que no tiene nada útil
que devolver. Un bloque que termina en `;` vale `()`, y una llamada a
`println!` también. Ese valor se puede guardar, anotar e imprimir. Para
imprimirlo hace falta `{:?}` en lugar de `{}`, el formato de depuración que
presenta [2.1 Tuplas y arreglos]{.ref}:

```rust
fn main() {
    let impreso: () = println!("hola");
    println!("{impreso:?}");   // ()
}
```

Que todo tenga un valor, aunque sea `()`, es lo que permite la regla 2 sin
excepciones. No hay bloques «sin valor»: hay bloques que valen `()`.

### [Regla 3:]{.prefijo} `if` como expresión

Un `if` con `else` es una expresión: vale lo que vale la rama que se ejecuta.
Cada rama es un bloque, así que la regla 2 dice qué valor deja. La forma
completa del `if`, con su condición y sus `else if`, está en
[1.6 Control de flujo]{.ref}. Esta es una referencia adelantada: aquí basta
la forma más simple.

```rust
fn main() {
    let n = -5;
    let signo = if n < 0 { -1 } else { 1 };
    println!("{signo}");   // -1
}
```

Esta línea hace el trabajo del ternario de C, `n < 0 ? -1 : 1`, con la misma
sintaxis que un `if` cualquiera. Por eso Rust no tiene un operador aparte.

`signo` necesita un tipo fijo al compilar, y el compilador no sabe qué rama se
va a tomar. Por eso las dos ramas deben dar el mismo tipo:

```rust,compile_fail
fn main() {
    let n = 7;
    let p = if n > 0 { "positivo" } else { 0 };
}
```

```salida
error[E0308]: `if` and `else` have incompatible types
3 |     let p = if n > 0 { "positivo" } else { 0 };
  |                        ----------          ^
  |                        |     expected `&str`,
  |                        |     found integer
  |                        expected because of this
```

Un `if` sin `else` vale `()` cuando la condición es falsa, así que su rama
también debe valer `()`. Por eso no sirve para asignar. Quitarle el `else`
al ejemplo de `signo` da *E0317*, «`if` may be missing an `else` clause», con
la nota «`if` expressions without `else` evaluate to `()`».

### `match` y `loop` también producen valor

`match` compara un valor contra una lista de patrones y vale lo que vale la
rama que encaja. Como en el `if`, todas las ramas dan el mismo tipo. El
patrón `_` encaja con cualquier valor y cubre el resto de los casos. `match`
y sus patrones se presentan en [1.6 Control de flujo]{.ref}; aquí interesa
solo su valor:

```rust
fn main() {
    let codigo = 2;
    let nombre = match codigo {
        1 => "uno",
        2 => "dos",
        _ => "otro",
    };
    println!("{nombre}");   // dos
}
```

`loop` repite su bloque sin fin, hasta que un `break` lo detiene. Un `break`
puede llevar un valor, y ese valor es lo que vale el `loop`. Este busca el
primer número cuyo cuadrado pasa de 50:

```rust
fn main() {
    let mut i = 0;
    let primero = loop {
        i += 1;
        if i * i > 50 {
            break i;   // el loop vale i
        }
    };
    println!("{primero}");   // 8
}
```

El `if` de adentro no lleva `else` y vale `()`: se usa solo para decidir
cuándo salir. El valor lo aporta el `break`.

## Aplicación

Un cálculo de envío sin variables mutables. La tarifa sale de un `if` y el
total de un bloque que esconde sus pasos intermedios.

```rust
fn main() {
    let peso_kg = 12;
    let distancia_km = 40;
    let tarifa_km = if peso_kg > 10 { 6 } else { 4 };
    let total = {
        let base = tarifa_km * distancia_km;
        let iva = base * 16 / 100;
        base + iva
    };
    println!("{total} pesos");   // 278 pesos
}
```

`base` e `iva` no existen fuera del bloque de `total`: el resto de `main` solo
ve el resultado. Con la tarifa decidida en una sola línea, no hace falta
declarar `tarifa_km` como `mut` para asignarla después en cada rama.

## A fondo

**La asignación también es una expresión, y vale `()`.** Una asignación como
`a = 1` a una variable `mut` no es un `let`: es una expresión de tipo `()`.
Por eso `a = b = 1` compila hasta la comprobación de tipos y ahí falla con
*E0308*, «expected integer, found `()`»: a `a` se le intenta asignar el valor
de `b = 1`, que es `()`.

**`x + 1;` es un enunciado de expresión.** Rust tiene dos clases de
enunciado. Las declaraciones, como `let`, introducen nombres. Los enunciados
de expresión son una expresión seguida de `;`: se evalúan y su valor se
descarta. Esa es la forma de casi todas las líneas que terminan en `;`, como
una llamada a `println!`.

**Solo `loop` acepta `break` con valor.** Un `while` o un `for` pueden
terminar sin ejecutar su cuerpo ni una vez, y entonces no habría valor que
devolver. Por eso siempre valen `()`, y `break i` dentro de un `while` da
*E0571*, «`break` with value from a `while` loop».

**`break`, `return` y `panic!` tienen el tipo `!`.** Ese tipo, llamado
*never*, es el de las expresiones que nunca terminan de evaluarse: saltan a
otro lado. Encaja con cualquier tipo, así que una rama puede valer `-1` y la
otra hacer `break` sin violar la regla 3.
