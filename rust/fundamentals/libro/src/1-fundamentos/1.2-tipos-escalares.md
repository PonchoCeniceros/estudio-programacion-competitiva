# 1.2 · Tipos escalares

En muchos lenguajes, `5 + 2.5` da `7.5` sin más. En Rust no compila. Y un
número que no cabe en su tipo tampoco pasa en silencio: según el caso, el
compilador lo rechaza o el programa se detiene.

Las dos sorpresas salen de lo mismo. En Rust cada valor tiene un tipo fijo, y
el tipo dice cuántos bytes ocupa y qué valores caben. Este capítulo presenta
los tipos de un solo valor, llamados escalares: enteros, flotantes, `bool`,
`char` y `()`.

## Definiciones y reglas

Tipo escalar
:   tipo que representa un solo valor: un número, un booleano, un carácter
    o la ausencia de valor.

Entero con signo, entero sin signo
:   `i8` a `i128` admiten negativos; `u8` a `u128` solo admiten cero y
    positivos. La letra es *integer* o *unsigned*; el número, los bits.

Flotante
:   número con parte decimal según el estándar IEEE 754: `f32` y `f64`.

Inferencia
:   el compilador deduce el tipo de un valor por cómo se escribe y se usa.

Desbordamiento
:   *(overflow)*: un resultado que se sale del rango de su tipo.

::: {.reglas titulo="Las tres reglas de los escalares"}
1. Cada tipo tiene un tamaño fijo, y con él un rango de valores.
2. Rust no mezcla tipos numéricos ni convierte por su cuenta: se pide con `as`.
3. Salirse del rango es un error, salvo que se pida de forma explícita otra cosa.
:::

## De un vistazo

| Tipo | Bytes | Rango o valores | Literal |
| :--- | :--- | :--- | :--- |
| `i8` `i16` `i32` `i64` `i128` | 1 a 16 | de −2ⁿ⁻¹ a 2ⁿ⁻¹ − 1 | `-42`, `7i64` |
| `u8` `u16` `u32` `u64` `u128` | 1 a 16 | de 0 a 2ⁿ − 1 | `255u8` |
| `isize` `usize` | 8 en 64 bits | los de un puntero | `0usize` |
| `f32` `f64` | 4 y 8 | IEEE 754 | `2.5`, `1e-3` |
| `bool` | 1 | `true`, `false` | `true` |
| `char` | 4 | un carácter Unicode | `'z'`, `'ñ'` |
| `()` | 0 | un solo valor, `()` | `()` |

Criterio: `i32` para un entero cualquiera, `usize` para posiciones y tamaños,
`f64` para decimales. Otro tipo solo cuando el rango o la memoria lo piden.

## Las reglas, una por una

### [Regla 1:]{.prefijo} el nombre dice el tamaño

El nombre de un tipo entero es un código de dos partes. `i` o `u` dice si
admite negativos, y el número dice cuántos bits ocupa: `u8` es un entero sin
signo de 8 bits, `i64` uno con signo de 64.

Con *n* bits caben 2ⁿ valores distintos. En 8 bits caben 2⁸ = 256. Un `u8`
los usa todos para el cero y los positivos: va de 0 a 255. Un `i8` gasta la
mitad en negativos y va de −128 a 127. Son los mismos 256 valores con distinto
inicio:

:::

`isize` y `usize` miden lo mismo que una dirección de memoria: 8 bytes en una
máquina de 64 bits. Por eso Rust usa `usize` para los índices y las
longitudes. Para el resto de los enteros, `i32` es el default: alcanza para
más de dos mil millones en cada sentido.

### Inferencia, anotación y sufijo

Un tipo casi nunca se escribe. El compilador lo infiere: un entero sin más
datos es `i32` y un número con punto es `f64`. Para fijar otro tipo hay dos
formas: anotar el nombre con `: tipo` o pegarle un sufijo al literal.

```rust
fn main() {
    let a = 42;          // i32: el default de los enteros
    let b = 2.5;         // f64: el default de los flotantes
    let c: u8 = 200;     // anotación
    let d = 255u8;       // sufijo
    let e = 1_000_000;   // _ solo separa dígitos
    println!("{} {} {} {} {}", a, b, c, d, e);
}
```

`let` da nombre a un valor; sus reglas están en [1.3 Variables]{.ref}. Un
literal que no cabe en el tipo anotado no compila: `let x: u8 = 256;` da
`error: literal out of range for u8`, y la nota dice el rango, `0..=255`.

### Flotantes, `bool` y `()`

`f64` es el flotante por default: en una computadora actual es tan rápido como
`f32` y tiene el doble de precisión. Un flotante es una aproximación binaria,
así que `0.1 + 0.2` imprime `0.30000000000000004`.

`bool` vale `true` o `false` y ocupa un byte. Es el tipo de toda comparación
(`==`, `!=`, `<`, `>`, `<=`, `>=`) y el que pide un `if`
([1.6 Control de flujo]{.ref}). Dos `bool` se combinan con `&&` (y), `||` (o) y
`!` (no): `edad >= 18 && !expulsado` es `true` solo si se cumplen las dos cosas.

`()` se llama unit. Es un tipo con un solo valor, también escrito `()`, y no
ocupa memoria. Cumple el papel del `void` de otros lenguajes: es lo que
devuelve una función que no devuelve nada ([1.5 Funciones]{.ref}). Su forma de
paréntesis vacíos se explica en [2.1 Tuplas y arreglos]{.ref}.

### `char` y el texto

Un `char` es un carácter Unicode: una letra de cualquier alfabeto, un símbolo
o un emoji. Ocupa siempre 4 bytes, lo necesario para cualquiera de ellos. Se
escribe entre comillas simples: `'a'`, `'ñ'`, `'λ'`. Las comillas dobles son
otro tipo, el texto, y no se intercambian:

```rust,compile_fail
fn main() {
    let c: char = "a";
}
```

```salida
error[E0308]: mismatched types
2 |     let c: char = "a";
  |            ----   ^^^ expected `char`, found `&str`
  |            |
  |            expected due to this
help: if you meant to write a `char` literal, use single
      quotes
```

### Dos referencias adelantadas

El mensaje anterior nombra un tipo que todavía no se puede explicar. El libro
lo usa desde ya, junto con otro, y los declara aquí:

- El texto entre comillas dobles, como `"hola"`, es un `&str`. El `&`
  significa referencia: un préstamo de un valor que vive en otro lado.
- Desde la sección 2, los ejemplos usan `String`, el texto que puede
  crecer.

Mientras tanto, los dos se leen como «una cadena de texto». El `&` se explica
en [3.3 Borrowing]{.ref}, el heap donde vive un `String` en [3.1 Stack y
heap]{.ref}, y los dos tipos a fondo en [3.4 Strings]{.ref}.

### [Regla 2:]{.prefijo} los números no se mezclan

Una suma necesita dos operandos del mismo tipo. Entre un entero y un flotante
no hay suma definida, y Rust no convierte uno en el otro:

```rust,compile_fail
fn main() {
    let x = 5 + 2.5;
}
```

```salida
error[E0277]: cannot add a float to an integer
2 |     let x = 5 + 2.5;
  |               ^ no implementation for
  |                 `{integer} + {float}`
```

Lo mismo pasa entre dos enteros de distinto tamaño: un `i32` más un `i64` da
*E0308*, `mismatched types`. La causa es la misma: cada conversión puede
perder información, y Rust exige verla escrita.

El tipo también decide qué hace la división. Entre enteros, `/` descarta la
parte decimal:

```rust
fn main() {
    println!("{}", 7 / 2);      // 3: división entera
    println!("{}", 7 % 2);      // 1: el residuo
    println!("{}", -7 / 2);     // -3: trunca hacia el cero
    println!("{}", 7.0 / 2.0);  // 3.5: división flotante
}
```

### Convertir con `as`

La conversión se escribe con `as` seguido del tipo destino. Es explícita, pero
no comprueba nada: si el valor no cabe, `as` lo recorta sin avisar.

```rust
fn main() {
    let grande = 300;
    let precio = 3.99;
    let letra = 'A';

    println!("{}", grande as u8);   // 44
    println!("{}", precio as i32);  // 3
    println!("{}", letra as u32);   // 65
}
```

300 no cabe en un `u8`. `as` conserva los 8 bits bajos, y quedan 300 − 256 =
44. De flotante a entero, `as` descarta los decimales sin redondear. De `char`
a entero da el número Unicode del carácter. Ninguno de los tres es un error
para el compilador.

El ejemplo usa un nombre y no el literal porque `300 as u8` no compila: el
literal toma el tipo `u8` y el compilador lo rechaza como fuera de rango.

### [Regla 3:]{.prefijo} el desbordamiento no se ignora

Un resultado que se sale del rango tiene tres destinos. Si el compilador lo
ve, como en `u8::MAX + 1` con valores fijos, no compila: `error: this
arithmetic operation will overflow`. Si solo se conoce al ejecutar, depende de
cómo se compiló el programa.

El ejemplo siguiente usa `mut` para que el valor cambie al ejecutar
([1.3 Variables]{.ref}). Compilado sin optimizar, el modo de desarrollo, el
programa hace panic: se detiene con un mensaje.

```rust,should_panic
fn main() {
    let mut volumen: u8 = 250;
    volumen += 10;
    println!("{}", volumen);
}
```

```salida
thread 'main' panicked at src/main.rs:3:5:
attempt to add with overflow
```

Compilado en modo release, con optimización, la comprobación se quita y el
valor da la vuelta: el mismo programa imprime `4`. Es el código fuente
idéntico con dos comportamientos según el perfil.

### Pedir el desbordamiento de forma explícita

A veces dar la vuelta o toparse en el límite es lo correcto. Para esos casos,
cada operación tiene cuatro variantes con nombre, y ninguna depende del
perfil:

| Familia | Qué hace al desbordar | `250u8` más `10` |
| :--- | :--- | :--- |
| `checked_add` | avisa que no hubo resultado | `None` |
| `wrapping_add` | da la vuelta | `4` |
| `saturating_add` | se topa en el límite | `255` |
| `overflowing_add` | da la vuelta y lo reporta | `(4, true)` |

`checked_add` devuelve un `Option`, el tipo de lo que puede faltar
([5.1 Option]{.ref}). `overflowing_add` devuelve una tupla de dos valores
([2.1 Tuplas y arreglos]{.ref}). Las dos que devuelven un número se usan así:

```rust
fn main() {
    let volumen: u8 = 250;
    println!("{}", volumen.wrapping_add(10));    // 4
    println!("{}", volumen.saturating_add(10));  // 255
}
```

`checked_` es la elección para una entrada que no es de fiar. `saturating_`
sirve para lo que tiene tope, como un volumen o una barra de vida.
`wrapping_` da la vuelta a propósito, como en un hash. Las cuatro familias
existen también para `sub`, `mul` y `pow`.

## Aplicación

Cuatro llamadas duraron 17 minutos en total. El promedio pide decimales, pero
los minutos se cuentan con enteros. El ejemplo es de la lección de tipos del
curso *Aprende Rust*:

```rust
fn main() {
    let total: u32 = 17;
    let llamadas: u32 = 4;

    let entero = total / llamadas;
    let promedio = total as f64 / llamadas as f64;

    println!("{}", entero);    // 4
    println!("{}", promedio);  // 4.25
}
```

`total / llamadas` es división entera y pierde el cuarto de minuto. Para el
promedio, los dos operandos se convierten a `f64` antes de dividir. Convertir
solo uno no compila, por la regla 2.

El segundo programa aplica un descuento. Si el descuento supera al precio,
una resta de `u32` desbordaría por debajo de cero; `saturating_sub` se queda
en 0:

```rust
fn main() {
    let precio: u32 = 80;
    let descuento: u32 = 100;
    let a_pagar = precio.saturating_sub(descuento);
    println!("{}", a_pagar);   // 0
}
```

## A fondo

**El perfil release se puede cambiar.** La comprobación de desbordamiento la
controla la opción `overflow-checks` de Cargo. Con `overflow-checks = true`
en el perfil release, también ahí hace panic ([7.2 Crates y Cargo]{.ref}).

**Los enteros con signo usan complemento a 2.** En un `i8`, el −1 se guarda
con los ocho bits en 1, igual que el 255 de un `u8`. Por eso `-1i8 as u8`
da 255: `as` entre enteros del mismo tamaño no toca los bits, solo cambia
cómo se leen.

**De flotante a entero, `as` satura.** `300.7_f64 as u8` da 255 y
`-5.0_f64 as u32` da 0. Entre enteros recorta bits; desde un flotante se topa
en el límite del tipo destino.

**Un `u8` se convierte en `char`, otro entero no.** `65u8 as char` da `'A'`,
porque todo `u8` es un carácter válido. Con un `u32` da *E0604*, `only u8 can
be cast as char`: no todo número de 32 bits es un carácter Unicode.

**Hay literales en otras bases.** `0xff`, `0o17` y `0b1010` son 255, 15 y 10
en hexadecimal, octal y binario. `b'A'` es el byte 65, de tipo `u8`.

**Cada tipo trae sus límites.** `u8::MAX` es 255 e `i8::MIN` es −128. Un
`u64` llega a 18446744073709551615, y un `i128` pasa de 10³⁸.
