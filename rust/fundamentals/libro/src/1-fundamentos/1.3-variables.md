# 1.3 · Variables

Un programa guarda valores con nombre para usarlos después. En muchos
lenguajes ese nombre se puede reasignar en cualquier línea. Quien lee el
código no sabe si el valor de la línea 3 sigue siendo el de la línea 40
sin revisar todo lo que hay en medio.

Rust invierte el default: una variable no se puede reasignar salvo que se
pida con `mut`. Si un valor no cambia, nadie lo modifica sin que se note.
Cuando sí debe cambiar, la declaración lo anuncia desde su primera línea.

## Definiciones y reglas

Binding
:   *(binding)*: la unión entre un nombre y un valor que crea cada `let`.
    Ligar es crear esa unión. «Variable» y «binding» se usan como sinónimos.

Inmutable
:   un binding que no admite otra asignación después de la primera. Es el
    default de `let`.

Shadowing
:   declarar con `let` un nombre que ya existe. Se crea un binding nuevo que
    oculta al anterior.

Scope
:   *(scope)*: la región del código donde un nombre es válido. Para un
    binding, va de su `let` a la llave que cierra su bloque.

::: {.reglas titulo="Las tres reglas de un binding"}
1. Un binding no se puede reasignar salvo que se declare con `mut`.
2. `mut` permite cambiar el valor, nunca el tipo.
3. Un binding existe desde su `let` hasta el final de su bloque.
:::

## De un vistazo

Hay cinco formas de dar nombre a un valor. Se distinguen por lo que permiten
cambiar y por dónde viven.

| Forma | ¿Reasigna? | ¿Otro tipo? | Tipo escrito | Vive |
| :--- | :--- | :--- | :--- | :--- |
| `let x = 5;` | no | no | opcional | su bloque |
| `let mut x = 5;` | sí | no | opcional | su bloque |
| `let x = x + 1;` | crea otro | sí | opcional | su bloque |
| `const N: u32 = 5;` | no | no | obligatorio | cada uso |
| `static N: u32 = 5;` | no | no | obligatorio | todo el programa |

Criterio: `let` por default; `mut` cuando el valor cambia de verdad;
shadowing para transformar un valor por etapas; `const` para un valor fijo
del programa.

## Las reglas, una por una

Primero la declaración con `let`; después, cada regla y las dos formas que
no son variables.

### `let`: ligar un nombre a un valor

`let` liga un nombre a un valor. El tipo se puede escribir después del
nombre, con dos puntos, o dejar que el compilador lo infiera:

```rust
fn main() {
    let edad = 31;           // inferido: i32
    let altura: f64 = 1.72;  // anotado
    let inicial = 'A';       // inferido: char
    println!("{edad} {altura} {inicial}");
}
```

La inferencia usa las reglas de [1.2 Tipos escalares]{.ref}: un entero sin
más datos es `i32` y un decimal es `f64`. La anotación hace falta cuando el
valor no basta para decidir, o cuando se quiere otro tipo, como `u8`.

### [Regla 1:]{.prefijo} inmutable por default

Un binding sin `mut` recibe su valor una vez. Una segunda asignación no
compila:

```rust,compile_fail
fn main() {
    let x = 5;
    println!("x vale {x}");
    x = 6;
    println!("x vale {x}");
}
```

```salida
error[E0384]: cannot assign twice to immutable variable `x`
2 |     let x = 5;
  |         - first assignment to `x`
3 |     println!("x vale {x}");
4 |     x = 6;
  |     ^^^^^ cannot assign twice to immutable variable
help: consider making this binding mutable
2 |     let mut x = 5;
  |         +++
```

El error señala las dos asignaciones. El `help:` propone además el arreglo
exacto: los `+++` marcan lo que hay que agregar y dónde. Muchos errores de
`rustc` traen una sugerencia así, y conviene leerla antes de cambiar nada.

La razón del default es práctica. Si `x` es inmutable, su valor en la
línea 5 es el de la línea 2, sin revisar nada en medio. Esa garantía es la
base de las reglas de préstamo de [3.3 Borrowing]{.ref}.

### `mut` y los operadores compuestos

Con `mut` el binding admite asignaciones nuevas. Los operadores compuestos
`+=`, `-=`, `*=`, `/=` y `%=` combinan la operación con la asignación:

```rust
fn main() {
    let mut vidas = 3;
    vidas -= 1;   // vidas = vidas - 1
    vidas += 5;   // vidas = vidas + 5
    vidas *= 2;   // vidas = vidas * 2
    println!("vidas: {vidas}"); // vidas: 14
}
```

`mut` pertenece al binding, no al valor ni al tipo. El tipo de `vidas` es
`i32` con o sin `mut`. Lo que cambia es si ese nombre admite otra
asignación. La distinción vuelve en [3.3 Borrowing]{.ref}, donde `&mut` sí
es parte del tipo.

### [Regla 2:]{.prefijo} `mut` cambia el valor, no el tipo

Una variable mutable recibe valores nuevos, pero todos del tipo con que se
declaró. Aquí `espacios` empieza como texto y se intenta guardar en ella
un número. `.len()` da la longitud de un texto en bytes:

```rust,compile_fail
fn main() {
    let mut espacios = "    ";
    espacios = espacios.len();
    println!("{espacios}");
}
```

```salida
error[E0308]: mismatched types
2 |     let mut espacios = "    ";
  |                        ------ expected due to this value
3 |     espacios = espacios.len();
  |                ^^^^^^^^^^^^^^ expected `&str`,
  |                               found `usize`
```

El tipo quedó fijo en la primera línea: `&str`, el de un literal de texto.
`.len()` devuelve un `usize`, y un binding no cambia de tipo.

### Shadowing: un binding nuevo con el mismo nombre

El mismo cambio compila si cada paso usa su propio `let`:

```rust
fn main() {
    let espacios = "    ";          // &str
    let espacios = espacios.len();  // usize
    println!("{espacios}");         // 4
}
```

El segundo `let` no reasigna nada. Crea un binding nuevo, de tipo `usize`,
que oculta al primero. Desde esa línea, el nombre `espacios` se refiere al
nuevo. El primero sigue existiendo, pero ya no hay forma de nombrarlo.

La diferencia se ve mejor con el mismo cálculo escrito de las dos formas.
Con `mut`, la línea `x = x * 2;` modifica la única variable. Con shadowing,
`let x = x * 2;` crea una segunda, y esa también queda inmutable:

::: {.figura src="figuras/1.3-mut-sombra.html"}
:::

El shadowing sirve para transformar un valor por etapas sin inventar
nombres como `texto`, `texto_limpio` y `texto_num`. Cada etapa queda
inmutable, y la anterior ya no se puede usar por error.

| | `mut` | shadowing |
| :--- | :--- | :--- |
| Variable | la misma | una nueva en cada `let` |
| Tipo | fijo | puede cambiar |
| Binding resultante | mutable | inmutable, salvo que se pida `mut` |
| Al cerrar un bloque | conserva el último valor | vuelve el binding anterior |

La última fila depende de la regla 3.

### [Regla 3:]{.prefijo} el scope de un bloque

Un par de llaves abre un bloque. Un binding creado dentro existe desde su
`let` hasta la llave que cierra. Fuera de ella, el nombre no existe:

```rust,compile_fail
fn main() {
    {
        let dentro = 10;
        println!("{dentro}");
    }
    println!("{dentro}");
}
```

```salida
error[E0425]: cannot find value `dentro` in this scope
6 |     println!("{dentro}");
  |                ^^^^^^
help: the binding `dentro` is available in a different
      scope in the same function
3 |         let dentro = 10;
  |             ^^^^^^
```

El `help:` encuentra el binding en otro scope de la misma función. No lo
ofrece como arreglo: solo explica por qué el nombre no se ve.

Una sombra creada dentro de un bloque también termina en su llave. Al
salir, el nombre vuelve a referirse al binding de afuera, que nunca cambió:

```rust
fn main() {
    let x = 5;
    {
        let x = x * 2;    // sombra local
        println!("{x}");  // 10
    }
    println!("{x}");      // 5: la sombra murió con el bloque
}
```

Con `mut` el resultado sería otro. Si afuera hubiera `let mut x = 5;` y
dentro `x = x * 2;`, la asignación cambiaría la única `x`, y el segundo
`println!` imprimiría 10.

### `const` y `static`

Las dos dan nombre a un valor fijo, y ninguna es una variable. Se pueden
declarar fuera de `main`, exigen el tipo escrito y su valor tiene que poder
calcularse al compilar. Por convención se escriben en mayúsculas, con
guiones bajos:

```rust
const MAX_INTENTOS: u32 = 3;
const SEGUNDOS_POR_DIA: u32 = 24 * 60 * 60;
static SALUDO: &str = "hola";

fn main() {
    println!("{SALUDO}: {MAX_INTENTOS} intentos");
    println!("un día tiene {SEGUNDOS_POR_DIA} s");
}
```

Sin el tipo, `const LIMITE = 100;` no compila: `rustc` responde
`` missing type for `const` item `` y sugiere `: i32`. Tampoco se admite un
valor que solo existe al ejecutar. Con un `let base = 10;` previo,
`const DOBLE: i32 = base * 2;` da E0435: *attempt to use a non-constant
value in a constant*.

La diferencia entre las dos está en la memoria. Una `const` no ocupa un
lugar propio: el compilador escribe su valor en cada sitio donde se usa,
como si fuera un literal. Una `static` ocupa un solo lugar durante toda la
ejecución, y cada uso lee de esa misma dirección. `SALUDO` guarda una
referencia a texto, `&str`, el tipo de los literales que adelanta
[1.2 Tipos escalares]{.ref}.

Regla práctica: `const` por default; `static` solo cuando importa que el
valor tenga una dirección única.

### Los avisos: `mut` innecesario y bindings sin usar

Un `mut` que nunca se aprovecha y un binding que nunca se lee no son
errores. El programa compila, pero `rustc` avisa:

```rust
fn main() {
    let mut total = 10;
    let descuento = 3;
    println!("{total}");
}
```

```salida
warning: variable does not need to be mutable
2 |     let mut total = 10;
  |         ----^^^^^
  |         |
  |         help: remove this `mut`
warning: unused variable: `descuento`
3 |     let descuento = 3;
  |         ^^^^^^^^^ help: if this is intentional, prefix it
  |                   with an underscore: `_descuento`
```

El primer aviso protege la regla 1: un `mut` de sobra anuncia cambios que no
ocurren. El segundo suele señalar un olvido. Si el binding sin usar es
intencional, el prefijo `_` lo declara así: `let _descuento = 3;` compila
sin aviso.

## Aplicación

Un viaje tiene tres tramos y un coche que rinde 12.5 km por litro. El
programa suma los tramos en una variable mutable, la congela con shadowing
y la convierte a `f64` para dividir:

```rust
const RENDIMIENTO_KM_L: f64 = 12.5;
static UNIDAD: &str = "litros";

fn main() {
    let mut km = 0;
    km += 120;   // tramo 1
    km += 85;    // tramo 2
    km += 45;    // tramo 3

    let km = km as f64;   // 250.0: ahora f64 e inmutable
    let litros = km / RENDIMIENTO_KM_L;
    println!("{km} km: {litros} {UNIDAD}");
    // 250 km: 20 litros
}
```

`km` empieza mutable porque acumula. El segundo `let km` hace dos cosas a la
vez: cambia el tipo a `f64` con `as` ([1.2 Tipos escalares]{.ref}) y deja el
binding inmutable. Después de esa línea, ningún `+=` puede alterar la
distancia por error. El rendimiento es una `const` porque no cambia entre
ejecuciones.

## A fondo

**`let x = x;` congela una variable mutable.** Un binding mutable que ya
terminó de cambiar se puede volver a ligar sin `mut`. El valor es el mismo;
el nombre deja de admitir asignaciones.

**Un binding se puede declarar sin valor.** `let x: i32;` reserva el nombre,
y la asignación llega después. Mientras no haya una, el compilador rechaza
leerlo con E0381. Una sola asignación posterior no necesita `mut`: la regla 1
prohíbe la segunda, no la primera.

**El shadowing no libera al binding oculto.** El valor oculto sigue en
memoria hasta el final de su bloque, aunque ya no tenga nombre. Cuándo se
libera cada valor lo explica [3.2 Ownership]{.ref}.

**Un `static` también puede ser mutable, pero con `unsafe`.** `static mut`
existe, y leerlo o escribirlo exige un bloque `unsafe`, porque dos hilos
podrían tocarlo a la vez. Las alternativas seguras están en
[8.3 Estado compartido]{.ref}.
