# 4.5 · Operadores y conversiones

Sumar dos puntos se escribe `a + b` en matemáticas. Con un `struct Punto`
recién definido, esa línea no compila: `+` funciona con `i32` y con `f64`,
pero no con un tipo propio.

El error no dice que el operador esté prohibido. Dice que falta implementar
un trait, `Add`. Los operadores `+`, `==`, `[]` y `*` no están reservados
para los tipos del lenguaje: cada uno es un método de un trait de `std::ops`
o `std::cmp`, y cualquier tipo puede implementarlo.

## Definiciones y reglas

Sobrecarga de operadores
:   implementar, para un tipo propio, el trait que corresponde a un
    operador.

`Output`
:   tipo asociado ([4.2 Generics]{.ref}) con el que el trait de un operador
    declara el tipo de su resultado.

Coerción de deref
:   *(deref coercion)*: conversión de `&T` a `&U` que el compilador
    inserta cuando `T` implementa `Deref<Target = U>`.

::: {.reglas titulo="Las tres reglas de los operadores"}
1. Un operador es la llamada a un método de un trait: `a + b` es
   `Add::add(a, b)`.
2. Los operadores aritméticos reciben sus operandos por valor: los mueven,
   salvo que el tipo sea `Copy`.
3. Si `T` implementa `Deref`, un `&T` se convierte solo a `&Target` en los
   argumentos de una función y antes del punto de un método.
:::

## De un vistazo

| Escrito | Trait | Método | Recibe |
| :--- | :--- | :--- | :--- |
| `a + b` | `Add` | `add` | `a` y `b` por valor |
| `a - b`, `a * b`, `a / b` | `Sub`, `Mul`, `Div` | `sub`, `mul`, `div` | igual que `Add` |
| `-a` | `Neg` | `neg` | `a` por valor |
| `a += b` | `AddAssign` | `add_assign` | `&mut a`, y `b` por valor |
| `a[i]` | `Index`, `IndexMut` | `index`, `index_mut` | `&a` o `&mut a` |
| `a == b` | `PartialEq` | `eq` | `&a` y `&b` |
| `a < b` | `PartialOrd` | `partial_cmp` | `&a` y `&b` |
| `*a` | `Deref` | `deref` | `&a` |

Los traits aritméticos, los de índice y `Deref` están en `std::ops`. Los dos
de comparación están en `std::cmp` y casi siempre se derivan
([4.4 Traits de la stdlib]{.ref}).

Criterio: un operador se sobrecarga cuando su significado es el que
cualquiera esperaría del símbolo. Si hay que explicarlo, va un método con
nombre.

## Las reglas, una por una

### El error ya nombra el trait

```rust,compile_fail
struct Punto {
    x: i32,
    y: i32,
}

fn main() {
    let a = Punto { x: 1, y: 2 };
    let b = Punto { x: 10, y: 20 };
    let c = a + b;
}
```

```salida
error[E0369]: cannot add `Punto` to `Punto`
9 |     let c = a + b;
  |             - ^ - Punto
  |             |
  |             Punto
note: an implementation of `Add` might be missing for `Punto`
1 | struct Punto {
  | ^^^^^^^^^^^^ must implement `Add`
```

El compilador buscó una implementación de `Add` para `Punto` y no la
encontró. Con `i32` la misma línea compila porque la stdlib trae
`impl Add for i32`.

### [Regla 1:]{.prefijo} un operador es un método de un trait

`Add` pide dos cosas: el tipo del resultado, en el tipo asociado `Output`, y
el método `add`.

```rust
use std::ops::Add;

#[derive(Debug, Clone, Copy)]
struct Punto { x: i32, y: i32 }

impl Add for Punto {
    type Output = Punto;
    fn add(self, otro: Punto) -> Punto {
        Punto { x: self.x + otro.x, y: self.y + otro.y }
    }
}

fn main() {
    let a = Punto { x: 1, y: 2 };
    let b = Punto { x: 10, y: 20 };
    let c = a + b;            // Punto { x: 11, y: 22 }
    let d = Add::add(a, b);   // la misma llamada
    println!("{c:?} {d:?}");
}
```

Las líneas de `c` y de `d` hacen lo mismo. El compilador traduce `a + b` a
`Add::add(a, b)`: el operando izquierdo pasa como `self` y el derecho como
segundo argumento. No hay otra maquinaria detrás del símbolo.

### [Regla 2:]{.prefijo} los operandos se pasan por valor

La firma es `fn add(self, otro: Punto)`, sin `&`. Por [3.2 Ownership]{.ref},
pasar un valor a una función lo mueve. El `Punto` anterior deriva `Copy`, y
por eso `a` y `b` sirvieron dos veces. Sin ese `derive`, la suma los
consume.

```rust,compile_fail
use std::ops::Add;

#[derive(Debug)]
struct Punto { x: i32, y: i32 }

impl Add for Punto {
    type Output = Punto;
    fn add(self, otro: Punto) -> Punto {
        Punto { x: self.x + otro.x, y: self.y + otro.y }
    }
}

fn main() {
    let a = Punto { x: 1, y: 2 };
    let b = Punto { x: 10, y: 20 };
    let c = a + b;
    println!("{a:?} {c:?}");
}
```

```salida
error[E0382]: borrow of moved value: `a`
14 |     let a = Punto { x: 1, y: 2 };
   |         - move occurs because `a` has type `Punto`,
   |           which does not implement the `Copy` trait
15 |     let b = Punto { x: 10, y: 20 };
16 |     let c = a + b;
   |             ----- `a` moved due to usage in operator
17 |     println!("{a:?} {c:?}");
   |                ^ value borrowed here after move
```

El mensaje completo agrega una nota, *calling this operator moves the
left-hand side*, y cita la firma de `Add` en la stdlib. Con `b` pasa lo
mismo: usarla después de la suma da otro E0382.

Hay dos salidas. La primera es derivar `Copy`, que sirve cuando todos los
campos son `Copy`. La segunda es implementar el operador sobre referencias:
`impl Add for &Punto`, con `fn add(self, otro: &Punto) -> Punto`. Ahí `self`
es un `&Punto`, la suma se escribe `&a + &b` y no mueve nada. Es la salida
que queda cuando el tipo guarda un `String` o cuando copiarlo es caro.

`String` usa una tercera combinación. Su `impl` en la stdlib tiene esta
forma:

```text
impl Add<&str> for String {
    type Output = String;
    fn add(self, other: &str) -> String
}
```

El operando izquierdo es un `String` por valor y el derecho un `&str`. Es
lo que [3.4 Strings]{.ref} mostró sin explicar: en `hola + &mundo`, `hola`
entra como `self` y queda movida, y `mundo` solo se presta. El `<&str>` dice
que el operando derecho es de otro tipo; el detalle está en «A fondo».

### `Index`: el índice puede ser de cualquier tipo

El trait `Index` es genérico sobre el tipo del índice, así que `a[i]` no
exige un entero. Una matriz que guarda sus celdas en un `[[i32; 3]; 2]`
puede recibir la fila y la columna juntas, en una tupla:

```rust
use std::ops::Index;

struct Matriz {
    celdas: [[i32; 3]; 2],   // 2 filas, 3 columnas
}

impl Index<(usize, usize)> for Matriz {
    type Output = i32;
    fn index(&self, (f, c): (usize, usize)) -> &i32 {
        &self.celdas[f][c]
    }
}

fn main() {
    let m = Matriz { celdas: [[1, 2, 3], [4, 5, 6]] };
    println!("{}", m[(1, 2)]);   // 6
}
```

`index` devuelve una referencia al elemento, no una copia, y cubre solo la
lectura. Asignar con `m[(0, 0)] = 10` pide además `IndexMut`.

### [Regla 3:]{.prefijo} `Deref` convierte referencias sin que se pida

`Deref` define qué entrega el operador `*` sobre un tipo propio. Sirve para
los tipos que envuelven a otro, como el newtype de
[4.4 Traits de la stdlib]{.ref}. Un `Etiqueta(String)` es un tipo distinto
de `String` y, sin más, no tiene ninguno de sus métodos.

```rust
use std::ops::Deref;

struct Etiqueta(String);

impl Deref for Etiqueta {
    type Target = String;
    fn deref(&self) -> &String {
        &self.0
    }
}

fn imprimir(s: &str) {
    println!("{s}");
}

fn main() {
    let etiqueta = Etiqueta(String::from("frágil"));
    println!("{}", etiqueta.len());          // 7, de String
    println!("{}", etiqueta.to_uppercase()); // FRÁGIL, de str
    imprimir(&etiqueta);                     // frágil
    let texto: &str = &etiqueta;             // también aquí
    println!("{texto}");
}
```

Ninguna de esas líneas escribe un `*`. El compilador ve que el tipo no
coincide con el que se espera, encuentra un `Deref` y lo aplica. Si el
resultado tampoco coincide, lo intenta de nuevo sobre el tipo nuevo.

::: {.figura src="figuras/4.5-coercion.html"}
:::

El segundo paso de la figura no depende de `Etiqueta`: `String` implementa
`Deref` con `Target = str`. Es la razón por la que en [3.4 Strings]{.ref}
un `&String` se aceptó donde se pedía un `&str`.

La coerción ocurre donde el compilador ya sabe qué tipo espera: en los
argumentos de una función, antes del punto de una llamada a método y en un
`let` con el tipo anotado. Fuera de ahí no ocurre:

| Escrito | Resultado |
| :--- | :--- |
| `imprimir(&etiqueta)` | compila: es un argumento |
| `etiqueta.len()` | compila: es el receptor del método |
| `let s: String = etiqueta;` | E0308: solo convierte referencias |
| `println!("{}", etiqueta)` | E0277: falta `Display`; con `*etiqueta` compila |
| `etiqueta == String::from("x")` | E0369: un operador no dispara la coerción |

::: {.advertencia titulo="Deref no es herencia"}
`Deref` se reserva para los tipos que envuelven a otro y se comportan como
él. Usarlo para que un struct tome prestados los métodos de uno de sus
campos compila, pero el lector encuentra llamadas a métodos que el tipo no
declara en ningún lado.
:::

### Tres vías de conversión

Con esta, el libro ya mostró tres formas de pasar de un tipo a otro. De las
tres, la coerción de deref es la única que no se escribe.

| Vía | Entre qué tipos | Cómo se pide | Capítulo |
| :--- | :--- | :--- | :--- |
| `as` | escalares | `x as u8` | [1.2 Tipos escalares]{.ref} |
| `From` e `Into` | cualesquiera, si hay un `impl` | `T::from(x)`, `x.into()` | [4.4 Traits de la stdlib]{.ref} |
| `Deref` | de `&T` a `&Target` | no se pide | este |

## Aplicación

Un tipo para dinero, guardado en centavos para no arrastrar los errores de
redondeo de `f64`. Su aritmética es la que cualquiera espera: los montos se
suman, cambian de signo y se acumulan.

```rust
use std::ops::{Add, AddAssign, Neg};

#[derive(Debug, Clone, Copy)]
struct Dinero(i64);   // en centavos

impl Add for Dinero {
    type Output = Dinero;
    fn add(self, otro: Dinero) -> Dinero {
        Dinero(self.0 + otro.0)
    }
}

impl Neg for Dinero {
    type Output = Dinero;
    fn neg(self) -> Dinero {
        Dinero(-self.0)
    }
}

impl AddAssign for Dinero {
    fn add_assign(&mut self, otro: Dinero) {
        self.0 += otro.0;
    }
}

fn main() {
    let precio = Dinero(13_500);
    let envio = Dinero(9_900);
    let descuento = Dinero(2_000);
    let mut total = precio + envio + -descuento;
    println!("{total:?}");    // Dinero(21400)
    total += Dinero(1_000);   // propina
    println!("{total:?}");    // Dinero(22400)
    println!("{precio:?}");   // Dinero(13500): es Copy
}
```

La expresión de `total` respeta la precedencia de siempre: primero el `-`
unario, luego las sumas. Implementar el trait le da significado al
operador, pero no cambia su lugar en la expresión. `AddAssign` no tiene
`Output` porque no devuelve nada: modifica a `self` a través de
`&mut self`. `Dinero * Dinero` no compila porque nadie implementó `Mul`, y
está bien: pesos al cuadrado no es un monto.

## A fondo

**El operando derecho puede ser de otro tipo.** `Add` se declara como
`trait Add<Rhs = Self>`: un parámetro genérico con valor por default.
`impl Add for Punto` usa el default y suma `Punto` con `Punto`. El
`impl Add<&str> for String` de la stdlib lo cambia. Con
`impl Mul<i64> for Dinero` compilaría `precio * 3`, pero no `3 * precio`:
ese busca `impl Mul<Dinero> for i64`, que es otro `impl`.

**Comparar e indexar no consumen.** `a == b` se traduce a
`PartialEq::eq(&a, &b)`, y `a[i]` a `*Index::index(&a, i)`. El compilador
pone los `&`, así que los operandos siguen disponibles aunque el tipo no
sea `Copy`. Dos `String` se comparan con `==` y los dos siguen vivos.

**`DerefMut` es el par mutable.** Con solo `Deref`, `Etiqueta` recibe los
métodos que piden `&self`. Llamar a `etiqueta.push_str("!")` da E0596:
*cannot borrow data in dereference of `Etiqueta` as mutable*. Hace falta
implementar además `DerefMut`.

**Los punteros inteligentes son `Deref` aplicado.** `Box<T>` implementa
`Deref<Target = T>`, y por eso responde a los métodos de lo que guarda. Es
el tema de [6.1 Box y listas enlazadas]{.ref}.
