# 4.3 · Closures

Una función `fn` solo ve sus parámetros. Si necesita un dato del lugar
donde se escribió, hay que pasárselo en cada llamada. Eso estorba cuando
la función se entrega a otra: quien la llama no conoce ese dato ni tiene
por qué conocerlo.

Una *closure* es una función anónima que puede usar las variables del
lugar donde se escribió. Para usarlas tiene que guardarlas, y guardar un
valor es prestarlo o moverlo. Por eso el capítulo descansa en
[3.3 Borrowing]{.ref}: una closure obedece las mismas reglas de préstamo
que cualquier otro código.

## Definiciones y reglas

Closure
:   función anónima escrita como expresión. Los parámetros van entre
    barras verticales: `|x| x + 1`. El libro la trata en femenino: una
    closure.

Capturar
:   usar dentro de la closure una variable del scope donde se escribió.
    La closure guarda una referencia a la variable, o la variable misma.

`Fn`, `FnMut`, `FnOnce`
:   los tres traits de las closures. El compilador los implementa según
    lo que el cuerpo hace con lo capturado.

`move`
:   palabra que, antes de las barras, obliga a capturar por valor.

::: {.reglas titulo="Las tres reglas de las closures"}
1. Cada variable se captura de la forma menos invasiva que el cuerpo
   permita: `&T` si solo la lee, `&mut T` si la modifica, `T` si la
   consume.
2. Lo que la closure hace con lo capturado decide su trait: `Fn` si lee,
   `FnMut` si modifica, `FnOnce` si consume.
3. Una closure que sale del scope donde nació necesita `move`: tiene que
   ser dueña de lo que captura.
:::

## De un vistazo

| Trait | Qué hace con lo capturado | Captura | Se puede llamar |
| :--- | :--- | :--- | :--- |
| `Fn` | solo lo lee | `&T` | muchas veces |
| `FnMut` | lo modifica | `&mut T` | muchas veces, si el binding es `mut` |
| `FnOnce` | lo consume | `T` | una sola vez |

Todo `Fn` es también `FnMut` y `FnOnce`, y todo `FnMut` es también
`FnOnce`. Criterio para una función que recibe una closure: pedir `FnOnce`
si la llama una vez, `FnMut` si la llama varias, y `Fn` solo si necesita
que no cambie nada.

## Las reglas, una por una

Antes de las reglas, lo que distingue a una closure de una `fn`.

### Lo que una `fn` no puede hacer

Rust permite declarar una `fn` dentro de otra. Aun así, la de adentro no
ve las variables locales de la de afuera:

```rust,compile_fail
fn main() {
    let factor = 3;

    fn triple(n: i32) -> i32 {
        n * factor
    }

    println!("{}", triple(5));
}
```

```salida
error[E0434]: can't capture dynamic environment in a fn item
5 |         n * factor
  |             ^^^^^^
  = help: use the `|| { ... }` closure form instead
```

El mensaje nombra la operación que falta, capturar, y la forma que sí la
tiene. Con una closure el programa compila:

```rust
fn main() {
    let factor = 3;
    let triple = |n: i32| n * factor;   // captura factor

    println!("{}", triple(5));          // 15
}
```

### De `fn` a closure, en cuatro pasos

La sintaxis de una closure es la de una `fn` a la que se le quita lo que
el compilador puede deducir. Las cuatro formas hacen lo mismo:

```rust
fn main() {
    fn suma_uno(x: i32) -> i32 { x + 1 }

    let a = |x: i32| -> i32 { x + 1 };   // barras, sin nombre
    let b = |x| { x + 1 };               // sin tipos
    let c = |x| x + 1;                   // sin llaves

    println!("{}", suma_uno(1) + a(1) + b(1) + c(1));   // 8
}
```

Las llaves sobran cuando el cuerpo es una sola expresión. Los tipos sobran
porque una closure se usa cerca de donde se escribe, y el compilador los
deduce de ese uso. Una `fn` es una interfaz pública y por eso los exige.

### Los tipos se fijan en el primer uso

Deducir los tipos no vuelve genérica a la closure. La primera llamada los
fija, y las siguientes tienen que coincidir:

```rust,compile_fail
fn main() {
    let identidad = |x| x;
    let texto = identidad(String::from("hola"));
    let numero = identidad(5);
}
```

```salida
error[E0308]: mismatched types
4 |     let numero = identidad(5);
  |                  --------- ^ expected `String`,
  |                  |           found integer
  |                  arguments to this function are incorrect
note: expected because the closure was earlier called
      with an argument of type `String`
3 |     let texto = identidad(String::from("hola"));
  |                 --------- ^^^^^^^^^^^^^^^^^^^^
```

Después de la línea 3, `identidad` recibe un `String` y devuelve un
`String`. Para aceptar varios tipos hace falta una `fn` genérica
([4.2 Generics]{.ref}).

### [Regla 1:]{.prefijo} la captura menos invasiva

El compilador lee el cuerpo de la closure y decide, variable por variable,
cuánto necesita de ella. No se escribe en ningún lado:

::: {.figura src="figuras/4.3-captura.html"}
:::

```rust
fn main() {
    let saludo = String::from("hola");
    let mut cuenta = 0;
    let nombre = String::from("Ferris");

    let medir = || saludo.len();            // lee
    let mut incrementar = || cuenta += 1;   // modifica
    let entregar = || nombre;               // consume

    println!("{}", medir());      // 4
    incrementar();
    incrementar();
    println!("{}", entregar());   // Ferris
    println!("{saludo} {cuenta}");   // hola 2
}
```

`entregar` devuelve el `String` capturado. Para devolverlo tiene que ser
su dueña, así que `nombre` se movió a la closure y ya no se puede usar en
`main`. `saludo` y `cuenta` solo estaban prestadas.

El binding de `incrementar` lleva `mut` porque llamarla modifica lo que
guarda. Sin él, el compilador da E0596: *calling `incrementar` requires
mutable binding due to mutable borrow of `cuenta`*.

Los préstamos de una closure duran lo mismo que los de [3.3
Borrowing]{.ref}: hasta el último uso, que aquí es la última llamada.
Mientras `incrementar` siga en uso, sostiene un préstamo exclusivo de
`cuenta` y nadie más puede leerla:

```rust,compile_fail
fn main() {
    let mut cuenta = 0;
    let mut incrementar = || cuenta += 1;

    incrementar();
    println!("{cuenta}");
    incrementar();
}
```

```salida
error[E0502]: cannot borrow `cuenta` as immutable
              because it is also borrowed as mutable
3 |     let mut incrementar = || cuenta += 1;
  |                           -- ------ first borrow occurs
  |                           |         due to use of `cuenta`
  |                           |         in closure
  |                           mutable borrow occurs here
6 |     println!("{cuenta}");
  |                ^^^^^^ immutable borrow occurs here
7 |     incrementar();
  |     ----------- mutable borrow later used here
```

El préstamo empieza donde se escribe la closure, en la línea 3, no en la
primera llamada. El arreglo es el de siempre: mover el `println!` después
de la última llamada.

### [Regla 2:]{.prefijo} el uso decide el trait

`medir` solo lee, y es `Fn`. `incrementar` modifica, y es `FnMut`.
`entregar` consume lo que capturó, y solo es `FnOnce`: una segunda llamada
ya no tendría qué entregar. Escribir `entregar()` dos veces da E0382, *use
of moved value: `entregar`*, con dos notas. La primera dice la causa:
*closure cannot be invoked more than once because it moves the variable
`nombre` out of its environment*. La segunda dice el trait: *this value
implements `FnOnce`, which causes it to be moved when called*.

Cada closure tiene un tipo propio y anónimo, que no se puede escribir.
Una función que recibe una closure pide entonces «cualquier tipo que
implemente `Fn(i32) -> i32`», con un bound de [4.2 Generics]{.ref}:

```rust
fn aplicar<F: Fn(i32) -> i32>(f: F, x: i32) -> i32 {
    f(x)
}

fn doble(n: i32) -> i32 { n * 2 }

fn main() {
    let factor = 3;
    println!("{}", aplicar(|n| n * factor, 5));   // 15
    println!("{}", aplicar(doble, 5));            // 10
}
```

Entre los paréntesis del trait van los tipos de los parámetros, y después
de la flecha, el de retorno. Una `fn` normal también implementa `Fn`, así
que `doble` se pasa por su nombre. La firma tiene una forma más corta y
equivalente: `fn aplicar(f: impl Fn(i32) -> i32, x: i32) -> i32`.

El trait pedido decide qué closures entran. `FnOnce` las acepta todas:

```rust
fn una_vez(f: impl FnOnce()) {
    f();
}

fn main() {
    let saludo = String::from("hola");
    let mut cuenta = 0;
    una_vez(|| println!("{saludo}"));   // una Fn
    una_vez(|| cuenta += 1);            // una FnMut
    println!("{cuenta}");               // 1
}
```

`Fn` es el más exigente. Una función `leer(f: impl Fn())` rechaza
`|| cuenta += 1` con E0594: *cannot assign to `cuenta`, as it is a
captured variable in a `Fn` closure*. Y una función que llama varias
veces a una `FnMut` declara el parámetro con `mut`, igual que el binding
de `incrementar`: `fn repetir(mut f: impl FnMut())`.

### [Regla 3:]{.prefijo} `move` para salir del scope

Una función puede fabricar closures y devolverlas. El tipo de retorno
`impl Fn(i32) -> i32` es de [4.2 Generics]{.ref}: «algún tipo que
implementa ese trait». Escrita sin más, la fábrica no compila:

```rust,compile_fail
fn multiplicador(factor: i32) -> impl Fn(i32) -> i32 {
    |n| n * factor
}

fn main() {
    let triple = multiplicador(3);
    println!("{}", triple(5));
}
```

```salida
error[E0373]: closure may outlive the current function,
              but it borrows `factor`, which is owned
              by the current function
2 |     |n| n * factor
  |     ^^^     ------ `factor` is borrowed here
  |     |
  |     may outlive borrowed value `factor`
help: to force the closure to take ownership of `factor`
      (and any other referenced variables),
      use the `move` keyword
2 |     move |n| n * factor
  |     ++++
```

La closure solo lee `factor`, así que por la regla 1 lo toma prestado.
Pero `factor` es un parámetro de `multiplicador` y desaparece cuando la
función termina. La closure devuelta guardaría una referencia a un valor
que ya no existe: es la regla 2 de [3.3 Borrowing]{.ref}. `move` cambia la
regla 1 y hace que la closure capture todo por valor, aunque solo lo lea:

```rust
fn multiplicador(factor: i32) -> impl Fn(i32) -> i32 {
    move |n| n * factor
}

fn main() {
    let doble = multiplicador(2);
    let triple = multiplicador(3);
    println!("{} {}", doble(5), triple(5));   // 10 15
}
```

`doble` y `triple` salen de la misma función y cada una guarda su propio
factor. `move` también es obligatorio al mandar una closure a otro hilo,
por la misma razón ([8.1 Hilos]{.ref}).

Fuera de una fábrica, `move` se nota en la variable original:

```rust
fn main() {
    let nombre = String::from("Ferris");
    let saludar = move || println!("hola, {nombre}");

    saludar();
    saludar();   // sigue siendo Fn: solo lee lo que guarda
}
```

Después de la línea 3, `nombre` ya no existe en `main`: usarla da el E0382
de [3.2 Ownership]{.ref}, con la anotación *value moved into closure
here*. Con un tipo `Copy`, como el `i32` de `multiplicador`, `move` copia
el valor y la variable original sigue disponible.

### Dónde aparecen

Una closure permite entregar un cálculo sin hacerlo. Quien la recibe
decide si la llama. `valor_o` recibe su respaldo ya calculado;
`valor_o_con` recibe cómo calcularlo:

```rust
fn costoso() -> i32 {
    println!("calculando...");
    42
}

fn valor_o(hay: bool, valor: i32, respaldo: i32) -> i32 {
    if hay { valor } else { respaldo }
}

fn valor_o_con(
    hay: bool,
    valor: i32,
    f: impl FnOnce() -> i32,
) -> i32 {
    if hay { valor } else { f() }
}

fn main() {
    let a = valor_o(true, 7, costoso());    // calculando...
    let b = valor_o_con(true, 7, costoso);  // no imprime nada
    println!("{a} {b}");                    // 7 7
}
```

Los argumentos se evalúan antes de la llamada, así que `costoso()` corre
aunque `valor_o` no use el resultado. A `valor_o_con` se le pasa la
función sin llamarla, y ahí nadie la llama. Una closure como
`|| costoso() + 1` se comporta igual: solo corre si alguien la invoca.

La biblioteca estándar usa las dos ideas. `unwrap_or` y `unwrap_or_else`
de [5.1 Option]{.ref} son este mismo par: el primero recibe un valor y el
segundo una closure. `sort_by_key` de [5.3 Vec]{.ref} recibe una closure
que dice por qué dato ordenar. Y los adaptadores de [5.6 Iteradores]{.ref}
(`map`, `filter`) reciben una closure cada uno.

## Aplicación

Una fábrica de validadores, ejercicio del curso *Aprende Rust*.
`crear_validador` devuelve una closure que dice si un texto tiene al menos
`minimo` caracteres. El largo se mide con `chars().count()`, que cuenta
caracteres y no bytes ([3.4 Strings]{.ref}).

```rust
fn crear_validador(minimo: usize) -> impl Fn(&str) -> bool {
    move |texto| texto.chars().count() >= minimo
}

fn main() {
    let contrasena_valida = crear_validador(8);
    let usuario_valido = crear_validador(3);

    println!("{}", contrasena_valida("ferris"));      // false
    println!("{}", contrasena_valida("cangrejo123")); // true
    println!("{}", usuario_valido("ana"));            // true
}
```

Las tres reglas están en la línea 2. La closure solo lee `minimo`: por la
regla 1 lo tomaría prestado, y por la regla 2 es `Fn`, que es lo que
promete la firma. Sale de la función donde nació, y la regla 3 exige el
`move`. Sin él, el error es el mismo E0373 de `multiplicador`. Cada
validador guarda su propio mínimo: 8 en uno, 3 en el otro.

## A fondo

**Una closure es un struct con lo capturado como campos.** El compilador
genera un tipo anónimo con un campo por cada variable capturada, y un
método que contiene el cuerpo. La closure de `multiplicador`, escrita a
mano, es `Multiplicador`. `size_of_val` mide en bytes el valor que
recibe, y da lo mismo para las dos:

```rust
struct Multiplicador { factor: i32 }

impl Multiplicador {
    fn llamar(&self, n: i32) -> i32 {
        n * self.factor
    }
}

fn main() {
    let factor = 3;
    let a_mano = Multiplicador { factor: 3 };
    let closure = move |n: i32| n * factor;

    println!("{} {}", a_mano.llamar(5), closure(5));  // 15 15
    println!("{}", std::mem::size_of_val(&a_mano));   // 4
    println!("{}", std::mem::size_of_val(&closure));  // 4
}
```

**Los tres traits son las tres formas de `self`.** El método de llamada
de `Fn` recibe `&self`, el de `FnMut` recibe `&mut self` y el de `FnOnce`
recibe `self`. La tabla de [3.5 impl y métodos]{.ref} explica entonces la
de este capítulo: con `&self` la closure sigue válida, con `&mut self`
exige un binding `mut`, y con `self` queda movida tras la llamada.

**El tamaño de una closure es el de lo que captura.** Capturar un `i32`
por referencia ocupa 8 bytes, lo que mide un puntero. Capturarlo con
`move` ocupa 4. Una closure que no captura nada ocupa 0 bytes.

**`move` decide la captura, no el trait.** Una closure con `move` que solo
lee lo que guarda sigue siendo `Fn`, como `saludar`. El trait depende de
lo que el cuerpo hace con sus campos, no de cómo llegaron ahí.

**Dos closures nunca tienen el mismo tipo.** Aunque el texto sea
idéntico, cada una es un struct distinto. Por eso una función no puede
devolver una closure u otra según un `if`: el compilador avisa que *no
two closures, even if identical, have the same type*. La salida es
`Box<dyn Fn>`, en [6.3 Despacho dinámico]{.ref}.
