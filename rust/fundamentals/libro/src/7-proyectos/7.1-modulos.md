# 7.1 · Módulos

Hasta la sección 6, cada programa del libro cabe en un archivo, y todos sus
nombres viven en el mismo espacio. Con cinco funciones no estorba. Con
quinientas, dos tipos quieren llamarse `Error` y dos funciones `area`. Además,
cualquier línea del programa puede escribir en cualquier campo de cualquier
struct.

El segundo problema cuesta más. Si una `Cuenta` guarda su saldo en un
campo, nada impide que una función lejana lo ponga en un valor imposible. Y si
mañana el saldo se guarda de otra forma, hay que corregir cada línea que lo
tocaba. Los módulos resuelven las dos cosas: separan los nombres y deciden qué
se ve desde fuera.

## Definiciones y reglas

Crate
:   la unidad que `rustc` compila de una vez: un programa o una biblioteca.
    Paquetes, `Cargo.toml` y dependencias están en [7.2 Crates y Cargo]{.ref}.

Módulo
:   un espacio de nombres dentro de un crate, con una frontera de privacidad.
    Se declara con `mod`.

Árbol de módulos
:   la jerarquía de módulos de un crate. Su raíz se llama `crate` y es el
    archivo `src/main.rs` (o `src/lib.rs` en una biblioteca).

Elemento
:   *(item)*: lo que se declara dentro de un módulo: una función, un struct,
    un enum, un trait, una constante, otro módulo.

Ruta
:   *(path)*: los nombres que llevan a un elemento, separados por `::`, como
    `std::collections::HashMap`.

::: {.reglas titulo="Las tres reglas de los módulos"}
1. Un módulo se declara una sola vez, con `mod`, dentro de su padre. `use` no
   declara nada: acorta una ruta.
2. Todo es privado por default. `pub` abre un elemento a quien ve a su módulo;
   en un struct, campo por campo.
3. Una ruta parte de la raíz (`crate::`), del padre (`super::`) o del módulo
   actual (`self::`, o sin prefijo).
:::

## De un vistazo

| Se escribe | Qué hace |
| :--- | :--- |
| `mod x { ... }` | declara el módulo `x` con su cuerpo en línea |
| `mod x;` | declara `x` y toma su cuerpo de `x.rs` o `x/mod.rs` |
| `pub fn`, `pub struct` | abre el elemento; un campo sin `pub` sigue privado |
| `pub enum` | abre el enum y todas sus variantes |
| `crate::a::b` | ruta absoluta, desde la raíz |
| `super::b`, `self::b` | ruta relativa: desde el padre o desde aquí |
| `use a::{b, c as d};` | trae `b` y `c` al scope; `c` se llama `d` |
| `pub use a::b;` | trae `b` y lo ofrece como si fuera propio |

Criterio: todo empieza privado, y se abre solo lo que quien usa el módulo
necesita.

## Las reglas, una por una

Antes de las reglas, el módulo como espacio de nombres.

### Un módulo separa nombres

Un `mod` con llaves declara un módulo en el mismo archivo. Lo de adentro se
nombra desde fuera con una ruta: el módulo, `::` y el elemento.

```rust
mod cuadrado {
    pub fn area(lado: f64) -> f64 {
        lado * lado
    }
}

mod circulo {
    pub fn area(radio: f64) -> f64 {
        std::f64::consts::PI * radio * radio
    }
}

fn main() {
    println!("{}", cuadrado::area(2.0));    // 4
    println!("{:.2}", circulo::area(1.0));  // 3.14
}
```

Las dos funciones se llaman `area` y no chocan: una es `cuadrado::area` y la
otra `circulo::area`. La constante `PI` también tiene ruta. La biblioteca
estándar es un crate, `std`, organizado en módulos: `f64` dentro de `std`, y
`consts` dentro de `f64`.

Los `pub` de este ejemplo son necesarios. Sin ellos, `main` no podría llamar a
ninguna de las dos funciones (regla 2).

### [Regla 1:]{.prefijo} `mod` declara, una sola vez

Cuando un módulo crece, su cuerpo pasa a un archivo propio. La declaración se
queda en el padre, sin llaves y con punto y coma. El compilador busca el cuerpo
en un archivo con el nombre del módulo. Este proyecto de Cargo tiene un módulo
`geometria` con dos hijos:

::: {.figura src="figuras/7.1-arbol.html"}
:::

Cada archivo abre con un comentario que dice su ruta. La raíz declara a
`geometria`:

```rust,ignore
// src/main.rs
mod geometria;   // el cuerpo está en geometria.rs

fn main() {
    let p = geometria::punto::Punto { x: 1.0, y: 2.0 };
    let c = geometria::circulo::Circulo::nuevo(p, 3.0);
    println!("área: {:.2}", c.area());   // área: 28.27
}
```

`geometria.rs` no contiene código propio. Solo declara a sus dos hijos, y como
tiene hijos, sus archivos van en una carpeta con su nombre:

```rust,ignore
// src/geometria.rs
pub mod circulo;   // en geometria/circulo.rs
pub mod punto;     // en geometria/punto.rs
```

```rust,ignore
// src/geometria/punto.rs
pub struct Punto {
    pub x: f64,
    pub y: f64,
}
```

`circulo.rs` usa a `Punto`, de un módulo vecino. Su primera línea es una
ruta relativa, que se explica en la regla 3:

```rust,ignore
// src/geometria/circulo.rs
use super::punto::Punto;   // = crate::geometria::punto::Punto

pub struct Circulo {
    pub centro: Punto,
    radio: f64,
}

impl Circulo {
    pub fn nuevo(centro: Punto, radio: f64) -> Self {
        Self { centro, radio: radio.abs() }
    }

    pub fn area(&self) -> f64 {
        std::f64::consts::PI * self.radio * self.radio
    }
}
```

`mod` no es un `import` de otros lenguajes. No trae nada de otro lado: agrega
un nodo al árbol, y por eso se escribe una sola vez, en el padre. Un archivo
que nadie declara no se compila; si se quita `mod geometria;` de `main.rs`,
la ruta `geometria::punto` da E0433 *use of unresolved module*. Declararlo de
nuevo en otro lugar crea otro módulo, que busca su propio archivo. Si
`main.rs` agrega `mod punto;` para llegar a `Punto`, Cargo responde:

```salida
error[E0583]: file not found for module `punto`
2 | mod punto;
  | ^^^^^^^^^^
  = note: if there is a `mod punto` elsewhere in the crate
          already, import it with `use crate::...` instead
```

La nota del compilador dice la regla: si el módulo ya existe, se llega a él
con una ruta, no con otro `mod`.

### [Regla 2:]{.prefijo} todo es privado por default

Sin `pub`, un elemento solo se ve en su módulo y en los que cuelgan de él:

```rust,compile_fail
mod termometro {
    pub fn leer() -> f64 {
        calibrar(20.0)
    }

    fn calibrar(crudo: f64) -> f64 {
        crudo + 0.5
    }
}

fn main() {
    let t = termometro::calibrar(3.0);
}
```

```salida
error[E0603]: function `calibrar` is private
12 |     let t = termometro::calibrar(3.0);
   |                         ^^^^^^^^ private function
```

El termómetro expone la lectura y guarda la calibración. `leer` sí puede
llamar a `calibrar`: está en el mismo módulo. `main` sí puede
nombrar a `termometro` aunque el módulo no sea `pub`, porque los dos viven en
la raíz. La frontera va en un solo sentido: un hijo ve lo privado de sus
ancestros, y un padre no ve lo privado de sus hijos. Como nada fuera de
`termometro` llama a `calibrar`, puede cambiar de firma o desaparecer sin
romper otro módulo.

Para llegar a un elemento, cada módulo del camino tiene que estar abierto:
si `rutas` no es `pub`, `api::rutas::salud()` da E0603 *module `rutas` is
private*, aunque `salud` sea `pub`.

### Structs: campo por campo

`pub struct` abre el tipo, no sus campos. Un campo privado y un constructor
protegen un invariante, una condición que todo valor del tipo cumple. En el
`Usuario` del curso, la edad nunca pasa de 150:

```rust,compile_fail
mod usuarios {
    pub struct Usuario {
        pub nombre: String,
        edad: u8,
    }

    impl Usuario {
        pub fn nuevo(nombre: &str, edad: u8) -> Self {
            Self {
                nombre: String::from(nombre),
                edad: edad.min(150),
            }
        }

        pub fn edad(&self) -> u8 {
            self.edad
        }
    }
}

fn main() {
    let ana = usuarios::Usuario::nuevo("Ana", 200);
    let eva = usuarios::Usuario {
        nombre: String::from("Eva"),
        edad: 200,
    };
}
```

```salida
error[E0451]: field `edad` of struct `Usuario` is private
23 |     let eva = usuarios::Usuario {
   |               ----------------- in this type
24 |         nombre: String::from("Eva"),
25 |         edad: 200,
   |         ^^^^ private field
```

`nuevo` es la función asociada de [3.5 impl y métodos]{.ref}; aquí además es
la única puerta. La línea de `ana` compila, y `ana.edad()` devuelve 150. La de
`eva` no: armar el struct con llaves desde fuera del módulo exige escribir un
campo que no se ve. Sin esa línea, el programa compila.

Leer o asignar el campo da otro error, E0616 *field `edad` of struct `Usuario`
is private*, y el compilador sugiere el método: *a method `edad` also exists,
call it with parentheses*. `ana.nombre` sí se lee y se asigna, porque es `pub`.

El campo privado también protege al código de fuera. Si `Usuario` pasa a
guardar el año de nacimiento en lugar de la edad, basta con cambiar `nuevo` y
`edad()`. Ninguna línea fuera de `usuarios` nombraba el campo.

### Enums: todas las variantes

Un enum funciona al revés. Un `pub enum` abre todas sus variantes, y no hay
forma de cerrar una. Un enum se usa con `match`, y un `match` desde fuera
necesita ver todas las variantes para ser exhaustivo.

```rust
mod pedidos {
    pub enum Estado {
        Pendiente,
        Enviado(u32),   // número de guía
    }
}

fn main() {
    let e = pedidos::Estado::Enviado(4521);
    match e {
        pedidos::Estado::Pendiente => println!("pendiente"),
        pedidos::Estado::Enviado(g) => println!("guía {g}"),
    }   // guía 4521
}
```

Escribir `pub` delante de una variante da E0449 *visibility qualifiers are not
permitted here*, con la nota *enum variants and their fields always share the
visibility of the enum they are in*.

### [Regla 3:]{.prefijo} rutas absolutas y relativas

Una ruta sin prefijo parte del módulo donde se escribe. Tres prefijos la hacen
partir de otro lugar:

| Prefijo | Parte de | Equivale a |
| :--- | :--- | :--- |
| `crate::` | la raíz del crate | una ruta absoluta |
| `super::` | el módulo padre | `..` en una carpeta |
| `self::` | el módulo actual | la ruta sin prefijo |
| `std::`, otro crate | ese crate | su raíz |

`super::` sirve para usar algo del padre. En este ejercicio del curso
*Aprende Rust*, `precios` lee la tasa del IVA de su padre, `tienda`:

```rust
mod tienda {
    const IVA: f64 = 0.16;   // privada de tienda
    pub mod precios {
        pub fn con_iva(precio: f64) -> f64 {
            precio * (1.0 + super::IVA)
        }
    }
}

fn main() {
    let p = tienda::precios::con_iva(19.99);
    println!("{p:.2}");   // 23.19
}
```

`IVA` no es `pub` y `precios` la ve igual, por la regla 2; `main` no podría
leer `tienda::IVA`.

En el proyecto de la figura, `circulo.rs` empieza con
`use super::punto::Punto;`. Para el compilador, `punto` es un hijo de
`geometria`, así que la ruta sube al padre y baja. La forma absoluta,
`crate::geometria::punto::Punto`, llega al mismo lugar. La ruta relativa no cambia si `geometria` se mueve a otra parte del árbol; la
absoluta no cambia si se mueve `circulo`. Las dos son válidas. `radio` es
privado por la misma razón que la edad de `Usuario`: `nuevo` garantiza que
nunca sea negativo.

### `use`: acortar rutas

Una ruta larga repetida estorba. `use` liga un nombre del scope actual con una
ruta, y desde ahí basta el nombre. Con llaves se traen varios nombres de un
mismo módulo, y con `as` se les cambia el nombre:

```rust
mod cuadrado { pub fn area(l: f64) -> f64 { l * l } }
mod circulo { pub fn area(r: f64) -> f64 { 3.14159 * r * r } }

use circulo::area as area_circulo;
use cuadrado::area;
use std::collections::{HashMap, HashSet};

fn main() {
    println!("{}", area(3.0));              // 9
    println!("{:.2}", area_circulo(1.0));   // 3.14
    let m: HashMap<u8, u8> = HashMap::new();
    let s: HashSet<u8> = HashSet::new();
    println!("{} {}", m.len(), s.len());   // 0 0
}
```

Sin el `as`, las dos líneas traerían el nombre `area` y el compilador las
rechazaría con E0252 *the name `area` is defined multiple times*. `use` no
crea ni copia nada: `area` sigue siendo `cuadrado::area`, con otro camino para
nombrarla. Por eso un `use` de un módulo que nadie declaró con `mod` falla: la
ruta no lleva a ningún lado.

### `pub use`: una API plana

Un `use` es privado como cualquier elemento: el nombre que trae solo vale en
su módulo. `pub use` lo hace público, y entonces el módulo ofrece el elemento
como si fuera suyo. Con eso, `geometria` puede cerrar sus dos hijos y exponer
solo los tipos:

```rust,ignore
// src/geometria.rs
mod circulo;
mod punto;

pub use circulo::Circulo;
pub use punto::Punto;
```

En `main.rs`, la línea `use geometria::{Circulo, Punto};` basta para escribir
`Circulo::nuevo(Punto { x: 1.0, y: 2.0 }, 3.0)`. Quien usa `geometria`
nombra `geometria::Circulo` y no sabe que existe un archivo `circulo.rs`. La ruta larga deja de funcionar: `geometria::punto::Punto`
da E0603 *module `punto` is private*. A cambio, `geometria` puede repartir sus
tipos en otros archivos, o juntarlos en uno, sin que `main` cambie.

## Aplicación

El ejercicio principal del curso *Aprende Rust* para este capítulo junta las
tres piezas: un campo privado, un constructor y un `pub use`. Una cuenta
expone a su titular y oculta el saldo, que solo cambia por `ingresar`:

```rust
mod banco {
    pub mod cuentas {
        pub struct Cuenta {
            pub titular: String,
            saldo: u32,
        }

        impl Cuenta {
            pub fn nueva(titular: &str) -> Self {
                Self { titular: titular.into(), saldo: 0 }
            }

            pub fn ingresar(&mut self, cantidad: u32) {
                self.saldo += cantidad;
            }

            pub fn saldo(&self) -> u32 {
                self.saldo
            }
        }
    }

    pub use cuentas::Cuenta;
}

fn main() {
    let mut cuenta = banco::Cuenta::nueva("Ferris");
    cuenta.ingresar(50);
    cuenta.ingresar(25);
    println!("{}: {}", cuenta.titular, cuenta.saldo());
}   // Ferris: 75
```

El saldo empieza en 0 porque `nueva` es la única forma de crear una cuenta.
Ninguna línea fuera de `cuentas` puede escribir `cuenta.saldo = 1_000`: daría
E0616. Un método `retirar` sería la otra puerta, y el lugar para revisar que
haya fondos antes de restar. El `pub use` permite escribir `banco::Cuenta`; la ruta larga,
`banco::cuentas::Cuenta`, también funciona aquí, porque `cuentas` es `pub`.

## A fondo

**`x/mod.rs` es la forma anterior de `x.rs`.** Antes de la edición 2018, el
cuerpo de `geometria` iba en `geometria/mod.rs`. Sigue siendo válida, pero no
junto con `geometria.rs`: las dos dan E0761 *file for module `geometria`
found at both*.

**`pub(crate)` abre a medias.** Hace visible un elemento en todo el crate,
pero no para otros crates que lo usen como biblioteca ([7.2 Crates y
Cargo]{.ref}). `pub(super)` lo abre solo al padre. Sirven para piezas que
varios módulos comparten y que no forman parte de la API.

**Un `use` vale solo en su módulo.** El `use` de `HashMap` al inicio de
`main.rs` no alcanza a un `mod` en línea del mismo archivo: dentro, `HashMap`
da E0425 *cannot find type `HashMap` in this scope*. Cada módulo escribe sus
propios `use`; uno escrito dentro de una función vale solo en ella.

**El preludio es un `use` automático.** `Option`, `Vec`, `String` y `Box` se
usan sin `use` porque cada módulo recibe, sin pedirlo, los nombres de
`std::prelude`. `HashMap` no está ahí, y por eso [5.4 HashMap y
HashSet]{.ref} lo trae a mano.

**`use` también trae variantes.** Un enum es un espacio de nombres para sus
variantes, así que `use Lista::{Nodo, Vacia};` permite escribir `Nodo` sin
`Lista::`, como en [6.1 Box y listas enlazadas]{.ref}. Con `*`,
`use pedidos::Estado::*;` trae todas. El `*` se evita fuera de ese caso y de
los tests ([7.3 Tests]{.ref}), porque esconde de dónde sale cada nombre.
