# 7.5 · Entrada y salida

Todos los programas del libro hasta aquí trabajan con datos escritos en el código
fuente. Para cambiar un número hay que editar y recompilar. Un programa útil lee
de algún lado y escribe a algún lado: un archivo, lo que llega por el teclado o
por una tubería, los argumentos con que se le llama.

Las tres fuentes comparten dos hechos. El primero: la operación sale del
programa, y afuera las cosas fallan. El archivo no existe, el disco se llenó, la
entrada se cortó. El segundo: lo que llega son bytes, y para usarlos como
`String` hay que validarlos como UTF-8 y lidiar con el salto de línea que
traen.

## Definiciones y reglas

Canales estándar
:   la entrada estándar *(stdin)* recibe texto del teclado o de otro
    programa; la salida estándar *(stdout)* lleva los resultados, y la salida
    de error *(stderr)*, los avisos.

`io::Result<T>`
:   alias de `Result<T, io::Error>`. Es el tipo de retorno de casi toda
    función de `std::io` y `std::fs`.

Búfer
:   *(buffer)*: un bloque de memoria intermedio. Junta muchas lecturas o
    escrituras pequeñas en pocas llamadas al sistema *(system calls)*, los
    pedidos del programa al sistema operativo.

::: {.reglas titulo="Las tres reglas de la entrada y salida"}
1. Toda operación de entrada o salida devuelve un `Result`: se abre con
   `match` o se propaga con `?`.
2. Leer o escribir de a poco pasa por un búfer, y lo escrito en un búfer
   no sale hasta que se vacía.
3. El texto que llega se valida como UTF-8 y trae su salto de línea:
   `lines()` lo quita, `read_line` lo conserva.
:::

## De un vistazo

| Tarea | Llamada |
| :--- | :--- |
| leer o escribir un archivo entero | `fs::read_to_string(ruta)`, `fs::write(ruta, texto)` |
| leer un archivo por líneas | `BufReader::new(archivo).lines()` |
| escribir de a poco | `writeln!(archivo, ...)` |
| leer una línea de stdin | `io::stdin().read_line(&mut s)` |
| leer stdin por líneas | `io::stdin().lines()` |
| imprimir un resultado o un error | `println!`, `eprintln!` |
| leer los argumentos | `env::args()` |

Todas devuelven `io::Result`, salvo las macros de impresión y `args`.

## Las reglas, una por una

### [Regla 1:]{.prefijo} un archivo entero en una llamada

`fs::write` crea el archivo, o lo vacía si ya existe, y escribe el texto.
`fs::read_to_string` lo lee completo a un `String`. Las dos devuelven
`io::Result`, así que `main` devuelve `io::Result<()>` para poder usar `?`
([5.2 Result]{.ref}):

```rust
use std::fs;
use std::io;

fn main() -> io::Result<()> {
    let ruta = std::env::temp_dir().join("saludo.txt");

    fs::write(&ruta, "hola\nmundo\n")?;
    let texto = fs::read_to_string(&ruta)?;

    print!("{texto}");
    println!("{} bytes", texto.len());
    Ok(())
}
```

```salida
hola
mundo
11 bytes
```

`temp_dir()` da la carpeta de archivos temporales del sistema, y `join` le
agrega el nombre del archivo. Los dos saltos de línea están en el texto leído y
cuentan en los 11 bytes. Por eso se imprime con `print!`: un `println!`
agregaría una línea vacía.

### El error real y `kind()`

Leer un archivo que no existe no es un bug: es una falla esperable. El error
implementa `Display`, con un mensaje que viene del sistema operativo. Ese texto
cambia entre sistemas, así que no sirve para decidir. Para eso está `e.kind()`,
que devuelve un valor del enum `io::ErrorKind`: `NotFound`,
`PermissionDenied`, `AlreadyExists` y otros. Un *guard*
([2.4 Patrones]{.ref}) separa el caso que tiene remedio:

```rust
use std::fs;
use std::io::ErrorKind;

fn main() {
    match fs::read_to_string("config.txt") {
        Ok(texto) => print!("{texto}"),
        Err(e) if e.kind() == ErrorKind::NotFound => {
            println!("{e}");
            println!("sin config: modo normal");
        }
        Err(e) => panic!("config ilegible: {e}"),
    }
}
```

```salida
No such file or directory (os error 2)
sin config: modo normal
```

Sin archivo, el programa sigue con valores default. Un archivo que existe pero
no se puede leer es otro problema, y ese sí lo detiene. Si el error llega con
`?` hasta `main`, el programa termina con código 1 e imprime el formato
`Debug`, con las tres piezas: `Error: Os { code: 2, kind: NotFound, message:
"No such file or directory" }`.

### Archivos grandes: línea por línea

`read_to_string` carga el archivo completo en memoria. Con varios gigabytes eso
no es opción, y no hace falta si se procesa una línea a la vez. `File::open`
abre el archivo sin leerlo; `BufReader` lo envuelve, y su método `lines()`
entrega un iterador de líneas ([5.6 Iteradores]{.ref}). Aquí cada línea es un
monto, y `main` devuelve `Box<dyn Error>` porque hay errores de dos clases
([7.4 Manejo de errores idiomático]{.ref}):

```rust
use std::error::Error;
use std::fs::{self, File};
use std::io::{BufRead, BufReader};

fn main() -> Result<(), Box<dyn Error>> {
    let ruta = std::env::temp_dir().join("montos.txt");
    fs::write(&ruta, "120\n80\n42\n")?;

    let mut total = 0;
    for linea in BufReader::new(File::open(&ruta)?).lines() {
        let linea = linea?;              // io::Error
        total += linea.parse::<i64>()?;  // ParseIntError
    }
    println!("total: {total}");          // total: 242
    Ok(())
}
```

Dos detalles. `parse` recibe `"120"` limpio porque `lines()` quita el `\n`, y
también el `\r\n` de los archivos de Windows. Y cada línea llega como
`io::Result<String>`, porque la lectura puede fallar a la mitad del archivo.
Sin el `?`, la línea no es un `String`: `linea.len()` no compila,
con ``error[E0599]: no method named `len` found for enum `Result<T, E>` `` y la
sugerencia *use the `?` operator to extract the `String` value*. Por último,
`lines()` es un método del trait `BufRead`, y por eso el `use` lo trae: un
método de trait solo se llama con el trait en scope ([4.1 Traits]{.ref}).

### [Regla 2:]{.prefijo} por qué hace falta el búfer

Un `File` solo también se puede leer, pero cada lectura sobre él es una
llamada al sistema. Leer línea por línea así sería pedir unos pocos bytes cada
vez. `BufReader` pide un bloque grande, lo guarda en memoria y entrega las
líneas desde ahí. Solo vuelve a llamar al sistema cuando el bloque se agota.

### Escribir de a poco

`File::create` abre un archivo para escribir: lo crea si no existe y lo vacía
si existe. La macro `writeln!` funciona como `println!`, con un destino como
primer argumento. `BufWriter` es el espejo de `BufReader` para escribir. Para
agregar al final de un archivo sin vaciarlo, se abre con `OpenOptions`:

```rust
use std::fs::{self, File, OpenOptions};
use std::io::{self, BufWriter, Write};

fn main() -> io::Result<()> {
    let ruta = std::env::temp_dir().join("bitacora.txt");

    let mut salida = BufWriter::new(File::create(&ruta)?);
    for n in 1..=2 {
        writeln!(salida, "línea {n}")?;
    }
    salida.flush()?;

    let mut extra =
        OpenOptions::new().append(true).open(&ruta)?;
    writeln!(extra, "línea agregada")?;

    print!("{}", fs::read_to_string(&ruta)?);
    Ok(())
}
```

```salida
línea 1
línea 2
línea agregada
```

La regla 2 tiene aquí su otra cara. Lo escrito queda en el búfer hasta que se
llena, hasta que el `BufWriter` se destruye o hasta que se llama a `flush()`.
El `flush` explícito devuelve un `Result`, así que un error al escribir no se
pierde. `writeln!` necesita el trait `Write` en scope; sin el `use`, la macro
sobre un `File` no compila: ``error[E0599]: cannot write into `File` ``.

### `Read`, `BufRead` y `Write`: lo que hay detrás

Las funciones anteriores no son exclusivas de los archivos. Detrás hay tres
traits de `std::io`: `Read`, `BufRead` y `Write`. Cada fuente o destino
implementa los que le corresponden ([4.1 Traits]{.ref}), y una función
genérica sobre el trait ([4.2 Generics]{.ref}) acepta cualquiera. `contar` recibe algo que sepa leer por líneas; `io::stdin().lock()` da un
`StdinLock`, la entrada estándar como `BufRead`, bloqueada una sola vez para
todo el recorrido y no en cada lectura. Del lado de la escritura,
`writeln!` sirve igual para la salida estándar que para un `Vec<u8>`:

```rust
use std::io::{self, BufRead, Write};

fn contar<R: BufRead>(lector: R) -> io::Result<usize> {
    let mut n = 0;
    for linea in lector.lines() {
        linea?;
        n += 1;
    }
    Ok(n)
}

fn main() -> io::Result<()> {
    let n = contar(io::stdin().lock())?;
    let m = contar("x\ny\n".as_bytes())?;

    let mut memoria: Vec<u8> = Vec::new();
    writeln!(io::stdout(), "stdin: {n} líneas")?;
    writeln!(memoria, "memoria: {m} líneas")?;
    println!("{:?}", String::from_utf8(memoria));
    Ok(())
}
```

```salida
$ printf 'a\nb\nc\n' | ./contar
stdin: 3 líneas
Ok("memoria: 2 líneas\n")
```

La segunda llamada lee de un `&[u8]` en memoria, y el segundo `writeln!`
escribe a un `Vec<u8>`. Así se prueba una función de entrada y salida sin
tocar el disco ([7.3 Tests]{.ref}). `String::from_utf8` valida los bytes y
devuelve un `Result`, porque un `Vec<u8>` cualquiera puede no ser UTF-8. La
tabla reúne los tipos de este capítulo y los traits que implementan:

| Trait | Aporta | Lo implementan, entre otros |
| :--- | :--- | :--- |
| `Read` | leer bytes | `File`, `Stdin`, `&[u8]` |
| `BufRead` | `read_line`, `lines` | `BufReader<R>`, `StdinLock`, `&[u8]` |
| `Write` | `flush`, `writeln!` | `File`, `Stdout`, `Vec<u8>`, `BufWriter<W>` |

### [Regla 3:]{.prefijo} `read_line` agrega y conserva el `\n`

`io::stdin().read_line(&mut s)` lee una línea de la entrada estándar y la
agrega al final de `s`, con su salto de línea. Devuelve cuántos bytes leyó. El
programa siguiente duplica un número; se compila como `doble` y recibe la
entrada por una tubería:

```rust
use std::io;

fn main() -> io::Result<()> {
    let mut linea = String::new();
    io::stdin().read_line(&mut linea)?;

    println!("{:?}", linea);
    match linea.parse::<i32>() {
        Ok(n) => println!("doble: {}", n * 2),
        Err(e) => println!("error: {e}"),
    }
    Ok(())
}
```

```salida
$ echo "42" | ./doble
"42\n"
error: invalid digit found in string
```

El `{:?}` muestra la causa: el texto es `"42\n"`, y `\n` no es un dígito. La
solución es `linea.trim().parse()`: `trim` devuelve un `&str` sin espacios ni
saltos de línea en los extremos, `\r\n` incluido.

Que `read_line` agregue, en lugar de reemplazar, importa en un bucle. Dos
lecturas sobre el mismo `String` con la entrada `uno` y `dos` dejan
`"uno\ndos\n"`. Por eso, en un bucle, el `String` se vacía con `clear()` antes
de cada lectura, y el fin de la entrada se reconoce porque `read_line`
devuelve 0. La aplicación del capítulo usa ese patrón. Reusar el `String`
evita reservar memoria en cada vuelta; cuando eso no importa, `for linea in io::stdin().lines()` es más directo: el mismo iterador
de `BufReader`, sin salto de línea y con un `io::Result` por línea. Para leer
toda la entrada de una vez está `io::read_to_string(io::stdin())`.

### `print!` y `flush`

La salida estándar también tiene búfer, y se vacía con cada salto de línea. Un
`print!` sin `\n` queda en el búfer. Si el programa pregunta algo con `print!`
y espera la respuesta, la pregunta no aparece: el programa espera una
respuesta a una pregunta que no se ve. La solución es la regla 2, vaciar a
mano con `flush()`, que viene del trait `Write`:

```rust
use std::io::{self, Write};

fn main() -> io::Result<()> {
    print!("Nombre: ");
    io::stdout().flush()?;

    let mut nombre = String::new();
    io::stdin().read_line(&mut nombre)?;
    println!("Hola, {}.", nombre.trim());
    Ok(())
}
```

```salida
$ echo Ana | ./saludo
Nombre: Hola, Ana.
```

Con una tubería la respuesta no se ve, así que la pregunta y el saludo quedan
en la misma línea. En una terminal, el cursor espera después de `Nombre: `.

### Dos salidas: `println!` y `eprintln!`

`eprintln!` escribe en la salida de error. En la terminal las dos se ven
iguales, pero son canales separados: al redirigir la salida estándar a un
archivo con `>`, lo que sale por `eprintln!` sigue en pantalla. Un programa
que se encadena con otros por tuberías escribe sus resultados con `println!`
y todo lo demás con `eprintln!`; así el siguiente recibe solo datos. El
ejemplo del apartado siguiente lo muestra.

### Argumentos de la línea de comandos

`std::env::args()` devuelve un iterador con los argumentos como `String`. El
primero es el nombre con que se llamó al programa, así que los del usuario
empiezan en el índice 1. Con `collect` quedan en un `Vec<String>`
([5.6 Iteradores]{.ref}); con `args.get(1)`, la falta de argumento es un `None`
y no un panic ([5.1 Option]{.ref}).

Para terminar con error, `std::process::exit(código)` sale en el acto. Por
convención, 0 es éxito y cualquier otro número es falla; muchos programas usan
2 para un uso incorrecto. `exit` nunca vuelve: su tipo es `!`, y por eso cabe
en el `else` de un `let-else` ([2.4 Patrones]{.ref}):

```rust
use std::env;
use std::process;

fn main() {
    let args: Vec<String> = env::args().collect();
    let Some(texto) = args.get(1) else {
        eprintln!("uso: {} <número>", args[0]);
        process::exit(2);
    };
    let Ok(n) = texto.parse::<u32>() else {
        eprintln!("no es un número: {texto}");
        process::exit(1);
    };
    println!("{n} al cuadrado = {}", n * n);
}
```

```salida
$ ./cuadrado 12
12 al cuadrado = 144
$ ./cuadrado; echo "código $?"
uso: ./cuadrado <número>
código 2
$ ./cuadrado doce > salida.txt; echo "código $?"
no es un número: doce
código 1
```

`$?` es la variable de la terminal con el código de salida del último programa.
En la última sesión, la salida estándar va a un archivo y el error sigue en
pantalla, porque sale por `eprintln!`.
Cuando los argumentos crecen, con opciones como `-v`, valores default y un
texto de ayuda, el crate `clap` los interpreta a partir de un struct
([7.2 Crates y Cargo]{.ref}).

## Aplicación

Un `wc` mínimo: líneas, palabras, caracteres y bytes del archivo del
argumento o, sin argumento, de la entrada estándar:

```rust
use std::fs::File;
use std::io::{self, BufRead, BufReader};

fn contar<R: BufRead>(mut r: R) -> io::Result<[usize; 4]> {
    let mut n = [0; 4]; // líneas, palabras, caracteres, bytes
    let mut linea = String::new();
    while r.read_line(&mut linea)? > 0 {
        n[0] += 1;
        n[1] += linea.split_whitespace().count();
        n[2] += linea.chars().count();
        n[3] += linea.len();
        linea.clear();
    }
    Ok(n)
}

fn abrir(ruta: Option<String>) -> io::Result<[usize; 4]> {
    match ruta {
        Some(r) => contar(BufReader::new(File::open(r)?)),
        None => contar(io::stdin().lock()),
    }
}

fn main() {
    match abrir(std::env::args().nth(1)) {
        Ok([l, p, c, b]) => println!("{l} {p} {c} {b}"),
        Err(e) => {
            eprintln!("cuenta: {e}");
            std::process::exit(1);
        }
    }
}
```

```salida
$ printf 'El año\nde la niña\n' | ./cuenta
2 5 18 20
$ ./cuenta no-existe.txt; echo "código $?"
cuenta: No such file or directory (os error 2)
código 1
$ printf '\xff\xfe\n' | ./cuenta; echo "código $?"
cuenta: stream did not contain valid UTF-8
código 1
```

El archivo y la entrada estándar pasan por la misma `contar`, genérica sobre
`BufRead`. La cuenta va en un arreglo, que `main` abre con un patrón
([2.4 Patrones]{.ref}). Usa `read_line` y no `lines()` para contar los
saltos de línea, como `wc`. Hay 18 caracteres y 20 bytes porque cada `ñ` ocupa
dos bytes ([3.4 Strings]{.ref}). Los bytes `ff fe` no son UTF-8, y
`read_line` da un error en lugar de un `String` inválido.

## A fondo

**`Path` y `PathBuf` son el par `&str` y `String` de las rutas.** `PathBuf`
es el dueño y `Path` el préstamo. Tienen tipo propio porque una ruta no
siempre es UTF-8: en Linux, un nombre de archivo es
cualquier secuencia de bytes. Por eso `Path` no implementa `Display`, y se
imprime con `ruta.display()`. Para archivos que no son texto, `fs::read` devuelve los
bytes sin validar en un `Vec<u8>`.


**Un `File` se cierra solo.** No hay método `close`. `File` implementa `Drop`
([4.4 Traits de la stdlib]{.ref}), y el archivo se cierra cuando el valor sale
de scope. Un `BufWriter` hace `flush` en su `drop`, pero si esa escritura
falla, el error se descarta: por eso el `flush` explícito.
